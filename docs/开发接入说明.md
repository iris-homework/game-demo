# R1 卡牌战斗开发接入说明

当前基线为 0.2.4-r1；维护核对日期为 2026-10-03，地图页面于 2026-10-07 接入。修改前先阅读 [维护文档](维护文档.md)，历史变化见 [修改记录](修改记录.md)。本说明中的预留接口不等于正式规则已经实现。

## 分层与事务

`CombatModel` 为纯 RefCounted 模型，不依赖界面节点。负责卡牌实例、三个牌堆、敌人数组、意图、回合与胜负。`snapshot / restore` 完整序列化局内状态。`battle.gd` 负责目标选择、卡牌飞行动画、意图和血条显示；`Game` 负责自动存档与剧情返回；`main.gd` 负责覆盖全屏的转场和换场。

出牌前校验卡牌仍在手里、目标存活、效果受支持，再统一结算。使用独立实例 UID，所以同一张定义的三张牌也能区分。重复提交、出牌起手、回合切换和转场期间的输入会被拒绝；命中后的视觉收尾不阻塞下一次出牌。卡牌移动和 HP 在同一逻辑提交内保存，动画只是显示。当前默认原型已验证战斗快照恢复；扩大敌人血量后，“首回合空手”可能被误认为首次发牌，需按维护文档补测并修正，不能对任意扩展牌组作无条件恢复保证。

## 新增卡牌

正式卡牌列表为 `data/cards/cards.json`，目前为空数组。当前 cards/schema.json 未在运行时执行完整校验。接入时每项需要稳定 `id`、`name`、`type`、`description`、`cost`、`artAssetId`、`effects`。模型会加载该目录，再合入独立的临时卡定义。要在开发牌组测试正式定义，可在 `data/prototype/combat.json` 的 deck 中引用其 ID；不能把临时牌自动加入正式奖励或冒险牌组。

当前只实现 `effects: [{"type":"damage","amount":1}]`。未知效果拒绝提交；能量、格挡、状态、升级、消耗、稀有度与正式牌组构筑均未实现。后续应在模型中扩展效果处理和校验，保持视图只消费结果。cost 为 null 时显示测试无费用，不产生虚构能量值。

临时卡视觉由 `CombatCard` 绘制青色切角框、线路纹样与选中洋红轮廓，正式卡图通过资源 ID 加载。卡牌文字与规则数据分离。当前原型手牌为三张；更多卡牌时应继续校验扇形间距、悬停和文本高度。

## 新增敌人和意图

`data/enemies/enemies.json` 每项包括 id、characterId、displayName、battlePortraitAssetId、maxHp、intentSequence。当前单敌战斗是验收范围；模型保存 enemies 数组，未来扩展多敌时需相应调整战场布局与目标规则。

maxHp=null、intentSequence=[] 时使用临时 profile 的 HP 3 与攻击 1，正式参数不冒充已定稿。正式数据可采用 maxHp 数值及 `intentSequence: [{"type":"attack","amount":1,"hits":1}]`。模型在回合结束执行当前意图，再推进序列索引并准备下一意图；界面从同一份 intent 读取数字，确保显示与实际伤害一致。当前只实现攻击类意图，其他类型应同步增加规则和图标。

在 `data/battles.json` 的 enemyIds 中引用敌人。E12 使用 mech_boss 与新增机甲战斗图；普通黑帮头目的敌方立绘仍空，避免把对白头像当作战斗图。空战斗图不绘制默认人物或占位卡片，HP、姓名、意图与点击目标区域仍存在。

## 背景与战斗立绘

背景取 Battle.placeId 对应 Place.backgroundAssetId。`cityMapAssetId` 专用于总览地图，不得用于战斗背景。诺伦通过 Character.battlePortraitAssetId 读取战斗图，对话继续读取 portraitAssetId。敌人使用敌人配置自己的 battlePortraitAssetId。

新增图片复制入 assets 后，在 `assets.json` 注册 ID。战斗 RGB 白底图可设置 whiteKey=true，使用运行时 shader 去白；透明战斗图应设置为 false，避免去掉白色细节。对白立绘当前由 DemoUI.portrait() 无条件应用去白材质，透明对白图不能只靠 false 关闭，还需调整材质应用条件并检查高光。源文件不会被处理或覆盖。

## 回合与动画

临时规则配置了补牌目标三张、结束回合弃置剩余手牌、牌堆空时将弃牌堆洗回。它们只是演示循环的配置决定，文档中的确定数值仍为攻击 1、敌方 HP 3 和敌方攻击 1。

抽牌从牌堆按 0.045 秒间隔并行飞往手牌位置；选牌后 targeting_line.gd 在画布坐标中绘制跟随鼠标的弧线、箭头和目标锁定环。卡牌在 0.16 秒内飞向目标；命中脉冲、伤害飘字和弃牌飞行并行播放，非致命命中立即恢复操作。出牌时立即将该牌从视图手牌字典移除，并关闭其鼠标拦截，避免飞行残影挡住下一次点击。致命命中额外保留 0.24 秒视觉反馈后返回剧情。抽牌和命中时长仍读取 profile.visuals；出牌弃牌尾动画上限为 0.22 秒。所有 Tween 跟随所属场景销毁，不改变模型与存档协议。

进入与退出战斗的花屏由 `shaders/glitch.gdshader` 实现。主场景先锁输入，自下向上覆盖，遮满后替换视图，再淡出。胜利、失败、投降及演练退出共用同一条路径。当前时长为覆盖 0.58 秒、消退 0.32 秒。

## 剧情返回和演练

每场战斗保留 win、lose、surrender 对应的返回节点。模型 outcome 只通知视图结束战斗，视图调用 `Game.battle_exit(result, revision)`；由流程管理器保存结果和历史，再进入正确节点。成功完成战后对白才标记事件完成。开发模拟按钮也使用同一接口。

演练开始时在内存中保存完整冒险状态，用临时独立状态启动战斗；不写入冒险文件。退出或胜负后恢复此前状态，返回菜单。演练不是正式关卡，不授予事件完成标记、信用点或奖励。

## 血量、日期与局外数据

冒险 schemaVersion 2 增加 maxHp、currentHp、currentDay、combat、inventory。初版存档读取时迁移为 HP 100、日期 1，其余原数据保留。存档会校验牌堆实例不重复、敌方生命范围等基本结构。

`healHpPercent` 按最大 HP 计算并封顶。医院和诊所通过 Place.services 调用同一动作。`advanceDay` 仅由明确请求或开发工具调用，日期封顶 7，不自动进入下一周。未给治疗添加费用、限制或耗时。

MetaProfile 使用独立文件，schemaVersion=1，cyberwareState 初始为空。新游戏不清除 MetaProfile。当前义体页面只作内容入口，不修改战斗属性。

当前战斗内临时义体（0.3.3）：`data/prototype/cyberware.json` 提供六张紫色占位卡，经 `CombatModel.activate_cyberware()` 激活，为下次攻击增加 1 点伤害。0.3.2 改为每张冷却 1 回合（含使用当回合），下个玩家回合恢复紫色并可再次激活；加成仍可叠加；局外页面仍不提供装备。配置随战斗 profile 保存，`usedCyberware` 与 `nextAttackBonus` 随快照恢复。具体规则和验证见维护文档“战斗临时义体”一节。

## 道具

`data/items/items.json` 初始为空。视图提供道具栏和 `use_item` 调用，模型接口接收 itemId、targetIndex、inventory、catalog；因效果规则待定，目前拒绝使用且不扣物品、不产生效果。正式道具接入时应同时增加物品校验、效果执行与数量的原子提交。

## 地图接口

地图读取 `data/map.json` 的总览插画资源，`cityMapAssetId` 经 [data/assets.json](../data/assets.json) 指向 `assets/map/map.jpg`。底图保持原始比例并统一计算绘制矩形，地点与标记映射到同一矩形。`coordinatesStatus` 当前为 `illustration-calibrated`，[data/places.json](../data/places.json) 的 16 个 `mapAnchor`（0—1 比例坐标）已按本轮插画校准到建筑；`mapDisplay` 的 `offset`／`labelOffset`／`avatarSide` 只用于展示，`hitArea` 是元数据，实际点击命中取自图钉与头像的当前尺寸。更换插画后需要重新校准锚点。

目标与状态查询在 `Game`：`map_target_events()` 返回下一步可推进的主线事件，`map_place_state(id)` 返回地点开放、可用事件、当前、目标与完成状态，两者都通过同一套条件求值过滤事件条件和地点条件。可推进主线按事件 ID 稳定排序，多条主线全部标金色。不要把 `state.targetId`（委托对象）或 `activeEventId`（可能停留在上一次事件）当作地图目的地。

主线 `!` 与可选 `?` 徽章可以同时出现，数量按本类分别统计，为 1 时只显示符号、大于 1 时显示数字。点击地点标记打开浮动详情卡，命中范围是标记本身而不是整幅插画建筑；卡片内任务类型文案为“主线任务”／“可选事件”，底部按钮为“进入地点 →”，按钮再次调用统一的 `start_event()`、`visit()` 或 `heal_at()` 校验。地图治疗不修改 `currentPlaceId`，视图重建后通过 `pending_selection_id` 恢复所选详情。纹理经 `ResourceLoader` 读取已导入资源，符号按 alpha 主体在运行时像素副本上裁切、降到 128 像素并生成 mipmaps，原素材不修改；外框状态由 `scripts/map/frame_state.gdshader` 染亮边。正式复杂的不规则轮廓可在此基础上扩展多边形热点。

悬停预览与详情卡的文字由 `MidnightMapCard` 自己的 `_label` 创建，只复用 `DemoUI` 的字体与主题；节点加入场景树后再设定受限 `size` 并开启 `clip_text`。文字测量与显示统一使用 Font 的 `BREAK_MANDATORY|BREAK_WORD_BOUND|BREAK_ADAPTIVE`，所有 CardLabel 设 `line_spacing=0`；Font 默认断行 flags 与 `Label.WORD_SMART` 不一致，再加上默认行距，会让 48 像素两行文字只露出一行。预览不使用单行 ellipsis，改动文案或字号后重新检查文字边界。

## 通用按钮与交互验证

`DemoUI.button_style` 提供对称内边距、圆角和五种状态；`neon_button.gd` 提供角标与短时发光动画，交互区域不缩放。按钮使用居中排版与基于项目内中文字体的 FontVariation，新增按钮继续通过 DemoUI.button 创建。无文字敌方点击区域使用独立 Button，避免通用角标绘制在立绘上。

`tests/interaction_visual.tscn` 使用真实视口输入验证选牌、缩放后的箭头位置、目标锁定、右键/Esc 取消、快速连续出牌、弹窗隔离和胜负返回；测试关闭存档写入。截图写入系统临时目录 midnight_ui_*.png。

## 牌堆浏览

`pile_view.gd` 是战斗内的模态大界面，使用 ScrollContainer + 五列 GridContainer，复用 CombatCard 的 read_only 预览模式（1.2 倍卡面、不触发选牌、不阻挡滚轮）。网格从内容区域最左侧开始排列，不足一行也不居中。重复实例逐张展示；Esc、右键与返回按钮关闭。浏览时拦截战斗鼠标与快捷键，关闭后恢复原战斗。

展示顺序只对 contents 的副本排序：排序值取可选整数 sortOrder，未填写则取 card_catalog 中的位置；同优先级按卡牌 ID、同卡按稳定实例 UID 排列。不会写回实际 draw_pile / discard_pile，也不会泄露临时洗牌结果。

`tests/pile_visual.tscn` 覆盖空牌堆、真实弃牌、30 张临时容量样本、重复卡、默认／显式排序、滚轮穿过卡面、末行完整可见、输入隔离和关闭。容量样本只在测试内存中生成，不加入正式牌组或存档。

手牌使用 BUTTON_PRESS，在鼠标按下时立即选中并更新指向线。battle.gd 记录本次按住的卡牌 UID；左键松开时重新检测有效目标并只结算一次。空白处松开保留点选模式；取消、出牌与回合忙碌会清理按住状态。只读牌堆卡不启用此输入模式。`tests/drag_visual.tscn` 验证按下起线、拖动松开出牌、取消、重复释放和原点选方式。
