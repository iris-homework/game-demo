# 开发接入说明

## 模块与状态

`Game` 是自动加载的流程管理器。主场景监听 `changed`，按 `page` 装载独立 PackedScene。界面只能通过 `visit`、`start_event`、`advance`、`choose`、`battle_exit`、`claim_rewards` 等入口请求状态变化。场景不存放故事文本和图片路径。

`currentScene` 保存真实流程页；`page` 可临时为菜单而不改变检查点。保存字段覆盖文档列出的 schemaVersion、周次、地点、事件、节点、目标、阵营、信用点、事件完成列表、flags、奖励领取列表；并保留 deck、battleId、result、battleHistory、choiceHistory 和双方立绘 ID。

对白完成节点统一提交事件完成动作，再进入结果页。每个事件只读自己的 `rewardIds`。当前奖励表为空。禁止在正式事件里加“临时默认卡牌”。

## 条件与动作

条件是 JSON 对象，同一对象内所有键都必须满足。支持 `all`、`any`、`completed`、`flag`、`faction`、`target`、`creditsAtLeast`。未知条件拒绝执行。例如：

```json
{"all": [{"flag":"portClue"}, {"target":"richard"}]}
```

状态动作白名单：`setFlag`、`addCredits`、`spendCredits`、`setTarget`、`setFaction`、`completeEvent`、`finishWeek`、`grantReward`。动作列表先在状态副本上校验，全部成功后整体提交，费用不足不允许产生部分效果。

流程动作单独映射为显式接口：`gotoNode` 对应 `enter_node`；`startBattle` 对应 `type: battle` 节点。不要把任意函数名或表达式放进数据执行。按钮捕获当前 `revision`，失效按钮与重复输入不能再次提交。

## 新增事件

在 `data/weeks/week1/events.json` 加入具有稳定 ID 的事件，填写 `placeId`、`unlockCondition`、`repeatPolicy`、`startNodeId`、`rewardIds` 与 `nodes`。同步维护 `week.json` 的事件索引；地图按配置查询符合条件的事件，不在脚本中列事件 ID。

普通节点字段：`id`、`speakerId`、`speakerSide`、`text`、`next`。舞台节点 `type: stage`，说话者为空，显示为“场景”，不占据角色槽。`{目标姓名}` 根据目标 ID 解析，未知变量显示配置错误而非原样暴露。

选项节点额外带 `choices` 数组，每项为 `id`、`label`、`condition`、`effects`、`next`。条件同时用于显示禁用态与提交前的二次检查。分支最后到 `type: finish` 节点。

左侧用于主角与当前友方，右侧用于对方；指定 `speakerSide` 时会替换同侧角色。人物跨侧时会清空旧侧以免重复显示。双方当前角色存入检查点，恢复后不会丢失站位。显示名由角色 ID 查询。

## 战斗替换

`BattleScene.enter(params)` 接收 `battleId` 与 `eventId`；根据战斗配置读取 `participants` 和 `returnNodeByResult`。正式战斗实现替换 `scripts/battle.gd` 内部即可。结束时调用 `Game.battle_exit(result, expected_revision)`，其中 result 只能是 win、lose、surrender。

流程管理器保存结果、追加历史，再跳转当前战斗配置中相应返回节点。不要让战斗自行回到事件开头；不要在失败路径写入胜利标记。目前 `rules` 与 `enemyStats` 明确为 null。

## 卡牌和奖励

`data/cards/cards.json` 当前为空数组。`schema.json` 仅定义后续卡牌数据结构，不是可使用的卡牌。初始牌组为 `deck: []`，尚无出牌、费用、生命与回合逻辑。

奖励示例仅用于理解接口，**不属于正式配置**：

```json
{"example_credit_reward":{"name":"示例","type":"credits","amount":20}}
```

该示例需在事件 rewardIds 中引用才会显示。现有执行器只允许非负信用点奖励；卡牌奖励应在正式卡牌规则确定后扩展。领取键是 `eventId:rewardId`，领取记录与信用点一起提交，并随返回地图保存。测试会注入一份临时奖励验证幂等，然后移除，不会修改正式 JSON。

## 替换美术

资源路径只登记在 `assets.json`。人物通过 portraitAssetId 引用，地点通过 backgroundAssetId 引用；空路径显示缺图占位。图片建议保留原比例，背景采用保持比例覆盖，人物采用保持比例居中。当前人物为 RGB 白底图，白色背景由 shader 在运行时透明化，白色细节也可能受影响；替换为透明 PNG 时应移除该去白 shader。

字体是 Noto Sans CJK SC，许可证位于 `assets/fonts/LICENSE.txt`。字体来源为 notofonts/noto-cjk 仓库的 Sans/OTF/SimplifiedChinese/NotoSansCJKsc-Regular.otf，项目附带原许可。原美术副本来自用户提供目录，商店图片未绑定任何地点。

## 验证入口

`tests/run.tscn` 运行真实流程管理器，独立测试存档路径。`tests/visual.tscn` 装载真正界面，在图形模式依次截图菜单、对话、地图、地点、选项、战斗、失败和结算；不会写入正常存档。测试后的截图放在系统临时目录，非游戏资源。
