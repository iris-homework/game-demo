## 固定内容与允许变化

| 项目 | 固定要求 | 每张牌允许变化 |
| --- | --- | --- |
| 画布 | 1086×1448，3:4，PNG RGBA | 无 |
| 卡面底板 | 黑色实底，外缘透明；插画合成后卡面内部保持不透明 | 无 |
| 卡框 | 同一几何与固定笔刷纹理；使用同一版式配置 | 等级对应颜色 |
| 费用 | 左上固定区域居中，使用源数据 | 数值 |
| 等级 | 右上圆形区域居中 | C/B/A/S |
| 标题 | 固定倾斜色条内居中；按配置预设字号适配 | 卡名 |
| 插画 | 固定斜切窗口及裁切方式；人物关键部位放安全区 | 卡牌对应动作与简单环境 |
| 类型 | 插画与说明交界居中，固定黑色承托 | 攻击／技能／能力，由源 type 映射 |
| 效果说明 | 固定区域、固定宋体、每行居中，按预设字号与行距适配 | 源 cardText |
| 底部 | 保留空白，无姓名、签名、额外标签 | 无 |

等级色：C `#A6ADB7`、B `#5AA9FF`、A `#F25B69`、S `#F2C35C`。这些颜色来自当前工程定义；v7 生成图只提供视觉方向，不能反向采样颜色取代规定色值。

字库使用模板附带的 Noto Serif CJK SC Bold，来源和许可随包保存。缺少字体必须报错，不能静默替换系统字体。PNG 作为可核验的排版输出；SVG 母版为可编辑工作文件，打开时须加载同一字库。SVG 编辑后应重新渲染和验收，不能假定所有编辑器显示完全相同。

### 文字处理

1. 读取源 `name/cost/rarity/type/cardText`，禁止让图像模型生成或修订卡牌文字。
2. 自动分行只能插入换行，不得改字、数字、空格、标点、效果顺序或省略规则。源中已有真实换行应保留语义分段。
3. 连续数字、小数、百分比和数值单位尽量保持在一起，不能把“14”拆成两行；避免闭合标点出现在行首。
4. 字号只能从配置中列出的档位选择。超出最小字号的容量即报错；不能继续压缩、横向拉窄文字或裁掉说明。
5. 未知等级、未知卡牌类型、缺少字段、不可显示字符、字面转义字符（如反斜杠加 n）列为源数据问题，不自动解释或修正。
6. 区分日志转义显示与真实字符。`noren_25 / 处决射击` 当前包含正常 LF 换行（字符码 10），工具保留它；不能只看日志显示的 `\n` 就判定源文案异常。

## 插画制作规范

### 参考顺序

1. v7 卡面作为画风与角色比例参考，固定使用参考来源清单中的文件。
2. 诺伦既有 Q 版动作图作为人物身份依据。
3. 剑或霰弹枪原设作为道具轮廓依据。
4. 本张卡的动作描述只补充场景，不覆盖以上设定。

不要把整张卡面交给图像模型重画。生成结果只包含插画，不带卡框、标题、费用、等级、类型、规则、文字、签名或水印。

### 画风

- 约三头身的大头、短身、短肢 Q 版诺伦；保留深色头发、洋红眼睛、兜帽披风、圆形耳部装置与米白三角标牌。
- 清楚描线、块面阴影、黑紫主色和少量洋红强调。减少碎纹、无关挂件与高亮装饰。
- 背景为简单灰紫都市块面，主要动作应在缩小后仍可辨认。
- 每图表达一个主要动作，默认一个主体和一件主要道具。只有卡牌含义需要时才出现目标。
- 不为了填满画面添加敌人、枪口以外的光束或复杂碎片。

### 构图与动作

独立插画推荐 1928×1488，横向。插画会等比覆盖到配置窗口，并受斜边与类型标签遮挡。先用模板检查裁切：脸、双手、握柄、护手、主要刃尖／枪口及关键接触点必须可辨。完整人物构图还应保留脚部支撑；近景裁切须明确是有意构图。

生成前用一句话说明“谁在做什么、哪只手接触什么、动作朝哪里、结果在哪里”。只描述画面关系，无须绘制武器内部构造。

- 持剑：剑柄、护手、单一剑刃连接清楚；手握在柄上；斩击特效与刀刃方向一致。
- 持枪：两只手与各自手臂连接清楚；握把手与支撑手位置区分；枪托与身体不穿插；特效始于正确枪口。
- 补弹／补给：可用准备姿态表达，两颗弹药可辨，手指和道具不穿插；不以不清楚的机械操作强行表现效果。
- 命中：若画出目标，攻击方向与接触／命中位置一致；目标难以安排时简化场景。
- 站姿：脚底接触地面，重心与动作方向相符；披风不掩盖关键结构。

### 生成与返修

每张单独生成，保留完整提示词、参考文件哈希与输出路径。检查发现问题后，针对具体部位修改，重检手部、武器及受影响的构图。
工具拒绝、生成失败、未完成或存在可见错误均保留记录，不能写成通过。可以采用更简单且保持卡牌含义的动作；若改变卡牌主题或角色设定，先与用户澄清。

## 验收分层

| 阶段 | 负责人／证据 | 通过条件 |
| --- | --- | --- |
| 文件与排版检查 | 工具报告、源数据与文件哈希 | 字库/模板/数据/插画引用有效；PNG尺寸模式、透明边缘、内部实底、文字保真与边界检查通过 |
| 画面检查 | 制作者或审阅 agent 逐张目视，记录实际证据 | 下表所有适用项通过；不适用项附原因 |
| 用户认可 | 用户明确意见及其聊天／记录定位 | 对当前版本明确接受；不能由制作者代填 |
| 运行接入 | 有明确授权的接入任务及游戏内证据 | 分别记录资源引用／加载、正常显示尺寸和交互表现；只做后台加载不能宣称游戏画面与真实输入已验收 |

自动工具不会可靠识别多余手指、道具穿插或错误攻击方向。程序检查通过不能代替目视检查。目视检查通过也不能代表用户已经认可。

候选作品可以在用户认可前展示并交付到试作目录；只有对应版本完成验收，才能标为“已认可成品”。实际接入游戏仍依据当前任务授权。

### 逐张画面检查表

| 编号 | 检查项 | 必须返修的情况 |
| --- | --- | --- |
| V01 | 人物身份与画风 | 变成长身成人比例、服装／耳部装置变更、上色与样板明显不一致 |
| V02 | 身体与手部 | 额外／缺失肢体、手腕断连、明显多余手指、手与道具融合 |
| V03 | 握持与支撑 | 握在刀刃上、托枪手悬空、枪托穿入身体、姿势不支撑动作 |
| V04 | 道具结构 | 多出剑刃、柄与刃接错、枪管断裂或方向互相矛盾 |
| V05 | 动作与特效 | 光束来源错误、斩击方向与刃口不符、命中点偏离攻击方向 |
| V06 | 接触与空间 | 道具穿过手／身体／地面、脚底悬空、目标与人物尺度关系失常 |
| V07 | 裁切与版式可读性 | 脸／关键手部／握柄被遮，旧卡框文字混入插画，标题或规则拥挤／遮挡 |
| V08 | 文字与卡牌含义 | 卡名／数值／标点有误，插画表达另一种效果，画中出现无关文字 |
| V09 | 干扰与细节 | 高亮背景抢主体、无关饰物过多、无意水印、拼接痕迹 |
| V10 | 缩小预览 | 正常预览尺寸无法辨认主要动作，说明难以阅读；需记录检查尺寸 |

先查看完整分辨率，再查看缩小预览。制作工具的样例采用固定展示尺寸做基础检查；游戏中的手牌、放大预览与多分辨率阅读体验必须在接入时另验。

### 记录与失效规则

使用模板包的验收记录格式，至少保存：卡牌 ID、模板版本、成品 PNG 与 manifest 的 SHA256、检查人、日期、各项状态与证据、用户认可状态及依据。
状态允许 `pending/pass/fail/not_applicable`；不适用必须写明原因。用户认可单独使用 `pending/accepted/rejected`。

图片、源文案、字库、模板或渲染器变化后，旧的文件检查及关联验收不再适用于新版本。重新生成并绑定新哈希，不能复制旧“通过”标记。
代码生成的测试夹具不是真实用户认可证据；不得将其写入正式素材记录。
