# 主菜单重构规划与任务清单

本文把主菜单讨论整理为可执行方案，基线为 **0.2.4-r1**，记录日期为
**2026-10-07（Asia/Shanghai）**。本次交付是规划文档：动态主菜单、专用插画、
新布局和下列验收均未实现或执行。

规划按讨论中推荐的“酒馆窗边＋委托终端”展开，作为首版制作方向；具体构图
和人物姿态仍可在样板阶段调整，不把推荐方案写成已定稿美术。

## 目标与现状

让玩家打开游戏时先感受到“雨夜都市里，一份委托正在等待诺伦”，并能快速
找到继续和新游戏。静态构图先成立，再通过局部环境运动增加气氛。

已静态核对 [menu.gd](../scripts/menu.gd)、[menu.tscn](../scenes/menu.tscn)、
[Game](../scripts/game.gd) 与 [DemoUI](../scripts/ui.gd)。当前菜单使用城市背景、
左侧大面积深色面板、标题与多组按钮，并已有短暂淡入和通用按钮反馈；尚无
本方案的雨夜环境动画。历史截图可用于构图对照，不代表本轮重新运行。

| 当前问题 | 重构目标 |
| --- | --- |
| 大面板遮住大半背景，场景存在感弱 | 用左侧局部渐暗保障文字可读，保留完整场景 |
| 文案和辅助按钮密集，演练入口抢眼 | 继续／新委托为主要操作，演练与档案降低视觉权重 |
| 主菜单继续使用城市总览视角 | 增加人物与近景道具，形成有故事感的入口 |
| 动画制作范围尚不明确 | 首版只做雨、局部灯光和终端提示灯三项环境效果 |

## 首版画面方案

画面为酒馆内向窗外看：诺伦位于右侧，以安静的侧影或背影为主，桌面上放着
委托终端；窗外城市的青色与洋红霓虹映入室内。角色首版保持静止。

- 左侧约 35% 留给标题、一句文案和主菜单，避免高亮招牌、人物或杂物穿过文字。
- 右侧约 65% 形成视觉中心：人物、窗框、桌面终端与城市灯光有前后层次。
- 标题采用现有中文字体进行界面排版，英文副标题降低权重；不将中文菜单
  或动态信息画死在背景图里。
- 菜单使用克制的深色底与清楚的浅色文字，主操作用项目既有强调色；人物
  与环境可以偏暗，按钮、标题和焦点必须清楚。
- 继续使用 1440×900 逻辑画布。背景建议按 16:10 制作，并预留边缘裁切余量；
  16:9 窗口先遵循现有等比缩放与留边策略，不为本轮菜单改整个工程的缩放规则。

示意布局如下，位置在静态样板阶段校准：

```text

│ 午夜委托                 窗框／雨夜城市／局部霓虹        │
│ MIDNIGHT COMMISSION                                      │
│ 一句短文案                         诺伦侧影              │
│                                                         │
│ 继续委托                                                │
│ 地点 · 阵营（有有效进度时）         桌面／委托终端        │
│ 新的委托                                                │
│                                                         │
│ 义体档案    演练                    动态效果开关 · 版本  │
└─────────────────────────────────────────────────────────┘
```

## 菜单入口与状态规则

沿用既有流程接口，菜单重构只改变展示和入口组织。没有实际功能的入口不作为
装饰性按钮上线。

| 入口／状态 | 首版行为与实现边界 |
| --- | --- |
| 继续委托 | 沿用 `Game.resume()`；无内存进度且无存档时禁用，有进度时突出 |
| 新的委托 | 沿用 `request_new()` 与 `Game.new_game()`；有进度时保留覆盖确认及取消 |
| 义体档案 | 保留 `Game.open_cyberware()`，不因新菜单添加装备或属性功能 |
| 演练 | 收入一组次级入口，仍可分别进入 B04 战斗演练与 B12 机甲演练 |
| 进度摘要 | 只读真实的当前地点与阵营；尚未选择阵营时显示现有对应名称 |
| 仅磁盘存档 | `has_save()` 只代表文件存在；摘要须经验证后读取，不能为展示摘要触发恢复、推进或保存。首版可只显示“已有检查点” |
| 损坏或不兼容存档 | 沿用读取失败反馈，不虚构进度，不自动开始新游戏或覆盖原文件 |
| 动态效果开关 | 首版提供当前会话的静态模式；不写入冒险存档。跨启动记忆作为后续独立界面偏好 |
| 设置、退出 | 完整设置页和新增退出入口列为后续范围，不在首版放无效按钮 |

移入按钮只改变焦点和反馈，不启动任务或演练。键盘焦点清楚可见，Tab 切换
及 Enter／Space 激活按钮；弹窗打开后焦点留在弹窗。Esc 沿用主流程规则，
尤其保留有进行中游戏时的恢复行为。

## 动态效果分级

首版只实施 P0。下表参数是调试起点，不是当前代码值或已测性能结论。

| 优先级 | 效果 | 实施方式与限制 |
| --- | --- | --- |
| P0 | 窗外细雨 | 用粒子或轻量着色器实现，限定在窗口区域；不落到标题、人物或按钮前面 |
| P0 | 局部霓虹变化 | 独立灯光遮罩，亮度缓慢变化，建议周期 4–8 秒；不用全屏明暗闪烁 |
| P0 | 终端提示灯 | 小区域轻微呼吸，建议周期 2–4 秒；不显示虚构的新任务通知 |
| P0 | 界面进入与按钮反馈 | 淡入约 0.3–0.6 秒，悬停反馈约 0.1–0.2 秒；按钮和文字位置稳定 |
| P0 | 静态模式与生命周期 | 关闭环境运动后保留清楚的静态画面；离开菜单释放动画、粒子和计时器，失去窗口焦点时暂停环境动画 |
| P1 | 前后景轻微视差 | 需要可拆分且补全遮挡区的素材；建议总位移控制在 4–8 逻辑像素，文字和按钮不跟随 |
| P1 | 杯口蒸汽、环境声 | 美术和音频到位后再加；音频须核对来源，设置可控制音量 |
| P2 | 人物呼吸、头发、衣物运动 | 需要拆层、补画或骨骼；不纳入首版验收 |
| P2 | 长视频、3D 场景、镜头漫游 | 暂缓，避免素材与运行成本扩大 |

难度主要集中在背景构图、光效遮罩和分层素材的质量；首版无需人物骨骼或
完整动画短片。若雨或灯光影响文字辨识，先降低效果强度再考虑增加装饰。

## 素材清单与工程组织

现有 `assets/backgrounds/bar.png`、`city.png` 和 `assets/characters/noren.png`
可作为风格与角色参考，不等于已有适合本构图的分层资源。专用插画需要另行
制作；未获得匹配素材前，可以用已有背景验证布局，但记录为占位样板。

| 素材 | 首版要求 |
| --- | --- |
| 酒馆窗边背景 | 一张完整、静态也成立的插画，建议 2560×1600；保留左侧文字空间 |
| 窗口区域遮罩 | 明确哪些区域显示雨；不能让雨越过窗框和人物 |
| 霓虹光效遮罩 | 只控制招牌、反光等局部；不让建筑整体变形 |
| 终端提示灯遮罩 | 小面积独立区域，不将可变文字、按钮画入背景 |
| 前景与人物拆层 | 仅当静态样板需要时拆分；P1 视差所需的遮挡区补画另列工作 |
| 资源记录 | 记录来源、提示词、选定版本与用途，区分原图和运行时资源 |

以下是拟新增路径，当前尚未创建：素材 `assets/menu/`、环境效果组件
`scripts/menu/`、验证证据 `artifacts/qa/menu-redesign-<日期>/`。
继续以 [menu.tscn](../scenes/menu.tscn) 和 [menu.gd](../scripts/menu.gd) 为主入口，
必要时把背景效果独立成子场景，菜单按钮仍通过 `Game` 调用既有流程。
动画不得写入剧情状态，装饰节点不得拦截鼠标。

## 分阶段任务清单

完成一阶段后依据验收结果进入下一阶段；这是执行顺序，不自动增加反复询问
许可的流程。当前仅资料核对与规划归档完成，其余任务均待执行。

- [x] M00：核对现有菜单入口、素材目录和缩放策略，归档本规划。
- [ ] M01：留存修改前文件、菜单截图与正式存档哈希，建立本轮证据目录。
- [ ] M02：制作静态构图样板，确定左侧菜单空间、诺伦姿态、窗户和终端位置。
- [ ] M03：接入静态菜单布局，校准主次按钮、标题和进度摘要的可读性。
- [ ] M04：接回继续、新游戏确认、义体档案和两种演练，检查真实状态与返回路径。
- [ ] M05：制作并接入最终背景及窗口、霓虹、终端遮罩，记录资源来源。
- [ ] M06：逐个加入窗外雨、局部霓虹、终端提示灯，分别检查效果与遮挡。
- [ ] M07：完成静态模式、焦点失去时暂停、离开菜单时清理和安全返回。
- [ ] M08：完成三尺寸画面、真实输入、循环动画与性能检查，修复实际问题。
- [ ] M09：核对正式存档未变，更新维护说明、修改记录和实际验收证据，交付首版。

| 阶段 | 任务 | 依赖与完成标准 |
| --- | --- | --- |
| A 静态样板 | M01–M03 | 先完成 M00；无动态时也能看清标题、人物和主操作，背景不被大面板截断 |
| B 功能接入 | M04 | 依赖 M03；五个既有功能入口均可达，确认／取消与返回正确 |
| C 环境动态 | M05–M07 | 基于稳定布局和匹配素材；三种效果独立可控，循环自然，不抢占输入 |
| D 验收交付 | M08–M09 | 前述全部完成，实际证据齐全；失败保留日志，修复后记录复测 |

先做 A，再做 B，随后 C 和 D。M05 的素材准备可在布局稳定后与 M04 并行；
图形输入测试始终顺序运行。首版不包含 P1／P2，后续按效果收益逐项安排。

## 验收任务与证据

现有 [qa.ps1](../tools/qa.ps1) 的 `-Target menu -Suite capture` 可作截图入口。
它不等于动态菜单的完整输入验收；执行前须核对测试环境隔离，必要时扩展专用
测试入口。所有写存档行为使用测试路径，子进程的用户数据目录也要隔离。

| 编号 | 检查任务 | 所需证据 |
| --- | --- | --- |
| U01 | 1280×800、1600×1000、1440×810 下标题、按钮、摘要不越界 | 各尺寸截图与实际窗口／画布尺寸 |
| U02 | 无存档、有内存进度、仅磁盘存档、损坏存档展示正确 | 隔离测试状态与入口操作记录 |
| U03 | 继续恢复到实际场景；开始新游戏的确认与取消正确 | 真正的按键／鼠标操作和页面状态 |
| U04 | 两种演练和义体档案可进入、返回，冒险进度不被演练覆盖 | 逐个入口操作及前后状态 |
| U05 | Tab 焦点、Enter／Space、Esc 和弹窗焦点正确 | 输入记录；弹窗打开时底层不误触 |
| U06 | 雨限定在窗外，光效不覆盖文字，动画无明显循环跳变 | 至少 20 秒录屏或带时间戳连续观察记录 |
| U07 | 静态模式立即停止环境运动，切场景后不残留效果或重复计时器 | 开关与反复进入／离开菜单的实际记录 |
| U08 | 同机同尺寸对照静态与动态帧时间，目标为稳定 60 FPS | 测量机器、窗口、采样时长和帧时间；截图不能证明性能 |
| U09 | 正式存档未新增或改写，源码无脚本／着色器错误 | 文件存在性与哈希、完整日志和退出码 |

若性能不达标，依次减少雨粒子、简化遮罩着色、降低环境效果更新频率；静态
模式始终可用。不要通过缩小菜单文字或删除入口来换取通过。
