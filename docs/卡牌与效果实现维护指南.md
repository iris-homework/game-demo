# 诺伦卡牌与效果实现维护指南

适用基线：**0.4.0-noren-cards，2026-10-17，Godot 4.7.2**。本指南用于修改卡牌、扩展效果、排查战斗问题，覆盖当前 40 种诺伦牌、旧战斗兼容、拥有牌与演练。维护原则是：**规则只在模型中结算一次，完整结算后提交快照，动画播放结果；新增字段同时维护执行、保存、恢复、校验和测试。**

玩家操作见[诺伦卡牌与控制台](诺伦卡牌与控制台.md)，设计原文见[诺伦角色卡牌完整卡表](../../卡牌和特殊效果设计/诺伦角色卡牌完整卡表.md)。本文记录当前实现；标为“扩展限制”的项目需要补实现，不能据此推断任意新效果已受支持。

`Game.initialize_combat()` 先复制旧原型参数，再在角色选择 `noren_v1` 时合并诺伦参数，加入角色信息、科技、初始牌和额外拥有牌。`CombatModel.is_noren()` 依据快照的 `profile.ruleset` 分派新旧规则，不能仅依据“当前主角是诺伦”切换正在进行的旧战斗。

创建战斗使用新的 `CombatModel.new()` 再 `initialize()`；读档使用新的模型再 `restore()`。当前 `initialize()` 没有清空已有实例、牌堆和敌人，不可把旧模型重复初始化当作重开战斗。

## 卡定义 拥有份数与局内实例

这三种数据含义不同，修改时不要混用。

| 数据 | 示例 | 生命周期 |
| --- | --- | --- |
| 卡定义 ID | `noren_01` 直击 | 同一种牌只有一个定义 ID；改名不改 ID |
| 额外拥有牌 `state.deck` | `["noren_36", "noren_36"]` | 两份短点连射，随冒险保存；不含固定初始牌 |
| 局内实例 UID | `card_000`、`card_001` | 每份牌各有 UID，`instances[uid]` 指向定义 ID；重开战斗重新生成 |
| 局内牌区 | `draw_pile`、`hand`、`discard_pile`、`exhaust_pile` | 四个数组存 UID，不能存定义 ID |

新冒险固定拥有直击×4、护身×4、贴近×1、拉开距离×1，共 10 张。`Game.owned_card_counts()` 合并 `startingDeck` 与 `state.deck` 统计份数；`library_cards()` 提供 40 种定义目录的排序副本。查看全部卡牌不代表已拥有，不能把总目录直接赋给战斗牌组。

在完整出牌／回合结算结束后，所有 UID 必须恰好落在四个牌区之一：四区总数量等于 `instances.size()`，不重复、不丢失，且每个 UID 指向快照中存在的卡定义。出牌执行中的卡会暂时离开所有牌区，**不要在这个中间状态保存**。

### 定义字段

| 字段 | 作用与维护约束 |
| --- | --- |
| `id`、`number`、`name` | 稳定 ID、卡表编号、展示名；当前 ID 为 `noren_01` 至 `noren_40` |
| `type` | `attack`、`skill`、`power`；决定普通耗弹／回弹、减费适用和能力离开循环 |
| `cost` | 非负整数基础费用；实际费用调用 `card_cost(uid)` |
| `rarity` | C／B／A／S；当前数量 4／22／10／4，不直接决定伤害或抽奖权重 |
| `target` | `enemy` 单个活敌人；`self` 自身；`all` 全部活敌人；`stance` 由形态决定 |
| `effects` | 按数组顺序执行，不按效果类型重新排序 |
| `description`、`cardText` | 完整规则文案、卡面紧凑文案；两者都不参与执行，改效果时一起更新 |
| `archetype`、`sortOrder` | 流派展示与排序；排序展示副本，不改变抽牌顺序 |
| `exhaust` | 为 true 时打出后进入消耗区；`type=power` 即使没写该字段也进消耗区 |
| `extraAmmoMax`、`extraAmmoBonus` | 卡级参数，额外耗弹上限与每颗的基础增伤；当前只用于 20、26 |
| `artAssetId` | 卡图资源接口，当前 40 牌为空；不是效果实现入口 |

品级颜色统一取 `CombatCard.RARITY_COLORS`：C 灰 `#a6adb7`、B 蓝 `#5aa9ff`、A 红 `#f25b69`、S 金 `#f2c35c`。品级字母以 26 号加粗大写独立显示在卡牌左上角，流派以 10 号小字放在右侧。战斗卡面显示 `cardText`，缺少时回退 `description`；动态费用调用 `show_cost(model.card_cost(uid))`，不能只显示原始 `cost`。

## 一次出牌的执行顺序

入口：`battle.play_selected(target, discard_uid, extra_ammo)` → `model.play_card(...)` → `play_noren_card(...)` → `Game.commit_combat(model)`。

1. 界面检查转场、战斗忙碌和模态窗口。`play_error()` 检查手牌、定义、能量、远程攻击弹药，以及是否有可弃的攻击牌。
2. 需要选择时先弹窗：12 号选另一张攻击牌的 **UID**；20／26 号选额外耗弹。界面用 `-1` 表示尚未选择，传给模型时转换为合法的非负值。取消不扣费、不移动牌。
3. 模型复查敌人目标、额外耗弹范围和效果类型／已支持的参数检查；弃牌必须仍在候选列表中。无效的正常操作返回 `{}`，不改变资源和牌区。
4. 冻结 `at_start=stance`、`ammo_before=ammo`、`before=enemies.duplicate(true)`。本牌的形态条件、末弹、处决、原有裂伤条件，都使用这个出牌前状态。
5. 通过 `card_cost()` 扣能量。攻击牌取出科技与本回合增伤，并消费这次攻击适用的增伤、减费标记。
6. 攻击牌按出牌前形态统一处理一次弹药：近战 +1；远程 −1−额外耗弹。多段、群攻都不重复收付。远程符合高压枪机条件时在这里加增伤并标记已触发。
7. 从手牌移除正在使用的 UID，暂不放进弃牌／消耗区，防止本牌抽牌或进近战时把自己抽回来。
8. 按 `effects` 顺序执行；`when` 始终对比 `at_start`，不会随着本牌中途切换形态改变。`requiresBleed` 检查选中敌人的出牌前裂伤。
9. 普通牌进入弃牌区；消耗牌和能力牌进入消耗区。被 12 号弃置的攻击牌进入普通弃牌区。
10. `resolve_outcome()` 判定结果，返回 `hits`、抽弃牌 UID 等；视图收到成功结果后加忙碌锁并立即 `commit()`，再播放飞牌、攻击、状态和补牌表现。

`card_cost()` 对攻击牌使用 `max(0, 原费用 − turn_discount − 形态减费)`；技能与能力不享受这些攻击减费。`stance_discount` 是布尔值，最多减 1；本回合减费数值可叠加。零费攻击也会消费已有的“下一张攻击”减费和增伤，不能因为实际扣费为 0 而保留标记。

上述是现有合法定义下的操作保证。**扩展限制：**当前不是完整的卡表校验器，也没有对任意异常配置自动回滚的机制。`play_error()` 会直接读取部分字段；仅通过 JSON 解析或 `valid_combat()`，不代表非法 `hits`、`cap`、`value` 等配置安全。新增字段必须补前置校验，不能等扣费之后才发现错误。

## 伤害 形态与状态的结算细节

### 攻击本体和裂伤

对每个存活目标、每一段攻击依次计算：

```text
本段基础值 = effect.amount
           + 第一段增伤（仅当前第一个 damage 效果的第一段）
           + 远程专属增伤（额外耗弹、末弹、处决，满足各自条件时）
本体请求伤害 = roundi(本段基础值 × 形态倍率)
形态倍率：近战 1.0；远程 1.5
实际 HP 损失 = min(目标当前 HP, 本体请求伤害 − 本次格挡吸收)
远程且本体后目标仍存活且裂伤大于 0：
    再以当前裂伤层数调用 enemy_damage，随后裂伤减 1
```

`roundi` 对当前非负数逐段四舍五入，1×1.5 为 2，3×1.5 为 5；不能把多段基础伤害先相加再统一取整。`result.damage` 和 `hit.damage` 记录实际 HP 损失，不包括被格挡或超出剩余 HP 的部分。

`enemy_damage(index, amount, bypass)` 统一处理敌人格挡与 HP。普通本体、裂伤、反击都先消耗格挡；只有 16 号的**远程本体**设置 `bypass=true`，其后裂伤仍遵守格挡。裂伤伤害不乘远程倍率，也不触发更多裂伤结算；近战和弹反不消耗目标已有裂伤。

攻击本体已经击杀目标时，不再结算该段裂伤，也不继续攻击后续段。后续 `bleed`／`weak` 效果跳过死敌。攻击牌的新裂伤通过后面的独立效果施加，因此不会让同一张牌前面的攻击段提前享受这些新层数。

### 增伤与条件读取

| 来源／条件 | 当前处理 |
| --- | --- |
| 科技 `next_attack_bonus` | 下次有效攻击的第一段基础增伤；可跨回合积累，攻击时清零 |
| `turn_damage_bonus` | 15／18／24 号提供，本回合下次攻击第一段基础增伤；使用或结束回合清零 |
| 高压枪机 `high_pressure` | 每回合首张远程攻击第一段 +3；`pressure_used` 控制；同回合先近战攻击不占用次数 |
| 群攻的第一段增伤 | 对每个存活目标的第一段各生效；整个第一个 `damage` 效果后才把局部增伤清零 |
| `extraAmmoBonus` | 远程按本次主动选择的额外耗弹数计算；当前牌均只有一段 |
| `lastAmmoBonus` | 远程且出牌前恰好 1 弹药，不是普通耗弹后变成 1 |
| `executeBonus` | 远程且出牌前 `hp * 2 <= maxHp`，包含恰好 50%；不按攻击途中下降后的 HP 重判 |
| `bleedExtraHit` | 远程且该目标出牌前裂伤达到阈值，增加一段；不是每段都检查一次 |

扩展限制：当前远程专属增伤写在段循环中；未来把带 `extraAmmoBonus`、`lastAmmoBonus`、`executeBonus` 的牌改成多段，会对每段应用该加成。若设计意图只加第一段，需要一起改执行器和测试，不能只改 `hits`。

### 切换 弹药与裂伤施加

`change_stance("melee"/"ranged"/"toggle")` 只有实际切换才发奖励：进入近战 `draw_cards(1)`；进入远程设 `stance_discount=true`。该减费保留至下一张攻击，即使后来切回近战也不会清掉；重复进入远程不叠加。开场初始化为近战不算一次切换，不额外抽牌。

09 切入斩、10 撤步反击按“伤害 → 切换”配置：资源支付和本体倍率取旧形态，切换奖励随后生效。视图应使用返回的 `result.stance` 播放本牌攻击，动画结束才显示模型的最终形态。

`gain_ammo()` 将增加后的弹药限制在 `profile.ammoCap`，溢出不保留。近战普通回弹在效果数组之前发生，因此 17 枪口重击的近战额外 +2 与普通 +1 分开计算并共同受上限限制。

`apply_bleed()` 对远程卡牌的施加量使用 `roundi(amount * 0.5)`。30 号在近战且目标出牌前已有裂伤时，把基础施加量换成 `woundedMeleeAmount=4`。剖解经验只在近战、单敌目标、施加量大于 0 且目标仍活着时，首次额外 +1，并设置 `dissection_used`；群攻、远程和弹反均不触发此能力。

### 可手算的回归样例

以下敌人均有足够 HP、没有格挡，没有未注明的增伤。

| 输入 | 应得到的结果 |
| --- | --- |
| 直击，近战／远程 | 本体 6／9；普通弹药分别 +1／−1 |
| 膛压蓄积后远程双发速射 | 第一段 `roundi((3+4)*1.5)=11`，第二段 `roundi(3*1.5)=5`，合计 16 |
| 远程短点连射，敌人原有 5 裂伤 | 本体 2×4，加裂伤 5+4+3+2，总损失 22，剩 1 裂伤，只消耗 1 普通弹药 |
| 远程过载射击，额外耗弹 0／1／2 | 本体 15／21／27，总耗弹 1／2／3；可选上限还受当前弹药约束 |

| 敌人 10×3 攻击、2 虚弱、玩家 100 格挡和 2 弹反 | 敌人逐段 8、总量 24；玩家不掉 HP；反击两次，每次 6；敌人仍活着则共加 2 裂伤，玩家剩 1 弹反 |

## 统一 Buff 效果库（2026-10-17）

入口是 [data/buffs/buffs.json](../data/buffs/buffs.json) 与 [scripts/combat/effects/buff_library.gd](../scripts/combat/effects/buff_library.gd)。分类相对于状态持有者：`positive` 为正面效果，`negative` 为负面效果；分类本身不改变数值或自动清除状态。

| 分类 | ID | 名称 | 原存储／规则 |
| --- | --- | --- | --- |
| 正面 | `block` | 格挡 | 玩家／敌人 `block`；自身回合开始清除，原盾牌显示，不另加图标 |
| 正面 | `parry` | 弹反 | `parry`；沿用卡牌的施加前上限判断、补层及整次攻击后减 1 层 |
| 正面 | `next_damage` | 下次攻击增伤 | `turn_damage_bonus`；使用或玩家回合结束清除 |
| 正面 | `technology` | 科技增伤 | `next_attack_bonus`；未使用时跨回合保留 |
| 正面 | `next_discount` | 本回合攻击减费 | `turn_discount`；使用或玩家回合结束清除 |
| 正面 | `stance_discount` | 形态攻击减费 | 布尔 `stance_discount`；不叠加，跨回合保留至下一攻击 |
| 正面 | `high_pressure` | 高压枪机 | `powers` 与 `pressure_used`；每回合首次远程攻击生效 |
| 正面 | `dissection` | 剖解经验 | `powers` 与 `dissection_used`；每回合首次近战单体卡施加裂伤生效 |
| 负面 | `bleed` | 裂伤 | 敌人 `bleed`；远程每段本体后触发，随后减 1 层 |
| 负面 | `weak` | 虚弱 | 敌人 `weak`；固定减伤 25%，该敌人回合结束减 1 层，最多 999 层 |

能量、弹药、形态、抽牌、直接伤害和科技冷却仍各自承担资源／动作职责，不分类为 Buff。`parry_fill` 是施加弹反的方式，`power` 是施加持续能力的方式，不重复注册成状态。

### 使用已有 Buff

```gdscript
var Buffs = model.buffs # CombatBuffs 实例，随战斗模型释放缓存
Buffs.definitions(Buffs.POSITIVE) # 返回定义副本，可按分类浏览
Buffs.definition("bleed")
Buffs.apply(model, "next_damage", 4) # 玩家状态
Buffs.apply(model, "weak", 1, enemy_index)
Buffs.count(model, "weak", enemy_index)
Buffs.clear(model, "weak", enemy_index)
```

科技增伤标记 `cardApply:false`，必须经 `activate_cyberware()` 连同冷却记录一起产生，以满足原存档来源校验，不能直接由卡牌添加。

直接 `apply()` 是原始施加。卡牌裂伤必须经 `apply_card_effect()` 或 `model.apply_bleed(index, amount, stance, single)`，以保留远程减半与剖解经验；弹反施加裂伤走原始路径。全部施加操作只能发生在模型结算阶段，UI 只读取 `player_badges()`／`enemy_badges()`；玩家弹反图标使用动画中的 `shown_player_parry`，不提前显示最终层数。

### 添加一种简单 Buff

下面是**接入示例，未加入正式目录或卡牌**。把新对象加入 `buffs.json`，可复用现有的攻击增伤行为：

```json
{
  "id": "focus",
  "name": "专注",
  "category": "positive",
  "target": "player",
  "stacking": "add",
  "maxStacks": 6,
  "duration": "player_turn_end",
  "handler": "attack_bonus",
  "consumeOnAttack": true,
  "icon": "damage",
  "color": "f17988",
  "showBadge": true,
  "description": "专注 · {count}\n本回合下一张攻击牌第一段基础伤害增加该数值；使用或回合结束清除。"
}
```

卡牌的有序 `effects` 中引用：`{"type":"buff","id":"focus","amount":4}`。已有卡牌的 `next_damage` 等写法无需改动。卡牌目标继续由 `target` 决定；敌人状态施加到该牌确定的目标数组，`both` 状态默认施加给玩家，需要时明确 `buffTarget:"enemy"`。未知 ID 或不匹配的持有者在消耗能量前拒绝。

- 新定义省略 `field`、`saveKey`，使用通用存储：玩家 `model.buff_state`／快照可选 `buffs`，敌人可选 `enemy.buffs`。空容器不新增到玩家快照，旧档缺字段默认为空；JSON 读回后统一为整数层数。无需为每个简单 Buff 再加模型变量、Game 白名单或 HUD 分支。
- `stacking`：`add` 累加并可用 `maxStacks` 截断；`flag`／`unique` 保留单份；`guarded_add` 保留弹反的施加前判断，仅用于需要该语义的效果。`duration`：`battle` 跨回合保留、`player_turn_end` 在玩家结束回合时清除、`own_turn_start` 在持有者开始回合时清除、`own_turn_end_decay` 在持有者回合结束时减 1 层，由 `own_turn_end()` 处理（当前用于虚弱）。
- 通用 `handler` 目前支持玩家 `attack_bonus`（第一段基础增伤）、`attack_discount`（攻击能量减费）。是否用后清除由 `consumeOnAttack` 决定。`none` 只提供状态存储／显示／生命周期，不会自动造成伤害或改变资源。裂伤、虚弱、弹反、格挡及两项能力为专门逻辑，不能换一个 ID 就复用这些专门处理器。
- 全新机制应在效果库的对应时点实现：`begin_attack`、`after_attack_hit`、`enemy_attack_damage`、`after_enemy_attack`、`player_turn_end`、`own_turn_start`，同步注册处理器校验与测试；需要全新结算时点时才扩展模型调用点。`category` 不是伤害系数；新图形仍在 `status_badge.gd` 绘制，也可复用现有 `icon`。
- 现有 `field`／`saveKey`／`usedField`／`usedSaveKey` 是旧存档兼容映射，不应复制到新定义；原状态数值仍只有一份。`catalog_errors()` 校验分类、行为名、叠加与显示字段，存档校验从目录读取状态边界。
- 效果目录随当前程序加载，不冻结在旧战斗快照中；本次保持旧语义不变。日后修改已有 ID 的规则、删除 ID、改变上限或目标时，仍需处理旧档兼容，不能假设换了统一库就自动完成迁移。

验证入口：`tests/buff_library_tests.tscn` 覆盖分类、叠加、生命周期、旧字段、展示副本、新正面／负面状态的存储与 JSON 往返；`tests/noren_cards_tests.tscn` 覆盖原 40 牌。改到显示链路时再运行 `tests/noren_cards_visual.tscn`。

## 通用效果执行器

以下名字是 `effects[].type`，不是要额外调用的函数。除 `stance`、`power` 等使用 `value` 的效果外，数值通常读取 `amount`。`when` 可为 `melee`／`ranged`，省略则不限制；`requiresBleed` 是本效果的前置条件，当前用于 39 号的格挡。

| 效果 | 对应状态或行为 | 必须保持的边界 |
| --- | --- | --- |
| `damage` | 对已确定的目标数组执行伤害；`hits` 默认 1 | 每段通过 `enemy_damage`，死亡提前停止；特殊参数见上节 |
| `block` | 玩家 `block += amount` | 不等同于治疗，不改 `player_hp` |
| `ammo` | `gain_ammo(amount)` | 与攻击普通耗弹／回弹分别处理 |
| `draw` | `draw_cards(amount)`，记录抽到的 UID | 在现有手牌数上增加，可超过 5；正在使用的牌不能被抽回 |
| `stance` | `change_stance(value)`，合并奖励抽牌 UID | `value` 仅支持两种形态和 toggle；顺序决定先攻击还是先切换 |
| `weak` | 对活目标累加虚弱，最多 999 | 固定降低攻击伤害 25%，该敌人回合结束减 1 层 |
| `bleed` | `apply_bleed`，含远程减半、旧伤条件、剖解经验 | 施加与远程触发是两条不同路径 |
| `parry` | 当 `parry < cap` 时加 `amount` | 当前 31／32 都加 1；代码是条件加法，不是任意 amount 的上限截断 |
| `parry_fill` | `parry = max(parry, amount)` | 当前只用补至 2；不应降低已有层数 |
| `next_damage` | 累加 `turn_damage_bonus` | 本回合下一张攻击用掉，跨回合失效 |
| `next_discount` | 累加 `turn_discount` | 同上；实际费用最低 0 |
| `power` | 唯一追加 `value` 到 `powers` | 同名不叠加；重复打出依然支付费用并进入消耗区 |
| `discard_attack` | 移动所选攻击牌 UID：手牌 → 弃牌 | 必须选本牌之外的现有攻击牌，不能按牌名随意删一份 |
| `buff` | 效果库按 `id` 施加已注册状态 | 原子验证 ID／持有者，按原数组顺序执行 |

2026-10-17 起，持续状态效果统一交给 `CombatBuffs`。现有卡牌效果类型保持兼容；新 Buff 使用 `type="buff"` 与注册 ID。伤害、抽牌、弹药、形态和弃牌仍是即时动作，由模型负责。全新触发机制仍需在效果库实现并测试，不能只添加名称就获得行为。

## 回合结束与弹反

`end_noren_turn()` 一次调用完成整次敌方行动和下一玩家回合的准备，不要按敌人逐个再次调用。

1. 剩余手牌全部移到弃牌区，清空本回合增伤和本回合减费。
2. 按 `enemies` 数组顺序处理活敌人；该敌人行动开始时清空其格挡。当前只执行 `intent.type=attack`，其他意图跳过。
3. 每段敌方伤害为 `roundi(intent.amount * (0.75 if weak > 0 else 1.0))`。逐段扣玩家格挡再扣 HP；玩家归零时停止该次攻击剩余段。
4. 如果玩家有弹反，按本次开始反击时的层数反击；每层一次，敌人死亡则停止。每次请求伤害为 `roundi(本次敌方攻击总量 * 0.25)`，敌人仍活着时追加 1 裂伤；不受玩家远程减半影响，不触发剖解经验。
5. 本次攻击的弹反处理结束后只消耗 1 层，不是每次反击消耗 1 层。例：2 层时先反击两次，剩 1；若后面还有敌人攻击，该 1 层可再次反击后耗尽。
6. 该敌人回合结束，虚弱减 1 层（最低 0）；非攻击意图也消耗 1 层，多段攻击只消耗 1 层。然后判定结果：玩家 HP 为 0 优先失败，否则全敌死亡为胜利。结束则停止处理后面的敌人。
7. 若战斗继续，回合数 +1，玩家格挡清零，能量重置为 3，重置 `pressure_used`、`dissection_used` 和科技冷却；推进敌人意图索引；抽牌补至 5。

**弹反基数的准确口径：**先按虚弱修正每段，再乘意图声明的 `hits`；不扣玩家格挡，也不按玩家实际掉血量计算。当前代码即使玩家中途死亡，也按声明的完整段数计算反击基数，并在反击后按“玩家死亡优先”判失败。若以后设计要求死亡即禁止反击或只计算已发生段数，需同时调整 `end_noren_turn()`、显示逻辑与边界测试。

### 状态何时保留与清除

虚弱更新于 2026-10-17：层数只影响持续回合数，不提高减伤比例；每段仍四舍五入。层数上限为 999。旧存档中的 `weak` 层数原样读取，恢复后按新规则结算，不需要修改存档结构。专项：`tests/weak_tests.tscn`。

| 状态 | 本场内保留范围 | 清除或消费时机 |
| --- | --- | --- |
| `energy` | 当前玩家回合 | 出牌扣费；下一玩家回合重置 |
| 玩家 `block` | 可覆盖整个敌方回合 | 受击消耗；下一玩家回合开始清零 |
| 敌人 `block` | 当前玩家阶段 | 被伤害消耗；该敌人自己行动开始清零 |
| `ammo`、`parry` | 跨回合 | 按耗弹、反击规则消耗；新战斗重新初始化 |
| 敌人 `bleed`、`weak` | 跨回合 | 裂伤被远程逐段消耗；虚弱固定减伤 25%，每次该敌人回合结束减 1 层；新战斗重置 |
| `turn_damage_bonus`、`turn_discount` | 当前回合下一张攻击 | 攻击时或回合结束清零 |
| `stance_discount` | 跨回合下一张攻击 | 下一张攻击清除；切回近战不清除 |
| `next_attack_bonus` | 科技产生，可跨回合 | 下一张有效攻击清零；不因科技冷却重置而丢失 |
| `powers` | 整场战斗 | 新战斗不继承；同名能力不重复加入 |
| `pressure_used`、`dissection_used` | 当前回合的触发记录 | 下一玩家回合重置；中途获得能力不会倒算先前出牌 |
| `used_cyberware` | 当前回合科技冷却 | 下一玩家回合清空；不属于手牌或消耗牌 |

## 抽牌 消耗与恢复

`draw_cards()` 不传数量时**补到** `profile.handSize`，当前为 5；`draw_cards(n)` 则在现有手牌上**额外抽 n 张**，不受 5 张限制。抽牌使用抽牌堆末端 UID；堆空时按配置回收整个弃牌区并洗牌，抽牌区与弃牌区都空则停止。消耗区不参与回收。

新诺伦战斗初始化时洗牌，旧规则沿用原初始化逻辑。`draw_cards()` 标记 `opening_draw_done=true`；视图 `start_hand()` 仅在标记为 false 时执行开场抽牌并提交。因此“首回合、手牌空、弃牌空”不能代替新快照的开场标记，尤其不能用于所有牌都消耗后的读档判断。

新快照的四区守恒在 `Game.valid_combat()` 检查。仅把 `exhaust_pile` 加进模型还不够，存档校验、恢复、消耗区浏览和相关测试必须一起跟进。消耗是本场离开抽牌循环，不删除局外拥有牌；能力从本场循环移除后，其效果通过 `powers` 继续生效。

## 快照与存档兼容

### 保存了什么

`CombatModel.snapshot()` 保存以下分组；`restore()` 按保存值恢复并复制数组／字典。

| 分组 | 字段 |
| --- | --- |
| 战斗与玩家 | `battleId`、`turn`、`playerHp`、`maxHp`、`outcome`、最近 30 条 `log` |
| 卡牌 | `instances`、`drawPile`、`hand`、`discardPile`、`cardCatalog` |
| 敌人与规则 | `enemies`（HP、格挡、裂伤、虚弱、意图、索引等）、`profile`（包括规则标记、牌组、角色和科技配置） |
| 科技 | `usedCyberware`、`nextAttackBonus`；内部名称保留兼容，界面称“科技” |
| 开场 | `openingDrawDone` |
| `norenState` 数值与形态 | `energy`、`block`、`stance`、`ammo`、`parry` |
| `norenState` 牌区与能力 | `exhaustPile`、`powers` |
| `norenState` 待消费与回合标记 | `turnDamageBonus`、`turnDiscount`、`stanceDiscount`、`pressureUsed`、`dissectionUsed` |

`Game.commit_combat()` 更新 `state.combat` 与冒险当前 HP，增加 `revision`，正式战斗按保存开关写盘，发送 `status_changed`。**不能用 `checkpoint()` 替代它**：后者发送 `changed`，可能重建视图并销毁仍在播放动画的节点。

### 校验与旧档边界

- 冒险 `schemaVersion` 仍为 2。旧无 `ruleset=noren_v1` 的战斗继续走旧执行器；新诺伦快照要求 `norenState` 和布尔型 `openingDrawDone`。
- `valid_noren_state()` 检查主要资源为有限、非负整数；能量不超过回合配置，弹药不超过上限，弹反最多 2、虚弱最多 999；形态合法、能力白名单无重复、回合标记为布尔值。
- 四区中的 UID 必须唯一且全部属于 `instances`，对应定义必须在 `cardCatalog`。增加新牌区时必须修改这条守恒链。
- 旧科技、旧测试牌、旧待领奖励有兼容路径；不要直接删旧 ID。`restore()` 有缺少开场标记时的历史推断，但新诺伦存档校验仍要求该字段，不能把恢复函数的回退误当成迁移已经完成。
- 进行中的战斗使用快照里的参数、卡目录与敌人数据；修改 JSON 后应开新战斗验证。**快照冻结数据，不冻结 GDScript 执行器**；若改变 `noren_v1` 的解释方式，旧快照也会受影响，需要新的规则版本或明确迁移。
- 新 Buff 优先使用统一库的可选 `buffs` 存储，按目录自动保存／恢复／校验。额外的非层数数据或全新状态字段仍需同步初始化、结算、快照、恢复、校验及旧档兼容，并补 JSON 往返测试。

完整磁盘恢复流程和备份轮换边界见[维护文档](维护文档.md)。测试时先设置独立 `save_path`、`meta_path`；`save_enabled=false` 不能替代隔离路径，因为测试可能直接调用保存函数。

## 模型结果与界面同步

成功出牌返回 `uid`、`target`、`damage`、`hits`、`drawn`、`discarded`、`exhausted`、`stance`、`outcome`；无效出牌返回空字典。群攻不要依赖顶层 `target` 定位每次命中，应读取各条 `hit.target`。

每条命中记录包含实际伤害、格挡吸收、命中后的 HP／格挡、是否击杀；诺伦攻击还提供 `attackDamage`、`bleedDamage`、`bleedAfter`。界面按这些快照更新 `shown_enemies` 等显示副本，不重新计算倍率、扣血或裂伤。

回合结束返回 `discarded`、`attacks`、`drawn`、`outcome`。每个敌方动作按 `id` 关联攻击者，分别提供玩家受击 `hits` 与反击 `counters`。模型已经在一次 `end_turn()` 中算完；动画只逐条展示。

必须保留的界面约束：

1. 开始出牌前完成弃牌／耗弹选择；每次回调重新检查 UID、目标和资源，不能绕过模型验证。
2. 已出牌和被弃置的牌立即从视图交互字典 `cards` 移除；飞行残影及其按钮设置 `MOUSE_FILTER_IGNORE`，避免重复点击。
3. 结束回合先加锁，播放弃牌与敌方提示，等待后调用一次 `model.end_turn()` 并提交，再演出敌方攻击。下一回合手牌已经在模型中抽好，`deal_hand()` 只创建界面，不再次抽牌。
4. `shown_draw_count`／`shown_discard_count` 随离堆、入堆动画变化，仅为显示计数；整批动画结束再 `refresh_counts()` 对齐，不能用显示计数写回模型。
5. 牌堆浏览和牌库排序只处理副本，只读卡不接战斗出牌信号。新抽到的牌通过 UID 创建一次，不能用名称判重。
6. Ctrl+Shift+A 控制台与牌堆／选择弹窗拦截底层输入；控制台关闭恢复原处理模式、按钮禁用状态与焦点模式。

## 拥有牌 奖励和模拟对手

右上角当前卡组入口由 `DemoUI.status_bar()` 调用 `Game.open_current_deck()`，通过 `current_deck_requested` 通知 `main.gd`。复用 `card_library.gd.setup_current_deck()`：非战斗复制拥有数量和定义；战斗复制快照 `cardCatalog`，对 `instances.values()` 计数，覆盖所有牌区并保持旧战斗定义。只排序展示副本，不排序牌堆，不把开战后的新增拥有牌带入当前浏览。当前卡组模式隐藏“全部卡牌”切换，关闭信号恢复原视图，不改页面、战斗与存档。模态打开前取消已有攻击选择，原非攻击牌优先消费点击的规则不变；需先取消才能按顶栏按钮。

`card_console.gd` 打开时从 `Game.library_cards()` 建立四列可滚动按钮列表，当前 40 种卡牌可同屏显示。每项展示牌名、品级颜色与已有数量；点击按 ID 调用 `Game.console_command("addcard <id> 1")`，随后从 `owned_card_counts()` 刷新数量。文本命令也刷新同一列表，关闭时沿用 `main.gd` 的牌库刷新。加牌权限、保存失败回滚和当前战斗隔离仍由 `Game` 负责。专项 `tests/card_console_visual.tscn` 验证 GUI 点击、重复添加、读档、回滚与关闭刷新。

`Game.console_command()` 只解析 `help`、`cards`、`owned`、`addcard`，没有任意代码执行。使用方法见[控制台说明](诺伦卡牌与控制台.md)。`addcard` 要求开发模式、已有冒险、不在演练、不忙碌；名称／编号／ID 解析后，数量必须为 1～99 的整数。

加牌只追加 `state.deck`，当前战斗快照不变，下场正式战斗或演练才带入。自动保存开启时写盘失败会恢复旧牌组；关闭自动保存时仅改内存。新委托清空额外牌。新战后奖励从 36 种非 C 牌中等概率选三个不同定义供选一张，保留 1000 信用点和防重复领取流程；品级色不代表抽奖权重。

`start_training()` 备份完整冒险，创建当前角色的新状态，并复制额外拥有牌。`initialize_combat()` 仅在 `training_mode` 下将敌人定义副本的 `maxHp` 设为 `Game.TRAINING_ENEMY_HP=100`，随后模型初始化当前 HP。B04、B12 和三人动作测试的每名对手均为 100/100；三人入口继承演练模板，不应再另写一份 HP 常量。

演练的战斗提交不保存冒险，不发正式奖励；结束或退出恢复 `training_backup`。演练中拒绝永久加牌。正式剧情敌人仍用原目录／原型数值，当前默认 3 HP、攻击 1；演练血量增加不代表已经完成正式难度平衡。

### 发生修改时必须逐项复核的边界

- 费用恰好不足／恰好足够、叠加减费到 0、普通弹药 0／1／6、额外耗弹选 0／可选上限／越界。
- 同形态不重复发奖励、攻击后切换使用旧形态、切换减费跨回合与跨形态保留。
- 逐段取整、格挡恰好耗尽、本体致死后不再裂伤、裂伤致死后不再追加段、新裂伤后置。
- 处决恰好 50%、追猎原有裂伤 4／5、血迹追踪原有裂伤 3／4、近战旧伤翻倍。
- 弹反 0／1／2、全额格挡仍可反击、多敌依次消耗、玩家与敌人同次归零的失败优先。
- 无法选择攻击牌时拒绝拆卸、弃掉同名牌的指定 UID、重复能力扣费但不叠加、抽牌不能抽回自身。
- 开场前保存、开场后首回合打空、全消耗、抽弃牌都空、回收中抽牌、JSON 往返后再出牌。
- 同一 UID 重复提交无效、模态输入不穿透、动画节点不再次扣血、存档不会落在出牌中间状态。

这是一份后续改动的核对清单，不表示每一项已有独立自动测试。新增或改变其中某项时，把对应场景补进相关专项，并记录实际运行证据。

## 常见故障定位

| 现象 | 先检查的位置和原因 |
| --- | --- |
| 加了牌但当前手牌／抽牌堆没有 | `state.deck` 与冻结的 `state.combat` 是两层；检查下场战斗，而非重建正在进行的战斗 |
| 改 JSON 数值后旧战斗没变化 | 快照保存 `profile`、`cardCatalog`、敌人；用新战斗核对，禁止静默覆盖玩家局内状态 |
| 远程多段伤害差 1～几分 | 是否逐段 `roundi`；第一段增伤是否只用一次；裂伤是否在每段本体后结算 |
| 切入斩／撤步反击弹药或动作不对 | `at_start` 与最终 `model.stance` 是否混用；效果数组是否换了顺序 |
| 弹反被多段攻击消耗过快 | 是否误把整次攻击的弹反改成逐段处理，或每次反击都扣层数 |
| 牌越抽越多或读档补发 | `openingDrawDone`、`draw_cards()` 与 `deal_hand()` 职责、正在使用的牌是否过早入弃牌区 |
| 消耗牌读档失败或抽回来了 | 四区守恒、快照 `norenState.exhaustPile`、回收是否误包括消耗区 |
| 动画后血量二次减少 | 是否在命中回调再次调用 `enemy_damage`／`play_card`，或把 `shown_enemies` 写回模型 |
| 飞行残影拦住点击或重复使用 | `cards.erase(uid)`、卡及按钮的鼠标过滤、忙碌锁是否齐全 |
| 刚激活能力就读档失败 | 新能力是否补进 `valid_noren_state()` 白名单；新状态是否同时保存恢复 |
| 测试通过却无法实际出牌 | 测试夹具是否跳过了弹窗、目标选择、忙碌锁或真实视图创建；补对应输入验证 |

排错时记录：版本、战斗 ID、是否演练、出牌 UID／定义 ID、目标、出牌前能量／形态／弹药／状态、选择参数、模型返回结果、预期与实际，以及是否旧档。需要复现快照时复制到测试路径，不覆盖玩家正式存档。

## 扩展与交付约定

1. 先确定是现有效果组合、增加参数，还是增加新机制。确认形态、目标、资源、取整、触发时点和状态生命周期后再实现。
2. 现有效果组合可修改 `cards.json`，但必须同步文案和逐卡表；新的效果／能力还需修改模型、输入选择或展示、保存恢复和校验。
3. [schema.json](../data/cards/schema.json) 仅为结构参考，当前没有运行时自动验证；不能用“符合 schema”代替模型、内容引用与边界测试。当前模型也不保证处理任意恶意或损坏的效果对象。
4. 当前诺伦结束回合直接弃掉全部手牌，未根据 `discardHandAtTurnEnd=false` 分支执行；只改该配置不会得到保留手牌规则。`handSize`、`ammoCap` 等可读参数仍要结合存档校验与界面一起验证。
5. 当前只有攻击类敌人意图、两种能力 ID，以及表中效果。新能量增长／上限、更多弹反层数、保留牌、复制牌、召唤敌人等都需要显式设计与扩展，不能套用当前已验证范围。
6. 修改既有语义时同时决定旧战斗的处理方式；新规则标记不能只改一个字符串，分派、初始化、迁移和验证必须一起维护。
7. 保留修改前副本和必要的存档备份，在独立路径验证；将真实通过／失败结果写入[修改记录](修改记录.md)，同步本指南、卡表和玩家说明。不要用删断言或把所有敌人调成 3 HP 的办法掩盖多段／状态问题。
