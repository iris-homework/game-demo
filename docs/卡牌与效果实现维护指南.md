## 卡定义 拥有份数与局内实例

这三种数据含义不同，修改时不要混用。

| 数据 | 示例 | 生命周期 |
| --- | --- | --- |
| 卡定义 ID | `noren_01` 直击 | 同一种牌只有一个定义 ID；改名不改 ID |
| 额外拥有牌 `state.deck` | `["noren_36", "noren_36"]` | 两份深度伤口，随冒险保存；不含固定初始牌 |
| 局内实例 UID | `card_000`、`card_001` | 每份牌各有 UID，`instances[uid]` 指向定义 ID；重开战斗重新生成 |
| 局内牌区 | `draw_pile`、`hand`、`discard_pile`、`exhaust_pile` | 四个数组存 UID，不能存定义 ID |

新冒险固定拥有直击×4、护身×4、贴近×1、拉开距离×1，共 10 张。`Game.owned_card_counts()` 合并 `startingDeck` 与 `state.deck` 统计份数；`library_cards()` 提供40种定义目录的排序副本；牌库、当前卡组和控制台统一按C → B → A → S、同级原编号升序排列。品级分布为4／23／9／4，只排序副本，不改变实际牌堆顺序。查看全部卡牌不代表已拥有，不能把总目录直接赋给战斗牌组。

在完整出牌／回合结算结束后，所有 UID 必须恰好落在四个牌区之一：四区总数量等于 `instances.size()`，不重复、不丢失，且每个 UID 指向快照中存在的卡定义。出牌执行中的卡会暂时离开所有牌区，**不要在这个中间状态保存**。

### 定义字段

| 字段 | 作用与维护约束 |
| --- | --- |
| `id`、`number`、`name` | 稳定 ID、卡表编号、展示名；当前 ID 为 `noren_01` 至 `noren_40` |
| `type` | `attack`、`skill`、`power`；决定普通耗弹／回弹、减费适用和能力离开循环 |
| `cost` | 非负整数基础费用；实际费用调用 `card_cost(uid)` |
| `rarity` | C／B／A／S；当前数量4／23／9／4，不直接决定伤害；战后奖励先按配置抽取B／A／S品级 |
| `target` | `enemy` 单个活敌人；`self` 自身；`all` 全部活敌人；`stance` 由形态决定 |
| `effects` | 按数组顺序执行，不按效果类型重新排序 |
| `description`、`cardText` | 完整规则文案、卡面紧凑文案；两者都不参与执行，改效果时一起更新 |
| `archetype`、`sortOrder` | 流派展示与排序；排序展示副本，不改变抽牌顺序 |
| `exhaust` | 决定正在使用的牌自身是否进入消耗区；`type=power`也进消耗区。12号自身未标消耗，所选牌由独立 `exhaust_hand`移入消耗区 |
| `consumeAllAmmo` | 卡级布尔值；20号仅在远程攻击时一次耗尽出牌前弹药，不再弹额外耗弹选择 |
| `extraAmmoMax`、`extraAmmoBonus` | 旧快照兼容参数；新40牌不再使用，旧20／26仍按冻结的定义支持额外耗弹 |
| `artAssetId` | 卡图资源接口，当前 40 牌为空；不是效果实现入口 |

品级颜色统一取 `CombatCard.RARITY_COLORS`：C 灰 `#a6adb7`、B 蓝 `#5aa9ff`、A 红 `#f25b69`、S 金 `#f2c35c`。费用以左上角彩色徽标中的大数字显示，卡名位于徽标右侧；品级字母以44号正体加粗艺术字居中显示，配细描边和轻投影。效果说明置于中央等级下方，居中换行，正文固定150×88逻辑像素，初始文案与动态预览统一按14至10号自适应，避免Label自动撑高挤到底栏。底部仅居中显示类型及消耗标记，不显示流派文字。战斗卡面显示 `cardText`，缺少时回退 `description`；动态费用调用 `show_cost(model.card_cost(uid))`，不能只显示原始 `cost`。

## 一次出牌的执行顺序

入口：`battle.play_selected(target, discard_uid, extra_ammo)` → `model.play_card(...)` → `play_noren_card(...)` → `Game.commit_combat(model)`。

1. 界面检查转场、战斗忙碌和模态窗口。`play_error()`检查手牌、定义、能量、远程攻击弹药及是否有另一张可消耗手牌；旧 `discard_attack`仍检查是否有其他攻击牌可弃。
2. 12号先通过 `exhaust_candidates(uid)`列出除自身外的所有手牌，弹窗选择另一张攻击／技能／能力牌的 **UID**；第三个 `play_card()`参数仍沿用 `discard_uid`名称，但新12号表示所选消耗实例。当前20号全耗弹、26号普通耗弹，均直接提交，不弹额外耗弹框。旧快照若仍有 `extraAmmoMax`，保留选择兼容；界面用−1表示尚未选择，传给模型时转换为合法非负值。取消不扣费、不移动牌。
3. 模型复查敌人目标、额外耗弹范围和效果类型／参数；`exhaust_hand`所选UID必须仍在 `exhaust_candidates(uid)`中，不能选自身或抽牌／弃牌／消耗区的牌。旧 `discard_attack`仍使用攻击牌专用 `discard_candidates(uid)`。所有选择在付费、移牌或补弹前验证，非法选择返回 `{}`且快照不变。
4. 冻结 `at_start=stance`、`ammo_before=ammo`、`before=enemies.duplicate(true)`。本牌的形态条件、末弹、处决、原有裂伤条件，都使用这个出牌前状态。
5. 通过 `card_cost()` 扣能量。攻击牌先用 `attack_segment_bonus()` 捕获每段增伤，再经 `begin_attack()` 捕获其他攻击增伤（含旧高压枪机）并消费这次攻击适用的增伤、减费标记；整张牌的各目标、各段及多个damage效果都使用捕获的合计值，不在首段／首个damage后清空局部值。
6. 攻击牌按出牌前形态处理弹药：远程通常在攻击前一次扣1颗；20号 `consumeAllAmmo` 使弹药直接归零，段数用冻结的 `ammo_before` 计算，提前击杀也不返还已消耗弹药。旧快照仍支持通常1颗加额外耗弹。近战每实际执行一段回1弹，群攻同段只计一次、未执行段不计、完全格挡计段。旧 `high_pressure` 仍可在首张远程攻击给每段+3并记录触发；新23号通过倍率能力生效。
7. 从手牌移除正在使用的 UID，暂不放进弃牌／消耗区，防止本牌抽牌或进近战时把自己抽回来。
8. 按 `effects` 顺序执行；`when` 始终对比 `at_start`，不会随着本牌中途切换形态改变。`requiresBleed` 检查选中敌人的出牌前裂伤。
9. 普通牌进入弃牌区；消耗牌和能力牌进入消耗区。新12号的 `exhaust_hand`先把所选另一张手牌移入消耗区，再补3弹；12号自身随后进入普通弃牌区。所选牌不执行自身效果。旧12号快照的 `discard_attack`仍把所选攻击牌移入普通弃牌区，且按原 `exhaust=true`消耗12号自身。
10. `resolve_outcome()` 判定结果，返回 `hits`、抽弃／消耗牌UID等；视图收到成功结果后加忙碌锁并立即 `commit()`，再播放飞牌、攻击、状态和补牌表现。

`card_cost()` 对攻击牌使用 `max(0, 原费用 − turn_discount − 形态减费)`；技能与能力不享受这些攻击减费。`stance_discount` 是布尔值，最多减 1；本回合减费数值可叠加。零费攻击也会消费已有的“下一张攻击”减费和增伤，不能因为实际扣费为 0 而保留标记。

上述是现有合法定义下的操作保证。**扩展限制：**当前不是完整的卡表校验器，也没有对任意异常配置自动回滚的机制。`play_error()` 会直接读取部分字段；仅通过 JSON 解析或 `valid_combat()`，不代表非法 `hits`、`cap`、`value` 等配置安全。新增字段必须补前置校验，不能等扣费之后才发现错误。

## 伤害 形态与状态的结算细节

### 攻击本体和裂伤

对每个存活目标、每一段攻击依次计算：

```text
本段基础值 = effect.amount + 力量
           + 每段增伤（next_hit_damage，对本牌每段生效）
           + 其他待用增伤（科技／next_damage等；同样对整张牌所有段生效）
           + 远程专属增伤（rangedBonus、末弹、处决；旧快照可有额外耗弹增伤）
本体请求伤害 = roundi(max(0, 本段基础值) × 形态倍率)
形态倍率：近战1；远程通常1.5，ranged_mastery生效后2
攻击受伤修正 = 有易伤时 roundi(本体请求伤害 × 1.5)，否则不变
实际HP损失 = min(目标当前HP, 攻击受伤修正 − 本次格挡吸收)
本体后目标仍存活时：
    若近战且有melee_attack_bleed，先对该目标施加1层裂伤
    裂伤触发次数 = effect.bleedTriggers（若明确指定）
                 否则远程1次、近战0次
    每次以当前裂伤层数调用普通enemy_damage；若无persistent_bleed则减1层
    目标死亡或裂伤为0时停止后续触发
```

`roundi` 对当前非负数逐段四舍五入，1×1.5 为 2，3×1.5 为 5；不能把多段基础伤害先相加再统一取整。`result.damage` 和 `hit.damage` 记录实际 HP 损失，不包括被格挡或超出剩余 HP 的部分。

`enemy_damage(index, amount, bypass, attack_damage)`统一处理敌人格挡与HP。当前新40牌本体、裂伤、反击都先消耗格挡；旧快照16号若有 `rangedIgnoreBlock=true`，仍允许远程本体绕过格挡，其后裂伤照常扣格挡。裂伤不受力量、易伤、远程倍率或逐段攻击增伤影响，也不递归触发裂伤；普通近战和弹反不触发裂伤，37号以 `bleedTriggers=2` 明确覆盖近战／远程的默认触发次数。

攻击本体已经击杀目标时，不再结算该段裂伤，也不继续攻击后续段。后续 `bleed`／`weak` 效果跳过死敌。攻击牌自身的裂伤通过后面的独立效果施加，因此不会让同一张牌前面的攻击段提前享受这些新层数；新剖解经验是逐段命中后的能力触发，先于该段显式裂伤触发。

### 电能图标与首次命中（2026-10-25）

电能通过统一Buff定义的showBadge和enemy_badges()生成图标，与其他状态同挂在ActorHUD血条下方的状态行，沿用层数与悬停说明。敌方回合的模型仍一次完整结算；视图的present_attack_start()只处理行动开始展示，电能图标保留经过接近／前摇／射线蓄力。首次实际命中回调调用present_attack_impact()，才移除展示电能，并将捕获增伤折入展示意图，保证后续段伤害预览不回落。重复命中回调不重复折入增伤；该流程不修改模型或保存快照。

### 双猎犬强化与格挡时机（2026-10-25）

修枝猎犬`fortify`依次产生格挡与力量`status_apply`结果，格挡5在自己的下一个行动回合开始时清除，力量永久增加1。模型保留`own_turn_start()`作为所有格挡统一清除入口；敌人旧格挡的清除以`block_clear`通知视图。视图不能在每个状态施加事件前清格挡，也不能在任意其他单位行动时清目标格挡。玩家格挡保留到下一玩家回合开始，已清空的格挡不能再次抵挡新回合伤害。

### 能量防护服（2026-10-25）

抢修工首次强化获得`energy_suit`（敌方flag，本场持续），随后只循环攻击5／攻击3×2。防护服让受到攻击时的电能不再衰减；每段本体在格挡后实际扣血才净增1层，完全格挡不增也不减。`after_incoming_attack(model,index,hp_loss)`读取本体HP损失，在额外裂伤前结算；裂伤、污染、弹反不触发。所有段共用下一次攻击开始时捕获的电能增伤，随后一次消耗全部电能，防护服保留。

### 机器人电能（2026-10-25）

B02意图循环为攻击10→充能5层电能→攻击5×2。`electric_charge`是敌方增益：下一次攻击每段基础伤害+当前层数，攻击前统一捕获并清空，不能首段消耗后让后续段失去增伤。`enemy_damage(..., attack_damage=true)`对存活敌人逐段削1层，全挡／0伤攻击也削；裂伤、污染和弹反的普通伤害不削。伤害结果与敌方攻击事件携带电能展示快照，动画只更新展示，不重复改模型。旧战斗意图与层数沿用冻结快照；新开正式／演练采用当前配置。

### 切换 弹药与裂伤施加

`change_stance("melee"/"ranged"/"toggle")` 只有实际切换才发奖励：进入近战 `draw_cards(2)`；进入远程设 `stance_discount=true`。该减费保留至下一张攻击，即使后来切回近战也不会清掉；重复进入远程不叠加。开场初始化为近战不算一次切换，不额外抽牌。

09切入斩按“两段伤害 → 切近战”配置，资源和本体倍率取出牌前形态，切换奖励随后生效。10快速装填是技能，按“补2弹 → 切远程”执行，不攻击、不额外消耗通常弹药。视图按实际卡牌类型区分：攻击先展示命中再切换，技能立即开始切换并与退场飞牌并行；本牌形态仍读取返回的 `result.stance`。

`gain_ammo()` 将增加后的弹药限制在 `profile.ammoCap`，溢出不保留。新战斗上限10，既有快照显式的旧上限继续保留；HUD读取同一profile。近战普通回弹在每个实际攻击段后发生，群攻同一damage效果的同序段只计一次；命中结果的临时ammoAfter用于逐段显示。17枪口重击先结算攻击段的普通+1，再结算卡面额外+2，两者共同受上限限制。只读预览独立推演HP／格挡以计算实际可执行段数，不改变原有潜在伤害文案或全局随机序列。

`apply_bleed()` 对远程卡牌的施加量使用 `roundi(amount * 0.5)`。30 号在近战且目标出牌前已有裂伤时，把基础施加量换成 `woundedMeleeAmount=6`。旧能力`dissection`只在近战、单敌目标、施加量大于0且目标仍活着时，首次额外+1，并设置`dissection_used`；群攻、远程和弹反不触发旧能力。当前40号授予`melee_attack_bleed`，按每段近战攻击命中施加裂伤，不再加成技能施加量，详见本轮说明。

### 双人舞者意图、连接与专用卡（2026-10-25）

一阶段黑舞者80 HP，按「攻击15 → 攻击10并施加2层虚弱」循环。二阶段黑、白舞者各80 HP；黑舞者按「攻击10 → 攻击8 → 强化：给存活白舞者增加2点力量」循环，白舞者按「施加2层虚弱 → 攻击3×3 → 给存活的黑舞者恢复10 HP」循环，治疗不超过最大生命、不复活。第三步强化独立于灵魂连接，仅对白舞者存活时生效；力量本场累加，每层使每段基础伤害+1，因此强化一次后白舞者下一次攻击为5×3。攻击数值为基础值，实际伤害受力量、虚弱与易伤影响。

二阶段双方初始各1层灵魂连接。每个敌方回合开始时（双方行动前，先清除双方上轮格挡），存活黑舞者有连接则给存活白舞者10格挡，存活白舞者有连接则给存活黑舞者2力量；连接存在时效果固定，0层停止；任意一方死亡后双方连接均不再触发，存活者的连接层数不自动清零，已获得的力量不移除。二阶段开启的新玩家回合不触发连接；新获得的10格挡保留经过下一玩家回合，到下次敌方回合开始再清除。进入二阶段时向抽牌堆随机位置各加入一张黑卡／白卡，然后正常抽新手牌；均1费，黑卡移除白舞者1层连接，白卡移除黑舞者1层连接，打出后消耗，进入本场消耗区，不再循环抽回。只用于本场战斗，不进入拥有牌、商店或奖励。玩家虚弱使攻击伤害降低25%，逐段四舍五入，自身回合末减1层；一阶段攻击附带虚弱即使全被格挡也施加，整次攻击只施加一次。

黑舞者第三步复用`strength_allies`，`amount=2`、`targetIds=["dancer_white"]`，只给存活白舞者累加力量，输出与灵魂连接分开的`status_apply`事件；舞者冻结意图校验允许该类型并检查目标数组非空、ID有效。该技能不依赖连接层数，强化提示明确显示白舞者；旧冻结`vulnerable`意图仍可读取。

`data/cards/dancer_encounter_cards.json`通过`profile.phaseTwoCards`冻结并合入局内卡目录，创建`encounter_dancer_black_card`／`encounter_dancer_white_card`两个UID；不修改全局40张目录。新效果`remove_soul_link`使用`enemyId`自动定位，打出后按`exhaust:true`进入消耗区。转阶段随机插入只执行一次，恢复快照不再生成。新战斗冻结`phaseOneEnemies`，旧快照缺该字段时仍按旧二阶段黑舞者定义校验一阶段。开局快照与实时快照实例差异仅允许二阶段新增的两张专用卡。

`weak`扩为双方状态，玩家存于`norenState.weak`，旧档缺失默认0；原敌方weak牌默认目标继续为enemy。`soul_link`存于敌方可选`buffs`，上限2、不自动衰减。`begin_dancer_enemy_turn()`在玩家回合末状态结算且战斗未结束后、任何舞者行动前执行：先清理存活舞者上轮格挡并返回`block_clear`，再给予交叉增益，返回`status_apply`并标记`clearSourceBlock:false`；舞者各自动作前不再重复清理本轮新格挡。转阶段与新玩家回合不触发连接，揭幕时没有预先给予的连接增益。玩家阶段的攻击预告计入即将触发的白舞者连接力量，并随连接移除／来源死亡即时更新；敌方演出读取已结算的展示状态，不重复预加力量。治疗意图`heal_ally`返回实际恢复量及`hpAfter`，动画只展示模型结果。攻击意图`onHitWeak`在整次攻击后施加一次虚弱。

本仓库格挡展示继续消费模型显式`block_clear`事件，`status_apply`、治疗及攻击展示起点不会额外清除来源格挡；电能、防护服与猎犬的既有事件流程保留。

### 双人舞者转阶段的新回合

进入二阶段即开启新的玩家回合：弃置旧手牌，按正常玩家回合结束规则结算污染／易伤并清除临时加成；存活时回合数加1，清空格挡、恢复每回合能量并抽新手牌（默认5张）。形态、弹药和跨回合能力保留，科技冷却只推进一次，开局额外抽牌不重发，新舞者本次不行动。弹反或敌人回合末污染触发时，已经执行的玩家收尾不重复；玩家回合末状态若致死则直接判负。

规则只在模型结算并提交一次。`advance_encounter_phase()`保留bool返回，额外通过`transition`返回弃牌／抽牌／玩家回合末事件；出牌结果的`phaseTurnEvents`供视图在一阶段命中后展示。普通出牌转阶段会展示一次“第N回合”并发新手牌；敌方阶段触发时复用既有新玩家回合展示。动画结束不再增加回合、扣血或修改牌堆，普通敌人战斗回合规则不变。

| 正面 | `persistent_bleed` | 深度伤口 | `powers`；整场裂伤触发不减层，同名不叠加 |
| 正面 | `technology` | 科技增伤 | `next_attack_bonus`；未使用时跨回合保留 |
| 正面 | `next_discount` | 本回合攻击减费 | `turn_discount`；使用或玩家回合结束清除 |
| 正面 | `stance_discount` | 形态攻击减费 | 布尔 `stance_discount`；不叠加，跨回合保留至下一攻击 |
| 正面 | `high_pressure` | 高压枪机（旧快照兼容） | `powers`与`pressure_used`；旧能力每回合首次远程攻击生效，新23号不再授予 |
| 正面 | `dissection` | 剖解经验（旧快照兼容） | `powers` 与 `dissection_used`；每回合首次近战单体卡施加裂伤生效 |
| 正面 | `melee_attack_bleed` | 剖解经验 | `powers`；近战每段攻击命中后对存活目标施加1层裂伤，多段／群攻逐段逐目标，无回合次数限制 |
| 负面 | `bleed` | 裂伤 | 敌人 `bleed`；远程默认每段触发1次，37号近远均2次；深度伤口生效后不减层 |
| 负面 | `weak` | 虚弱 | 双方 `weak`；固定减伤 25%，自身回合结束减 1 层，最多 999 层 |
| 负面 | `pollution` | 污染 | 双方可选 `buffs.pollution`；自身回合末按层数造成伤害（先扣格挡）再减1，最多999层 |
| 正面 | `strength` | 力量 | 双方可选`buffs.strength`，每段攻击基础+层数，−999～999，跨回合保留，Buff伤害排除 |
| 负面 | `vulnerable` | 易伤 | 双方可选`buffs.vulnerable`，攻击受伤×1.5逐段取整后扣格挡，自身回合末减1，上限999，Buff伤害排除 |

能量、弹药、形态、抽牌、直接伤害和科技冷却仍各自承担资源／动作职责，不分类为 Buff。`parry_fill` 是施加弹反的方式，`power` 是施加持续能力的方式，不重复注册成状态。

### 使用已有 Buff

```gdscript
var Buffs = model.buffs # CombatBuffs 实例，随战斗模型释放缓存
Buffs.definitions(Buffs.POSITIVE) # 返回定义副本，可按分类浏览
Buffs.definition("bleed")
Buffs.apply(model, "next_damage", 4) # 玩家状态
Buffs.apply(model, "weak", 1, enemy_index)
Buffs.count(model, "weak", enemy_index)
Buffs.clear(model, "weak", enemy_index)
```

科技增伤标记 `cardApply:false`，必须经 `activate_cyberware()` 连同冷却记录一起产生，以满足原存档来源校验，不能直接由卡牌添加。

直接 `apply()` 是原始施加。卡牌裂伤必须经 `apply_card_effect()` 或 `model.apply_bleed(index, amount, stance, single)`，以保留远程减半与旧`dissection`兼容加层；当前剖解经验由攻击命中钩子触发。弹反不再施加裂伤，每次反击通过 `gain_ammo(1)` 补弹。全部施加操作只能发生在模型结算阶段，UI 只读取 `player_badges()`／`enemy_badges()`；玩家弹反图标使用动画中的 `shown_player_parry`，不提前显示最终层数。

### 添加一种简单 Buff

下面是**接入示例，未加入正式目录或卡牌**。把新对象加入 `buffs.json`，可复用现有的攻击增伤行为：

```json
{
  "id": "focus",
  "name": "专注",
  "category": "positive",
  "target": "player",
  "stacking": "add",
  "maxStacks": 6,
  "duration": "player_turn_end",
  "handler": "attack_bonus",
  "consumeOnAttack": true,
  "icon": "damage",
  "color": "f17988",
  "showBadge": true,
  "description": "专注 · {count}\n本回合下一张攻击牌每段基础伤害增加该数值；使用或回合结束清除。"
}
```

卡牌的有序 `effects` 中引用：`{"type":"buff","id":"focus","amount":4}`。已有卡牌的 `next_damage` 等写法无需改动。卡牌目标继续由 `target` 决定；敌人状态施加到该牌确定的目标数组，`both` 状态默认施加给玩家，需要时明确 `buffTarget:"enemy"`。未知 ID 或不匹配的持有者在消耗能量前拒绝。

- 新定义省略 `field`、`saveKey`，使用通用存储：玩家 `model.buff_state`／快照可选 `buffs`，敌人可选 `enemy.buffs`。空容器不新增到玩家快照，旧档缺字段默认为空；JSON 读回后统一为整数层数。无需为每个简单 Buff 再加模型变量、Game 白名单或 HUD 分支。
- `stacking`：`add` 累加并可用 `maxStacks` 截断；`flag`／`unique` 保留单份；`guarded_add` 保留弹反的施加前判断，仅用于需要该语义的效果。`duration`：`battle` 跨回合保留、`player_turn_end` 在玩家结束回合时清除、`own_turn_start` 在持有者开始回合时清除、`own_turn_end_decay` 在持有者回合结束时减 1 层，由 `own_turn_end()` 处理（用于虚弱、污染、易伤）。
- 通用 `handler` 目前支持玩家 `attack_bonus`（所有来源均逐段生效；`everyHit:true`由`attack_segment_bonus()`捕获，其余由`begin_attack()`捕获）、`attack_discount`（攻击能量减费）。是否用后清除由 `consumeOnAttack` 决定。`none` 只提供状态存储／显示／生命周期，不会自动造成伤害或改变资源。裂伤、虚弱、弹反、格挡及形态倍率／裂伤保层等能力为专门逻辑，不能换一个 ID 就复用这些专门处理器。
- 全新机制应在效果库的对应时点实现：`begin_attack`、`attack_segment_bonus`、`after_attack_hit`、`enemy_attack_damage`、`after_enemy_attack`、`player_turn_end`、`own_turn_start`，同步注册处理器校验与测试；需要全新结算时点时才扩展模型调用点。`category` 不是伤害系数；新图形仍在 `status_badge.gd` 绘制，也可复用现有 `icon`。
- 现有 `field`／`saveKey`／`usedField`／`usedSaveKey` 是旧存档兼容映射，不应复制到新定义；原状态数值仍只有一份。`catalog_errors()` 校验分类、行为名、叠加与显示字段，存档校验从目录读取状态边界。
- 效果目录随当前程序加载，不冻结在旧战斗快照中；保留 `high_pressure`、`dissection`旧ID及行为，新能力使用独立ID。日后修改已有 ID 的规则、删除 ID、改变上限或目标时，仍需处理旧档兼容，不能假设换了统一库就自动完成迁移。

验证入口：`tests/combat/rules/buff_library_tests.tscn` 覆盖分类、叠加、生命周期、旧字段、展示副本、新正面／负面状态的存储与 JSON 往返；`tests/combat/cards/noren_cards_tests.tscn` 覆盖原 40 牌。改到显示链路时再运行 `tests/combat/cards/noren_cards_visual.tscn`。

## 通用效果执行器

以下名字是 `effects[].type`，不是要额外调用的函数。除 `stance`、`power` 等使用 `value` 的效果外，数值通常读取 `amount`。`when` 可为 `melee`／`ranged`，省略则不限制；`requiresBleed` 是本效果的前置条件，当前用于39号在目标出牌前至少3裂伤时额外抽1张。

| 效果 | 对应状态或行为 | 必须保持的边界 |
| --- | --- | --- |
| `damage` | 对已确定的目标数组执行伤害；`hits` 默认 1 | 每段通过 `enemy_damage`，死亡提前停止；特殊参数见上节 |
| `block` | 玩家 `block += amount` | 不等同于治疗，不改 `player_hp` |
| `ammo` | `gain_ammo(amount)` | 与攻击普通耗弹／回弹分别处理 |
| `draw` | `draw_cards(amount)`，记录抽到的 UID | 在现有手牌数上增加，可超过 5；正在使用的牌不能被抽回 |
| `stance` | `change_stance(value)`，合并奖励抽牌 UID | `value` 仅支持两种形态和 toggle；顺序决定先攻击还是先切换 |
| `weak` | 对活目标累加虚弱，最多 999 | 固定降低攻击伤害 25%，该敌人回合结束减 1 层 |
| `bleed` | `apply_bleed`，含远程减半、旧伤条件、旧`dissection`兼容加层 | 施加与远程触发是两条不同路径 |
| `parry` | 当 `parry < cap` 时加 `amount`，全局最多3层 | 当前03／31／32／33都加1；31／32保留各自卡面条件，所有获得与补层最终受3层上限限制 |
| `parry_fill` | `parry = max(parry, amount)` | 保留旧33号快照补至2的兼容，新33号改为普通加1；不降低已有层数 |
| `next_damage` | 累加 `turn_damage_bonus` | 下一张攻击用掉，可叠加并跨回合保留 |
| `next_discount` | 累加 `turn_discount` | 同上；实际费用最低 0 |
| `power` | 唯一追加 `value` 到 `powers` | 同名不叠加；重复打出依然支付费用并进入消耗区 |
| `exhaust_hand` | 所选另一张任意类型手牌UID：手牌 → 消耗区 | 使用 `exhaust_candidates(uid)`，排除自身；按UID保留同名实例区分，所选牌不执行效果，非法选择原子失败 |
| `discard_attack` | 旧快照兼容：所选攻击牌UID从手牌进弃牌区 | 仍用 `discard_candidates(uid)`，只选本牌之外的现有攻击牌；新12号不使用此效果 |
| `buff` | 效果库按 `id` 施加已注册状态 | 原子验证 ID／持有者，按原数组顺序执行 |

2026-10-17 起，持续状态效果统一交给 `CombatBuffs`。现有卡牌效果类型保持兼容；新 Buff 使用 `type="buff"` 与注册 ID。伤害、抽牌、弹药、形态和弃牌仍是即时动作，由模型负责。全新触发机制仍需在效果库实现并测试，不能只添加名称就获得行为。

## 回合结束与弹反

`end_noren_turn()` 一次调用完成整次敌方行动和下一玩家回合的准备，不要按敌人逐个再次调用。

1. 剩余手牌全部移到弃牌区，结算玩家回合末污染，清空本回合增伤和本回合减费。污染先按层数扣格挡／HP，再减1；若玩家死亡立即停止，不执行敌人意图。
2. 按本轮已显示的意图、依 `enemies`数组顺序处理活敌人，并清空该敌人格挡；此时不检查黑帮阶段切换。当前支持 `attack`、`pollution`、`strength_allies`、`vulnerable`意图；非攻击意图不触发弹反，但仍结算该敌人回合结束。
3. 每段先将敌人力量加到意图基础值并限制最低0，再按虚弱固定25%减伤四舍五入；玩家有易伤时再逐段乘1.5并四舍五入，随后扣玩家格挡与HP。若该段实际扣血且敌人配置 `attackPollution`，追加该数值污染；玩家归零时停止剩余段。
4. 如果玩家有弹反且攻击者存活，只反击一次，请求伤害为 `roundi(本次敌方攻击总量 * 0.5)`，获得1颗弹药（包括反击致死，受弹药上限约束），不施加裂伤。结果保留原 `bleedAfter` 并新增临时 `ammoAfter`，视图在反击命中时展示对应弹药数量，不再次修改模型。
5. 每次触发消耗1层，层数只决定剩余可触发次数。例：3层面对三个敌人的三次攻击，各反击一次并各获得1颗弹药，最终剩0层；一名敌人的多段攻击合并为一次触发。
6. 该敌人回合结束，污染先造成层数伤害再减1层（已死亡者不触发），虚弱减 1 层（最低 0）；非攻击意图也消耗 1 层，多段攻击只消耗 1 层。然后判定结果：玩家 HP 为 0 优先失败，否则全敌死亡为胜利。结束则停止处理后面的敌人。
7. 若战斗继续，回合数 +1，玩家格挡清零，能量重置为 3，重置 `pressure_used`、`dissection_used` 和科技冷却；先推进全部敌人意图索引，再调用 `begin_round_intents()`检测小弟死亡、必要时重置老大阶段与游标为攻击8，并将 `intent_change`追加到 `turnEvents`末尾；最后抽牌补至5。这是下一玩家回合的边界，玩家阶段击杀小弟后，当轮老大仍执行已显示的强化。

**弹反基数的准确口径：**每段先加敌人力量、应用虚弱，再应用玩家易伤，取整后乘意图声明的 `hits`；不扣玩家格挡，也不按玩家实际掉血量计算。反击自身不再叠加力量、易伤或远程倍率。当前代码即使玩家中途死亡，也按声明的完整段数计算反击基数，并在反击后按“玩家死亡优先”判失败。若以后设计要求死亡即禁止反击或只计算已发生段数，需同时调整 `end_noren_turn()`、显示逻辑与边界测试。

2026-10-25攻击附带虚弱：`enemy_intent.gd`读取冻结攻击意图的`onHitWeak`，在原96×66区域内并列显示攻击与虚弱图标，各自显示伤害预览和层数；无附带虚弱时保留原单图标居中样式。图标现使用`assets/icons/intents/`下64×64透明SVG，以40×40显示并使用线性mipmap过滤；九类意图与未知回退统一使用切面／高光，具体映射及制作说明见该目录README。图标子节点忽略鼠标，tooltip仍挂在原意图根节点；`setup()`重用时清理旧图标和旧数值。普通意图伤害字符串及悬停说明保持原接口，不在视图施加状态。

## 抽牌 消耗与恢复

2026-10-26双人舞者转阶段计数：模型已提交新手牌、但动画尚未发牌时，`battle.prepare_phase_deal_counts()`在揭幕前重建显示起点。待发牌数仅统计还没有卡面节点的手牌，待回收总数仅统计这些UID对应的`pending_recycles`；显示抽牌数为“模型抽牌堆剩余数 + 待发牌数 − 待回收数”，显示弃牌数为“模型弃牌堆剩余数 + 待回收数”。随后继续由原发牌／洗牌回调逐张更新，落稳后统一对齐。该函数只写展示计数，不改模型、快照、随机顺序或真实牌区；控制台恢复没有待播洗牌事件时也能重建对应的发牌起点。见[无窗口逐事件专项](../tests/combat/presentation/dancer_pile_count_tests.tscn)。

`draw_cards()` 不传数量时**补到** `profile.handSize`，当前为 5；`draw_cards(n)` 则在现有手牌上**额外抽 n 张**，不受 5 张限制。抽牌使用抽牌堆末端 UID；堆空时按配置回收整个弃牌区并洗牌，抽牌区与弃牌区都空则停止。消耗区不参与回收。

新诺伦战斗初始化时洗牌，旧规则沿用原初始化逻辑。`draw_cards()` 标记 `opening_draw_done=true`；视图 `start_hand()` 仅在标记为 false 时执行开场抽牌并提交。因此“首回合、手牌空、弃牌空”不能代替新快照的开场标记，尤其不能用于所有牌都消耗后的读档判断。

新快照的四区守恒在 `Game.valid_combat()` 检查。仅把 `exhaust_pile` 加进模型还不够，存档校验、恢复、消耗区浏览和相关测试必须一起跟进。消耗是本场离开抽牌循环，不删除局外拥有牌；能力从本场循环移除后，其效果通过 `powers` 继续生效。

## 快照与存档兼容

### 保存了什么

`CombatModel.snapshot()` 保存以下分组；`restore()` 按保存值恢复并复制数组／字典。

| 分组 | 字段 |
| --- | --- |
| 战斗与玩家 | `battleId`、`turn`、`playerHp`、`maxHp`、`outcome`、最近 30 条 `log` |
| 卡牌 | `instances`、`drawPile`、`hand`、`discardPile`、`cardCatalog` |
| 敌人与规则 | `enemies`（HP、格挡、裂伤、虚弱、意图、索引等）、`profile`（包括规则标记、牌组、角色和科技配置） |
| 科技 | `usedCyberware`、`nextAttackBonus`；内部名称保留兼容，界面称“科技” |
| 开场 | `openingDrawDone` |
| `norenState` 数值与形态 | `energy`、`block`、`stance`、`ammo`、`parry` |
| `norenState` 牌区与能力 | `exhaustPile`、`powers` |
| `norenState` 待消费与回合标记 | `turnDamageBonus`、`turnDiscount`、`stanceDiscount`、`pressureUsed`、`dissectionUsed` |
| 通用Buff | 顶层可选 `buffs`，其中 `next_hit_damage` 保存逐段待消费增伤；新能力仍保存在 `norenState.powers` |

`Game.commit_combat()` 更新 `state.combat` 与冒险当前 HP，增加 `revision`，正式战斗按保存开关写盘，发送 `status_changed`。**不能用 `checkpoint()` 替代它**：后者发送 `changed`，可能重建视图并销毁仍在播放动画的节点。

### 校验与旧档边界

- 冒险 `schemaVersion` 仍为 2。旧无 `ruleset=noren_v1` 的战斗继续走旧执行器；新诺伦快照要求 `norenState` 和布尔型 `openingDrawDone`。
- `valid_noren_state()` 检查主要资源为有限、非负整数；能量不超过回合配置，弹药不超过上限，弹反最多 3、虚弱最多 999；形态合法、能力白名单无重复、回合标记为布尔值。
- 四区中的 UID 必须唯一且全部属于 `instances`，对应定义必须在 `cardCatalog`。增加新牌区时必须修改这条守恒链。
- 旧科技、旧测试牌、旧待领奖励有兼容路径；不要直接删旧 ID。`restore()` 有缺少开场标记时的历史推断，但新诺伦存档校验仍要求该字段，不能把恢复函数的回退误当成迁移已经完成。
- 进行中的战斗使用快照里的参数、卡目录与敌人数据；修改 JSON 后应开新战斗验证。**快照冻结数据，不冻结 GDScript 执行器**；若改变 `noren_v1` 的解释方式，旧快照也会受影响，需要新的规则版本或明确迁移。
- 新 Buff 优先使用统一库的可选 `buffs` 存储，按目录自动保存／恢复／校验。额外的非层数数据或全新状态字段仍需同步初始化、结算、快照、恢复、校验及旧档兼容，并补 JSON 往返测试。

完整磁盘恢复流程和备份轮换边界见[维护文档](维护文档.md)。测试时先设置独立 `save_path`、`meta_path`；`save_enabled=false` 不能替代隔离路径，因为测试可能直接调用保存函数。

## 模型结果与界面同步

2026-10-17：`end_noren_turn()` 新增有序 `turnEvents`，包含 `status_tick`（污染伤害与减层）、`status_apply`（主动污染）、`attack`（含明确敌人数组index）。`attacks`保留兼容查询。每段攻击的 `pollutionAfter` 及状态事件的 `stacksAfter / hpAfter / blockAfter` 驱动显示快照，按实际先后展示；不能用模型整轮最终污染提前刷新中间命中。污染伤害只调用普通伤害入口，不调用攻击追加或弹反钩子；玩家或敌人污染致死也播放受击／退场。

当前两只鱼定义 `deathPollution=3`，双杀合计6层：统一敌方伤害入口在存活转为死亡时施加污染，再由调用者判定胜负；无需保存额外触发标记，已死亡对象不会重复触发。返回命中的 `deathPollution` 与 `playerPollutionAfter` 描述本次死亡效果和当时玩家污染层数；裂伤并入攻击结果时保留这两项，弹反和敌人污染事件沿用。界面在对应致死命中／状态事件时展示，不提前读取最终模型层数。旧快照缺少该配置时仍默认为0；若显式保存 `deathPollution=5`则继续每只5层，不以新目录的3层覆盖。攻击接触污染仍为每实际扣血段2层，主动污染意图仍为3层。

右上角当前卡组入口由 `DemoUI.status_bar()` 调用 `Game.open_current_deck()`，通过 `current_deck_requested` 通知 `main.gd`。复用 `card_library.gd.setup_current_deck()`：非战斗复制拥有数量和定义；战斗复制快照 `cardCatalog`，对 `instances.values()` 计数，覆盖所有牌区并保持旧战斗定义。只排序展示副本，不排序牌堆，控制台新增牌已在本场 `instances` 中，因此立即计入当前浏览；只改拥有牌而未进入本场快照的卡不计入。当前卡组模式隐藏“全部卡牌”切换，关闭信号恢复原视图，不改页面、战斗与存档。模态打开前取消已有攻击选择，原非攻击牌优先消费点击的规则不变；需先取消才能按顶栏按钮。

`card_console.gd` 打开时从 `Game.library_cards()` 建立四列可滚动按钮列表，当前 40 种卡牌可同屏显示。每项展示牌名、品级颜色与已有数量；点击按 ID 调用 `Game.console_command("addcard <id> 1")`，随后从 `owned_card_counts()` 刷新数量。文本命令也刷新同一列表，关闭时沿用 `main.gd` 的牌库刷新。加牌权限、保存失败回滚与快照提交由 `Game` 负责；关闭控制台时 `battle.resume_console_combat()` 同步模型与展示。专项 `tests/combat/cards/card_console_visual.tscn` 验证 GUI 点击、重复添加、读档、回滚与关闭刷新。

`Game.console_command()` 只解析 `help`、`cards`、`owned`、`addcard`、`kill`，没有任意代码执行。使用方法见[控制台说明](诺伦卡牌与控制台.md)。`addcard` 要求开发模式、已有冒险、不忙碌且没有待重试保存／转场；名称／编号／ID 解析后，数量必须为 1～99 的整数。

正式冒险加牌追加 `state.deck`；进行中的战斗还通过 `CombatModel.add_cards_to_draw_pile()` 创建唯一 `console_` 实例并放入抽牌堆顶，不移动已有牌。保留已有冻结定义，缺失定义才补入目录，同时扩展实时与 `battleStart` 的 `profile.deck`、`cardCatalog`、`instances` 和 `drawPile`，二者使用同一 UID，不把中局状态写成开局。旧档无开局记录时只扩展实时快照。写盘失败整体恢复旧状态；关闭自动保存仅改内存。演练只扩展本场快照，不改 `state.deck`。新委托清空额外牌。

`kill` 通过 `CombatModel.kill_enemies()` 对当前存活敌人调用无视格挡的致死伤害，保留死亡效果，再统一结算胜负与Boss转阶段。命令保存成功后递增revision；失败恢复整个状态。控制台成功提交 `kill` 后自动关闭，视图恢复新快照、牌堆及敌方HUD；转阶段时退休旧手牌视图并播放既有开灯／新回合／发牌，最终胜败沿用 `finish()`。非战斗、已有结局、忙碌、转场或待保存时拒绝。

新战后奖励按冻结战斗类型从36种非C牌中选三个不同定义：先按 `data/card_reward_rates.json` 的B／A／S概率抽品级，再在该级剩余卡中等概率抽取。普通60／37／3，精英50／40／10，Boss0／0／100；固定概率，无隐藏保底。基础奖励固定50信用点，在奖励页点击信用点条目才到账；金钱芯片额外信用点合并同次领取，治疗仍在胜利时执行。信用点和选卡分别保存领取状态，离开将放弃未领项目；旧已到账记录不再发放，已生成候选不重抽。抽样职责为 `scripts/card_reward_sampler.gd`，配置和卡池不足以生成三张时不结算。

`start_training()` 备份完整冒险，创建当前角色的新状态，并复制实际拥有牌、移除记录及携带科技。`initialize_combat()`按当前正式敌人定义初始化，不覆盖敌人生命。主菜单的七个选项由`data/training_enemies.json`引用B02／B04／B11／B13／B14／B15／B16，`start_enemy_training()`复制完整战斗配置为临时战斗，不复制或注册临时敌人；Boss两阶段配置同样保留。

演练固定使用正式战斗地点，菜单不提供场景选择。`training_scenery_place_id`仅保留给开发工作台背景预览，普通演练开始与恢复时清空。演练的战斗提交不保存冒险、不发正式奖励；结束或退出恢复`training_backup`并删除临时战斗。演练中加牌仅本场有效，不写永久拥有牌。独立动作测试入口是开发工具，不属于七项玩家演练。

### 发生修改时必须逐项复核的边界

- 费用恰好不足／恰好足够、叠加减费到0、普通弹药0／1／10；火力倾泻1／3／10弹对应2／4／11段且无选择框；旧快照额外耗弹0／上限／越界。
- 同形态不重复发奖励、攻击后切换使用旧形态、切换减费跨回合与跨形态保留。
- 逐段取整、格挡恰好耗尽、本体致死后不再裂伤、裂伤致死后不再追加段、新裂伤后置。
- 处决恰好50%；追猎近远均2次裂伤、裂伤1层时第二次归零停止、持有深度伤口时不减层；血迹追踪裂伤2／3门槛与额外抽1；近战旧伤3／6施加分支。
- 弹反0／1／2／3、全额格挡仍可反击、多敌依次消耗、玩家与敌人同次归零的失败优先。
- 新拆卸弹药无其他手牌时拒绝，可消耗另一张攻击／技能／能力牌；重复同名实例只移走指定UID；自身／非手牌／缺失选择原子失败。旧 `discard_attack`仍只允许攻击牌且保留原去向；重复能力扣费不叠加，抽牌不能抽回自身。
- 开场前保存、开场后首回合打空、全消耗、抽弃牌都空、回收中抽牌、JSON 往返后再出牌。
- 同一 UID 重复提交无效、模态输入不穿透、动画节点不再次扣血、存档不会落在出牌中间状态。

这是一份后续改动的核对清单，不表示每一项已有独立自动测试。新增或改变其中某项时，把对应场景补进相关专项，并记录实际运行证据。

## 常见故障定位

| 现象 | 先检查的位置和原因 |
| --- | --- |
| 加了牌但当前手牌／抽牌堆没有 | 检查 `console_` 实例是否加入实时抽牌堆及开局快照，关闭控制台后模型与计数是否同步；已有手牌不会因加牌自动变化 |
| 改 JSON 数值后旧战斗没变化 | 快照保存 `profile`、`cardCatalog`、敌人；用新战斗核对，禁止静默覆盖玩家局内状态 |
| 远程多段伤害差 1～几分 | 是否逐段 `roundi`；各来源增伤是否对每段生效且整张牌仅消费一次；裂伤是否在每段本体后结算 |
| 切入斩／快速装填弹药或动作不对 | `at_start`与最终形态是否混用；09先两段攻击后切换，10是先补2弹再切换的技能；检查实际type和效果顺序 |
| 弹反被多段攻击消耗过快 | 是否误把整次攻击的弹反改成逐段处理，或每次反击都扣层数 |
| 牌越抽越多或读档补发 | `openingDrawDone`、`draw_cards()` 与 `deal_hand()` 职责、正在使用的牌是否过早入弃牌区 |
| 消耗牌读档失败或抽回来了 | 四区守恒、快照 `norenState.exhaustPile`、回收是否误包括消耗区 |
| 动画后血量二次减少 | 是否在命中回调再次调用 `enemy_damage`／`play_card`，或把 `shown_enemies` 写回模型 |
| 飞行残影拦住点击或重复使用 | `cards.erase(uid)`、卡及按钮的鼠标过滤、忙碌锁是否齐全 |
| 刚激活能力就读档失败 | 新能力是否补进 `valid_noren_state()` 白名单；新状态是否同时保存恢复 |
| 测试通过却无法实际出牌 | 测试夹具是否跳过了弹窗、目标选择、忙碌锁或真实视图创建；补对应输入验证 |

排错时记录：版本、战斗 ID、是否演练、出牌 UID／定义 ID、目标、出牌前能量／形态／弹药／状态、选择参数、模型返回结果、预期与实际，以及是否旧档。需要复现快照时复制到测试路径，不覆盖玩家正式存档。

## 扩展与交付约定

1. 先确定是现有效果组合、增加参数，还是增加新机制。确认形态、目标、资源、取整、触发时点和状态生命周期后再实现。
2. 现有效果组合可修改 `cards.json`，但必须同步文案和逐卡表；新的效果／能力还需修改模型、输入选择或展示、保存恢复和校验。
3. [schema.json](../data/cards/schema.json) 仅为结构参考，当前没有运行时自动验证；不能用“符合 schema”代替模型、内容引用与边界测试。当前模型也不保证处理任意恶意或损坏的效果对象。
4. 当前诺伦结束回合直接弃掉全部手牌，未根据 `discardHandAtTurnEnd=false` 分支执行；只改该配置不会得到保留手牌规则。`handSize`、`ammoCap` 等可读参数仍要结合存档校验与界面一起验证。
5. 当前敌人支持攻击、污染、力量强化、易伤等已接入意图；当前牌池的能力ID为 `ranged_mastery`／`persistent_bleed`／`melee_attack_bleed`，旧`dissection`与`high_pressure`仍注册兼容，以及表中效果。新能量增长／上限、更多弹反层数、保留牌、复制牌、召唤敌人等都需要显式设计与扩展，不能套用当前已验证范围。
6. 修改既有语义时同时决定旧战斗的处理方式；新规则标记不能只改一个字符串，分派、初始化、迁移和验证必须一起维护。
7. 保留修改前副本和必要的存档备份，在独立路径验证；将真实通过／失败结果写入[修改记录](修改记录.md)，同步本指南、卡表和玩家说明。不要用删断言或把所有敌人调成 3 HP 的办法掩盖多段／状态问题。

## 2026-10-19 力量与易伤执行边界

力量在`attack_hit_amount()`逐段加到基础值，远程形态随后乘通常1.5或弱点瞄准的2，基础最低0；敌人`enemy_attack_damage()`先加力量再套虚弱。易伤仅由攻击本体的`enemy_damage(..., true)`第四参数／`player_damage(..., true)`第二参数启用，逐段放大50%并四舍五入，然后扣格挡。默认调用仍为Buff伤害路径，污染、裂伤和弹反不增加伤害。玩家意图预览考虑自己回合末先减一层，卡牌预览只对攻击damage行放大，不改变bleed_damage行。力量通用存储允许负值，目录`minStacks:-999/maxStacks:999`与快照校验一致，负值也显示图标。易伤新增`status_decay`，视图使用显示副本按有序事件更新。老大阶段切换只在完整回合结束、下一玩家回合开始时发生，细节见[开发接入说明](开发接入说明.md#2026-10-19-后巷三人战接口)。
