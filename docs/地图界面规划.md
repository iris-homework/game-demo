# 地图界面重构规划与任务表

本表把当前讨论转为可执行的地图工作安排，供后续分阶段开发和验收使用。
规划日期为 **2026-10-07（Asia/Shanghai）**，游戏基线为 **0.2.3-r1**。
本页保留实施前的讨论与建议。用户随后授权自主制作，已在 **0.2.4-r1** 接入；
当前行为见[游戏规则](游戏规则.md)，完成情况见[地图制作 TODO](地图制作TODO.md)，
本轮实测见[地图界面验收清单](地图界面验收清单.md)。下文“现状”指规划时基线，
不能据此将已完成的接入继续视为待实现。

## 已确认方向与实施建议

用户已同意以下地图方向。尺寸、碰撞避让及具体交互细节仍需在样板中检验。

- 参照《欺诈之地》的城市总览插画与点击标记交互。
- 使用 [map.jpg](../assets/map/map.jpg)，让地图占据主要空间，取消常驻右侧大栏。
- 当前所在地使用青色提示，并在地点标记旁放诺伦小头像。
- 下一步主线目标使用金黄色，其他可用事件使用较低亮度的青色提示。
- 当前地点同时是目标时，显示金色地点标记和青色头像。
- 鼠标悬停显示简介，任务地点展示更多任务信息；点击固定详情后明确确认进入。
- 查看、悬停和选中不改变所在地；实际进入地点或开始当地事件才更新头像位置。
- 地图不增加行走、寻路、碰撞、旅行费用或自动推进日期。

下文标为“建议”的细节是本次实施提案，不代表已完成或额外玩法已获确认。
总体方向见 [美术方向](美术方向.md)，实际现状见
[游戏规则](游戏规则.md)和[游戏流程与路由](游戏流程与路由.md)。

## 当前工程依据

已有数据和组件可以复用，但以下边界必须在开发时明确区分。

| 内容 | 核对到的现状 | 对规划的影响 |
| --- | --- | --- |
| 城市底图 | 图片已在工程；`city_map.path` 仍为空 | 需要正式资源接入，不重新生成城市底图 |
| 地点 | `data/places.json` 有 16 个地点，比例坐标为调试布局 | 逐个校准，保留全部现有入口 |
| 图标 | 已补齐十七地点图标及三种外框，详见地点图标样板 | 优先复用；美术预览不等于正式接入 |
| 当前所在地 | `currentPlaceId` 由 `visit()`、`start_event()` 等流程更新 | 头像读取真实状态，不读取点击选中状态 |
| 可用事件 | `available_events()` 排除完成事件并判断事件条件 | 还要判断地点本身是否开放 |
| 当前目标文字 | `objective()` 取第一个可用主线，或显示无目标／周完成文字 | 目前没有独立目标 ID 查询和明确的多主线优先级 |
| 活动事件 | 完成事件后 `activeEventId` 仍保留 | 不能直接作为金色目标或进行中判据 |
| 治疗 | 地图和地点页可治疗；`heal_at()` 不移动角色并会刷新视图 | 保留现有流程，检查头像和固定详情的刷新 |
| 地图信息 | 原页面使用文字热点和常驻详情；通用 HUD 使用固定布局 | 需要新的地图布局，避免连带改变对白和战斗页 |

图标来源及历史预览见 [地点图标样板](地点图标样板.md)。
概念稿中的义体教会暂无游戏地点；“归零运动营地”与当前“革命军营地”
名称也有差异。第一版保留游戏 ID、条件和名称，教会先作为底图地标。

## 地点与任务状态规则

一个地点可以同时具有多种状态。制作时分别判断开放、事件、当前位置、目标
和选中状态，最后组合显示，不能用一个颜色枚举把其他信息覆盖掉。

| 状态 | 显示规则 | 更新依据 |
| --- | --- | --- |
| 当前位置 | 青色头像外环，当前地点名称常驻 | `currentPlaceId` |
| 下一步目标 | 金色图钉或任务外框，目标名称常驻 | 未完成主线、事件条件和地点开放条件 |
| 可用主线／可选 | `!`／`?` 徽章；数量统计真正可开始的事件 | 过滤后的事件列表 |
| 已完成且暂无新事件 | 小勾和低亮度地点图标 | 本地有完成记录，且无可开始事件 |
| 地点暂无事件 | 低亮度功能图标；已有服务仍可用 | 事件列表及 `services` |
| 锁定 | 灰蓝图钉和锁，显示已有 `lockHint` | 地点 `unlockCondition` |
| 悬停／固定选中 | 提亮或浅色外圈，保留任务颜色和头像 | 仅地图视图临时状态 |

建议由 `Game` 提供统一的地图状态／目标查询，详情、徽章和目标文字共用结果。
不解析 `objective()` 的显示字符串来获取 ID，不在视图复制另一套解锁规则。
第一版优先通过现有状态推导，不新增存档中的任务追踪字段。

目标更新需要遵循以下建议规则：

1. 已完成事件不再作为目标；后续目标按实际已满足条件的主线重新计算。
2. 战败或投降回地图但事件未完成时，不因为返回地图就清除任务提示。
3. 没有可开始主线时，不虚构目的地；第一周完成后只保留真实可用支线和地点。
4. 如果多条主线同时可开始，建议把这些地点都标为主线目标，并显示候选列表；
   若产品需要唯一推荐目标，再明确配置优先级，不能依赖 JSON 遍历次序。
5. 条件已满足但地点尚未开放的事件不计入可开始数量，也不标为可前往目标。
6. 第一版不增加支线追踪按钮，也不把重新开始事件描述为“继续上次进度”。

## 地图空间与标记布局

第一版建议完整展示底图，以固定构图验证标记和文字，不加入缩放或拖拽。
底图比例与窗口比例不同产生的留白纳入坐标计算，打开详情时不移动底图。

- 顶部采用地图专用的紧凑 HUD，保留 HP、日期、信用点、阵营、菜单和周次入口。
  共用 HUD 的其他页面布局保持原行为；地图页移除大块调试文字。
- 所有建筑锚点按底图实际显示矩形定位，采用图钉尖端对齐地标。
  图钉位移、头像、文字及短引线使用独立展示偏移，不偷偷改变建筑位置。
- 以默认 `1280×800` 窗口检查约 48 像素标记、36～44 像素头像；
  这些是屏幕尺寸建议，需要换算到逻辑画布并实际渲染检查。
- 点击区域略大于图案，但相邻点击区不得争抢；不能直接沿用旧大矩形热点。
- 当前位置和目标名称常驻；其他名称在悬停或选中时显示。
  长名称换行或调整位置，不截掉必要文字。
- 头像默认位于图钉左侧，边缘不足时翻至右侧；不得遮住邻近目标的点击区。
- 重点检查大楼／商场／医院，后巷／酒馆，城寨／黑市／地下诊所三组密集区域。
  必要时偏移图标并用短引线连接地标，不把几个地点合并为一个新入口。
- 图钉下使用深色衬底与清楚描边抵抗建筑灯光；避免大面积发光和持续闪烁。

16 个地点的校准表在实施时记录 ID、建筑、比例锚点、展示偏移、标签方向、
点击范围及截图证据。没有独立地标的细分地点采用街区内合理锚点，记录原因。

## 信息卡与输入规则

信息卡分为只读悬停预览和可操作固定详情，共用内容来源，避免两套信息不一致。
以下为第一版建议的交互状态机。

| 输入或状态 | 反馈 |
| --- | --- |
| 无固定详情，悬停标记约 0.2 秒 | 显示该地点预览；移开隐藏，切换目标取消旧计时 |
| 悬停普通地点 | 名称、简介、所在地／服务／锁定等真实状态 |
| 悬停任务地点 | 增加主线／可选、标题、任务说明和可用数量 |
| 点击标记、头像或任务徽章 | 固定该地点详情，隐藏悬停预览，不立即进入 |
| 固定 A 后悬停 B | 仅高亮 B，保留 A；不叠加第二张预览 |
| 固定 A 后点击 B | 切换固定详情到 B |
| 点击卡片或滚动内容 | 不穿透点击底图，按钮只执行一次 |
| 点击地图空白或按 Esc | 关闭固定详情；若有周次弹窗，先关闭顶层弹窗 |
| 点击明确的进入／事件按钮 | 通过 `Game` 执行已有流程，重新校验条件及输入锁 |
| 治疗引发地图刷新 | HP 更新，头像保留真实所在地，恢复仍有效的固定地点详情 |

卡片优先摆在标记侧面空处，碰到窗口边缘时翻转并限制在 HUD 之外；
固定卡在鼠标移动时保持稳定位置。不能默认总放右下角而遮住港口。
同一时刻只显示一张预览或固定卡，避免频繁跳动。

详情包括地点名称、简介、可用事件列表和对应操作。多个事件分条列出；
列表可滚动，主要操作仍可达。任务、治疗和普通进入的按钮名称明确区分。
当前没有正式奖励、难度等数据，相关区域暂不出现；`demoNote` 不作为玩家
任务简介。若要显示任务目标，需要明确的文本来源，不从对白猜测。

保留地图直接治疗的现有行为：治疗不自动移动头像、不增加费用、不推进日期。
如果后续改为先进入医院再治疗，需要另行讨论流程变化，不能混入视觉重构。

固定详情的选中 ID 可在地图刷新期间临时保留；不写入冒险存档。
返回地图建议默认显示完整地图和真实当前位置、目标，详情默认关闭。
