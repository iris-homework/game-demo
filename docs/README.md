# 午夜委托文档索引

这里说明各份文档的用途，以及理解游戏、修改功能和制作美术时的查阅顺序。
本轮整理日期为 **2026-10-07（Asia/Shanghai）**，游戏基线为 **0.2.6-r1**。
地图重构已接入；主菜单于 0.2.5-r1 接入 P0，0.2.6-r1 起改用逐帧动画背景。
实际运行结果和证据见对应验收清单与验收记录，历史记录不替代本轮检查。

## 从哪里开始

如果你还不了解游戏，先读玩法，再看流程；准备修改工程时再查技术说明。

1. 阅读[游戏规则](游戏规则.md)，了解当前可玩的内容、临时数值和未实现机制。
2. 阅读[游戏流程与路由](游戏流程与路由.md)，了解页面、事件解锁、选择分支
   和战斗结果返回位置；其中涉及剧情剧透。
3. 根据任务查阅下表，修改前核对[维护文档](维护文档.md)中的相关边界。
4. 查看[修改记录](修改记录.md)中相关的历史变化，按
   [开发工具与工作流](开发工具与工作流.md)选择本次验收方式。

## 资料与实现的区别

原始设计和图片是理解项目的资料来源。它们可能包含待实现方案或旧方向，
不能仅凭文档中出现字段、概念图中出现按钮，就认定游戏已支持该功能。

- 用户已删除工程同级的 `Development-Documentation-and-Art-Assets`。
  地点图标保存在 `assets/icons/map/`，提示词和清单也在该目录；新预览
  输出到 `artifacts/icon-previews/all-locations/`，可按图标说明重新生成。
  运行时内容以工程脚本、场景和 `data` 为依据。
- [参考图](参考/)用于设计对照，不是游戏资源已接入的证明。
- [历史预览](预览/)保留已有截图；查看时结合对应记录的日期、版本和场景。
- 地图底图与 16 个地点符号已接入正式地图页；教会只保留为插画地标。
  地点设计名称与当前地点 ID 的差异见[概念稿边界](城市地图概念稿.md#设计与运行时的边界)。
- 主菜单背景自 0.2.6-r1 起使用用户审核的
  `assets/menu/noren-bar-idle-motion-v2-neon.gif`，逐帧无损解码为
  `assets/menu/noren_idle_frames` 下的 60 张 PNG。0.2.5-r1 的 `asset/source`
  静止立绘副本与 `assets/menu/source-manifest.json` 仅作来源历史，未接入
  新生成图片。
- 整体美术风格与 AI 母提示词仍处于讨论阶段。本轮不将未确认的提案写成
  已批准规范；后续确认后再归档并在此添加入口。

用户最新要求优先。描述当前行为时核对代码、配置与对应验证证据；
发现文档与实现冲突时明确指出差异，不能擅自把旧设计实现成新规则。
历史通过只说明当时的结果。

## 文档如何随开发更新

修改功能时同步维护对应说明，记录日期、适用版本和实际检查范围。

| 发生的变化 | 需要同步的文档 |
| --- | --- |
| 玩法、卡牌效果、数值、治疗或日期规则变化 | 游戏规则；涉及技术边界时更新维护文档与接入说明 |
| 页面入口、事件条件、分支或胜败返回变化 | 游戏流程与路由；涉及数据接口时更新接入说明 |
| 美术方向确认、样板制作或资源接入 | 美术方向或对应样板文档，明确设计与接入状态 |
| 工具、agent 分工或 QA 入口变化 | 开发工具与工作流；涉及协作约定时更新 AGENTS |
| 任意交付变更 | 修改记录；必要时更新本索引和工程 README 的入口 |

规则和流程文档说明当前实现，不替代技术维护约定；修改记录说明历史，
不替代当前规则。阶段验收按本次实际结果记录，未运行的检查明确写未运行。
