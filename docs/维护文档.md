## 出牌流程必须保持的约定

### 战斗临时科技

- 角色可配置 0—6 项，当前上限为 6（`CombatModel.CYBERWARE_LIMIT`），诺伦仍为六张两行三列，HUD 按该战斗实际可用卡计算数量。旧八卡快照保留历史配置供加成校验，但只开放前六张；第七、八张的旧冷却记录不计入可用数量，不可再次激活，已获得的伤害加成保留。

- 六张原型卡的 ID、名称、说明与加成量位于 `data/prototype/cyberware.json`，目录定义未改动。角色的 `cyberwareIds` 决定可用项及顺序；`Game.player_cyberware()` 返回选定定义的深拷贝，`initialize_combat()` 将它们写入新战斗／演练 profile。空列表或缺字段表示无科技，不继承六张。配置校验拒绝重复、未知、超过上限的 ID 和非法效果数值，接入细节见[角色科技配置](开发接入说明.md#角色科技配置)。正式 `data/cyberware/cyberware.json` 和局外 Meta 不受影响。
- `CombatModel.activate_cyberware()` 负责激活校验及状态更新；每张科技冷却 1 回合（含使用当回合）。`used_cyberware` 仅记录当前回合冷却的 ID，在成功进入下一玩家回合时清空，防止当回合重复使用，`next_attack_bonus` 叠加到下一次有效攻击的第一个伤害效果，多段攻击只加一次。无效出牌、空效果或非攻击牌不消耗，结束回合不清除。
- `cyberware_view.gd` 按战斗实际列表、最多两行三列显示卡牌；空列表显示无可激活科技提示。与只读牌堆不同，点击或数字键 1—6 按列表顺序请求激活。场景通过 `commit_combat()` 保存，再刷新标记，不在动画回调中添加属性。
- 科技与牌堆共用 `pile_overlay` 模态占位，阻止底层出牌、结束回合和开发快捷键；开窗时取消瞄准。不得把科技卡加入抽牌、手牌或弃牌堆。
- 快照包含可选字段 `usedCyberware`、`nextAttackBonus`，仍使用冒险 schemaVersion 2。缺字段按空数组与 0 恢复。新 profile 增加 `playerCyberwareIds`，校验它与快照科技定义 ID 及顺序一致；此标记不强制加入旧六／八项快照。`migrate_save()` 仅在旧战斗缺科技配置时按保存的主角补入，不替换已有配置；进行中快照不因角色列表调整而重建。`valid_cyberware_state()` 校验唯一 ID、合法加成及回合累计上限，允许未消耗加成跨回合累积。0.3.1 的已使用 ID 按当前回合冷却恢复，下个玩家回合解除，不需修改原存档。
- 当前只支持包含使用当回合的 1 回合冷却；如扩展多回合冷却或费用，需同步修改模型、存档校验、界面说明和测试。
- 使用 `tests/cyberware_tests.tscn` 检查规则、临时文件存取、旧档和损坏字段；使用 `tests/cyberware_visual.tscn` 检查六卡布局、鼠标／键盘激活、弹层隔离、重复激活及真实攻击结算。图形样本敌人 20 HP 仅在测试内存中设置。角色独立配置用 `tests/character_cyberware_tests.tscn` 和 `tests/character_cyberware_visual.tscn` 检查列表隔离、空列表、顺序、配置错误、新旧存档与演练恢复。

一次出牌的顺序为：**按下选牌 → 目标确认 → 模型校验并结算 → 保存快照 → 播放命中与弃牌效果**。

### 按下与释放

- 手牌的 `card_button.action_mode` 使用 `BUTTON_PRESS`，按下即触发 `begin_card_aim()`；不要改回释放后选中。
- `selected_uid` 表示选中的实例，`held_card_uid` 只表示这一次鼠标按住的实例。卡牌定义 ID 不能代替实例 UID，否则同名卡容易被一起移除或重复使用。
- 左键释放时先清空按住状态，再重新检测目标。不能只使用上一帧的 `hovered_target`，也不能在两个信号回调里各提交一次伤害。
- 首次原地点击松手保留选中；非攻击牌持续跟随鼠标，攻击牌居中置顶。指定敌人的牌在空白处松开保留选择；非攻击牌在整个视图内优先出牌，不触发底层按钮，自身／群体非攻击牌不再因离开旧中部区域而取消。再次点选同一张指定敌人的牌、右键或 Esc 取消；取消后再松开左键不能出牌。
- 目标检测、箭头终点和卡面起点使用同一画布坐标体系。保持 `get_global_mouse_position()` 与卡牌 `get_global_transform()` 的转换，不混入桌面屏幕坐标。

### 回合提示与战斗时间条

- `DemoUI.chrome(section, show_days=true)` 与 `map_chrome(section, weeks_action)` 均调用 `status_bar()` 构建 76px 紧凑顶栏。战斗调用 `chrome("战斗", false)` 隐藏日期及七格进度条，在中央显示回合信息，不修改 `currentDay`；其他冒险页面显示居中日期。旧的 WEEK 标注与带文字日期块已移除。
- `battle.gd.announce_turn()` 持有居中模态提示 `turn_banner`，用 `turn_banner.gd` 的 SubViewport 渲染中文，再由 `turn_banner.gdshader` 对完整字样自下向上扫描显隐；避免逐字 UV 导致每个字符单独擦除。提示含扫描线、轻微错位和闪烁；己方采用亮蓝字芯 `8fcaff`、电光蓝强调色 `3d9eff`、蓝色残影 `597bff`，敌方保留红色。
- 时序为显现 0.34 秒、停留 0.44 秒、消失 0.32 秒。首次 `first_draw` 成立时，等全屏进场结束后先显示“第1回合”再抽牌；已有手牌恢复不重播。0.3.19-rewards 起首次条件同时要求“第 1 回合、手牌为空、弃牌堆为空”，已打完首轮手牌的恢复不会额外补牌。0.4.0 已用 `openingDrawDone` 独立记录发牌，新消耗区不参与“是否首次发牌”的推断；旧快照缺字段时才用历史条件推断。
- 结束回合先锁定输入，将剩余手牌视图移出 `cards`，同时播放弃牌飞行与“敌方回合”提示。等待提示结束且所有卡牌飞抵后，再调用原 `model.end_turn()`、提交一次快照并播放受伤；若未结束战斗，显示“第%d回合”后补牌并解锁。不能在提示动画回调中再次结算或增加回合。常驻回合状态栏位于顶部 (596,14)，尺寸 248×48，中心 x=720，采用亮蓝配色，与左侧信用点区域留出间距。
- 提示期间 `battle_busy` 与全屏模态控件共同拦截出牌、结束回合、牌堆、科技、菜单及键盘操作；提示移出场景后释放。未初始化或已有结局时不能发起结束回合。
- `tests/turn_banner_visual.tscn` 覆盖初始、第2／3回合、重复输入、未提前扣血、已有快照恢复、战败不再提示下一回合、地图日期保留。可加 `--fixed-fps 60` 和 `-- --record` 将实际动画写至系统临时目录用于制作预览；普通测试只保存阶段截图，不写正式存档。

### 模型提交与动画

`CombatModel.play_card()` 先验证目标、牌是否仍在手中及效果，再改 HP、移入弃牌堆并判断结局。视图随后调用 `Game.commit_combat()` 保存快照。重复点击和重复释放不得再次消费同一 UID。

当前等待整次角色攻击收尾与出牌飞抵弃牌堆后恢复操作；入堆光环和飘字可继续播放。飞行卡牌必须立即移出视图的 `cards` 字典，并将本体和按钮的 `mouse_filter` 改为忽略。否则残影会挡住下一次点击，或回合回收时出现重复卡面。

伤害飘字由 `scripts/combat/damage_number_fx.gd` 绘制，以传入字体按实际字符宽度居中，使用多层描边在 Compatibility 下实现霓虹亮边；玩家受伤的 HP 后缀独立小号显示。亮白字芯、青红错位、斜闪和碎片仅在局部出现，短促放大后上浮淡出，总长 0.64 秒。`impact()` 为同一目标的存活飘字分配横向位置，最多五档；节点只绘图，无鼠标控件，不改模型和输入锁，切场景随父节点释放。敌方行动等待 `test_stage.attack()` 的全部命中与收势；飘字尾光不阻塞人物动作。

抽牌视觉由 `scripts/combat/draw_fx.gd` 管理，开场和回合补牌共用 `deal_hand(true)`。卡牌始终属于战斗视图，不交给特效释放；等待发牌时隐藏，依次从抽牌堆中心沿弧线旋转展开。飞行时长为 `max(visuals.drawDuration, 0.38)` 秒，逐张间隔 0.055 秒。`landed` 信号发出前，恢复卡牌 home、home_scale 和 home_rotation，并解除特效对卡牌的引用；最后一张落稳后恢复输入，0.18 秒余光只绘图，不再触碰卡牌。读档恢复已有手牌走 `deal_hand(false)`，直接显示正常卡面。特效仅负责视觉，不抽牌、不存档、不修改输入锁。

弃牌视觉由 `scripts/combat/discard_fx.gd` 独立管理：接管已从 `cards` 移除的卡面节点，以三次贝塞尔路径飞向弃牌堆中心，绘制青红拖尾、卡形残影和入堆光环。特效不结算伤害、不移动模型牌堆、不修改输入锁。卡牌本体和按钮均忽略鼠标，特效节点随战斗场景销毁，尾动画结束释放所拥有的卡面。

单张飞行 0.40 秒，入堆光环 0.24 秒；当前等角色收势与卡牌落堆后解锁；致命攻击还等死亡淡出后转场。回合结束先清空视图 `cards`，每张相隔 0.045 秒、飞行 0.32 秒，以较低亮度播放；飞行与敌方回合提示并行；等待提示和最后一张飞行均结束后继续敌方表现，默认五张牌在提示期间飞抵，不再额外等待弃牌。上述时长由 `animate_discard()` 统一设置，旧 `visuals.discardDuration` 当前不再控制弃牌特效。

`set_busy(true)` 会清理按住状态并禁用手牌。新入口应检查转场锁 `transition_locked`、战斗忙碌 `battle_busy` 和牌堆弹层是否存在。致命命中、回合切换及转场期间继续锁定输入。Tween 随所属场景销毁；尾动画不应再修改战斗模型。

**战斗提交使用 `commit_combat()`，不能用 `checkpoint()` 替代。** 前者更新快照并发送 `status_changed` 更新 HUD；后者发送 `changed`，会触发视图重建。动画中误用后者可能销毁正在使用的卡牌节点。

`revision` 用于对白、选项和战斗退出的过期请求检查；`commit_combat()` 本身没有调用者 revision 校验。新增异步规则或多个提交来源时，需要另行处理过期状态，不能假定已有检查覆盖所有写入。

## 牌堆和按钮维护

牌堆数量的动画显示由 `shown_draw_count` / `shown_discard_count` 管理。`draw_fx.departed` 在卡牌真正离堆时通知视图减一；显示抽牌堆耗尽时，按现有回收配置先将显示弃牌数量转入，再继续减一。`discard_fx.landed` 在卡牌抵达弃牌堆时通知视图加一，普通出牌和回合清手牌共用，允许并行动画。显示计数不写模型或存档；初始化／已有快照恢复及整批补牌落稳后使用 `refresh_counts()` 与模型对齐，单张出牌不能在飞行途中强制刷新以免覆盖其他在途卡的计数。动画中的数字代表已离堆／已入堆数量，牌堆浏览仍读取已结算的模型；飞行结束后两者一致。`tests/pile_count_visual.tscn` 覆盖逐张抽牌、回合清手牌、部分回收、连续出牌、读档、关闭回收及短补牌。


牌堆浏览使用 `contents.duplicate()` 建立展示数组。默认排序键为：定义中的 `sortOrder`，未填写则使用卡目录位置；再按卡牌 ID、实例 UID 排列。`sortOrder` 是直接参与排序的数值，不是“所有设置了此字段的牌都排在前面”。

保留以下表现与输入约定：

- `GridContainer.columns = 5`，水平布局使用 `SIZE_SHRINK_BEGIN`。一张或两张牌也从最左边开始，不居中；重复卡逐张展示。
- 只读卡使用 `setup(..., true)`。它们可以显示卡面和悬停反馈，但不连接战斗出牌、不执行抬升位移，不截断滚轮传递。
- `ScrollContainer` 负责垂直滚动；调整卡面缩放时同步调整格子大小、间距和可视高度，检查最右列及最后一行完整可见。
- 弹层拦截底层按钮和快捷键；Esc、右键或返回按钮关闭弹层，不能直接退出战斗。关闭回调可能立即移除节点，标记输入已处理应发生在移除之前。
- 通用按钮通过 `DemoUI.button()` 创建，保留居中文字与对称内边距。无文字的敌方点击区域单独处理，避免把按钮角标画在立绘上。

## 增加卡牌和敌人的步骤

1. 在正式目录中定义唯一、稳定的 ID，检查 `battles.json`、`characters.json`、`assets.json` 等引用。正式卡与临时卡不要使用相同 ID；当前合并规则会保留正式目录中的同名定义。
2. 卡牌准备名称、说明、资源引用、费用字段和效果。新诺伦执行器支持 damage、block、ammo、draw、stance、weak、bleed、parry、parry_fill、next_damage、next_discount、power、discard_attack；使用明确整数，先验证资源／目标／选择再原子执行。旧执行器保留测试 damage 路径。
3. 新效果须先实现模型的验证、执行和快照语义，再接入卡面说明、目标选择及动画，补充成功、非法目标、重复提交与读档测试。
4. 敌人目前只执行 `attack` 意图，HUD 也固定显示攻击。其他意图只填 JSON 会出现规则不执行或显示不符，需同时实现模型与展示。
5. 创建战斗时先 `CombatModel.new()` 再 `initialize()`。当前 `initialize()` 不清空旧模型，不支持安全地在同一对象上反复初始化。
6. 改卡牌或敌人数值后用新战斗验收。已有战斗快照包含 `profile`、`cardCatalog` 和敌人数据，修改 JSON 不会自动更新进行中的旧战斗；需要保留旧规则或显式迁移。
7. 新增演练入口时检查其事件确有名为 `battle` 的节点，并引用对应战斗。当前 `start_training()` 固定从这个节点进入。

`data/cards/schema.json` 是预留结构说明，当前运行时没有加载它进行验证，其中已列出诺伦必要字段和效果枚举；运行时的模型与存档校验仍需独立维护。JSON 能解析或存档通过基础校验，不代表所有内容引用及效果正确。新增正式内容后，还要同步调整测试中“正式目录为空”等原型专用断言，保留有效的业务检查。

## 存档维护与恢复

默认冒险文件为 `user://checkpoint.json`，备份为 `checkpoint.json.bak`，写入中间文件为 `.tmp`。macOS 当前目录为：

```text
~/Library/Application Support/MidnightCommissionDemo/
```

局外资料使用同目录下的 `meta_profile.json`。冒险 schemaVersion 为 2，Meta 为 1；UI 版本提升不会自动改变这两个格式。

### 必须区分的实际行为

- `checkpoint()` 和 `commit_combat()` 不检查 `save_game()` 的返回值。写盘失败会提示，但内存状态已经提交，不会自动回滚或停止；逻辑结算成功不代表已经可靠落盘。出现保存错误时，先排查权限和磁盘问题并尽量保留当前进程状态，不要假定重启后能恢复刚才进度。
- 冒险保存先写 `.tmp`，再复制旧主文件到 `.bak`，最后替换主文件。**`.bak` 是上一次主文件的副本，不保证一定有效**；当前代码没有校验旧主文件或检查复制结果。
- 加载依次尝试主文件和备份，迁移后再校验。只存在一个文件不代表可以成功继续游戏。
- `migrate_save()` 实现冒险版本 1 到 2，以及 schema 2 内追加科技配置、空 `battleReward` 的兼容迁移；0.3.22-characters 追加 `playerCharacterId`，缺字段的旧档固定补诺伦并转换旧诺伦对白头像引用，已有 HP、奖励牌与战斗快照保持不变。新档的主角必须同时属于可玩目录与人物目录，战斗快照中的主角 ID（若存在）必须一致。新增存档字段或删除既有 ID 时，同步改初始化、迁移、校验及旧档测试，不只修改版本数字。
- `valid_combat()` 检查基础字段、HP 范围、UID 唯一性与三个牌堆的实例守恒，但不完整校验所有效果和意图结构。
- Meta 只有 `.tmp` 替换，没有 `.bak` 恢复；加载失败时保留默认空资料。新游戏不主动清空正常加载的 Meta。
- `save_game()` 和 `save_meta()` 的函数内部没有 `save_enabled` 保护。调用方负责隔离；测试如直接调用保存，必须改为测试专用文件路径。

### 遇到损坏或不兼容存档

1. 退出游戏，先复制整个存档目录到单独的带日期备份。不要先删文件或开始新游戏。
2. 使用备份副本调查，记录游戏版本、Godot 版本、事件节点和错误输出，查看 `load_game()`、迁移及校验失败位置。
3. 程序会尝试 `.bak`。若从备份恢复成功，先保留这份备份的独立副本，再保存新进度；因为下一次保存可能先用损坏的主文件覆盖 `.bak`。
4. 两份文件均无效时，保留它们供修复或迁移。不要用测试存档替代玩家进度。
5. 回退程序前检查旧版本能否读取当前 schema。当前没有版本 2 降回版本 1 的迁移；旧代码与旧存档应配套恢复。

## 剧情跳过（2026-10-15）

验证入口：`tests/dialogue_skip_tests.tscn` 对照所有现存对白起点的普通推进结果，并覆盖付款、过期请求、锁、奖励和循环；`tests/dialogue_skip_visual.tscn` 用隔离保存路径检查右上角按钮、逐字播放中点击、选择停留与战斗转场。后者是实际渲染／合成输入，不等于物理输入验收。

## 常见问题排查

| 现象 | 首先检查 |
| --- | --- |
| 必须松开鼠标才出线 | `card_view.gd` 是否仍为 `BUTTON_PRESS`，`chosen` 是否接到 `begin_card_aim()` |
| 取消后松开仍出牌或扣两次血 | `held_card_uid` 清理、释放回调是否重复、模型 UID 是否已移出手牌 |
| 线跟鼠标有偏移 | 全局画布坐标转换与 `canvas_items`，是否误用桌面坐标 |
| 连续出牌发卡或点击被吞 | 飞行卡是否仍接收鼠标、是否等尾动画才解锁、hover Tween 是否与重新排手牌冲突 |
| 打开牌堆改变了下次抽牌 | 是否直接 `sort()` 了模型牌堆，而非 `duplicate()` 后排序 |
| 少量牌又出现在中间 | `pile_view.gd` 的 `SIZE_SHRINK_BEGIN` 是否被改回居中 |
| 滚轮放在卡牌上不滚动 | 只读按钮的鼠标传递、滚轮透传、外层滚动容器与格子尺寸 |
| 弹层打开时还能结束回合或退出战斗 | 模态层级、鼠标遮挡、键盘事件是否在移除弹层前标记已处理 |
| 改 JSON 后旧战斗没变化 | 快照是否保留旧 `profile` 和 `cardCatalog`；先新开一场战斗验证 |
| 立绘白边或白色细节消失 | 共用 shader、素材是否透明、对白与战斗去白条件差异 |
| 继续游戏失败或重新补牌 | 保存版本与 ID 校验、主档／备份，再检查首回合空手恢复边界 |
| 画面更新时卡牌节点消失 | 是否误用 `checkpoint()` 引发整页重建，或旧异步回调访问已移除视图 |
| 地图标记点击或悬停偏移 | 标记尺寸、图钉尖端换算与 `_input` 坐标体系，是否对 viewport 坐标做了二次逆变换 |
| 地图详情滚动按钮无效 | 只读事件按钮的鼠标穿透属性应为 `mouse_force_pass_scroll_events`；按钮类型需能接收滚轮事件 |
| 地图治疗移动头像或重复治疗 | `heal_at()` 不应改 `currentPlaceId`；重建后 `pending_selection_id` 只恢复所选详情 |
| 地图悬停时长或长列表点击异常 | hover 用单调时钟判定真实间隔，Timer 首帧不计启动前 delta；长列表项与同矩形卡用 `gui_input` 分发并加幂等提交 guard，`Game.revision` 只应加 1，`_on_card_action` 被拒绝时清除 guard 允许重试 |
| 地图普通单任务详情按钮被裁剪 | 详情高度按真实子项 `sumHeight` 与实际 `separation` 计算，不能只估算固定行高；长列表继续走 `Scroll`，不要为单任务关掉滚动 |

报告问题时至少记录：工程版本、Godot 版本、窗口尺寸、从菜单开始的复现步骤、预期与实际行为、出现频率、错误日志，以及是否使用旧存档。只在必要时附相关存档副本，不附整个私人目录。
