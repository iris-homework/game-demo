# 午夜委托项目维护文档

本文面向继续开发本项目的人或 AI 助手，说明改动位置、需要保持的行为、测试方法和故障排查顺序。维护目标是减少功能回退、重复结算、存档丢失和界面误操作；测试覆盖的是当前原型，扩展规则时仍需补充对应检查。

核对日期：**2026-10-07，Asia/Shanghai**。当前基线：**0.3.15-fix**，Godot **4.7.2 standard / Compatibility**，逻辑画布 **1440×900**，默认窗口 **1280×800**，缩放模式为 `canvas_items`。其他 Godot 4.x 版本尚不能视为已验证。

历史变化见 [修改记录](修改记录.md)，功能接入参考 [开发接入说明](开发接入说明.md)，历史原始输出见 [验收记录](验收记录.txt)。本文描述当前代码；文中标明“扩展前需要处理”的内容尚未实现。

## 开始修改前

1. 先确认需求涉及哪一层，并查看下表和相关函数。保持用户最近确认的行为，尤其是按下立即瞄准、牌堆左对齐及默认排序。
2. 留下可恢复的工程副本或版本提交。当前交付包使用固定文件名，反复覆盖它不能替代版本历史；备份时使用版本号和日期区分。
3. 涉及存档、数据 ID 或战斗规则时，先备份用户存档，并阅读本文存档章节。
4. 为改动选定验收场景。逻辑缺陷补有意义的回归测试；小型文案、配色或对齐调整通常做实际画面检查即可。
5. 完成后更新修改记录、必要的维护说明和工程包。未运行的检查明确写“未运行”，不沿用旧通过结果。

原始 Word 文档和 `卡牌游戏美术资源` 目录在工程之外，作为设计与素材来源保留。修改工程内代码或素材副本，不用临时测试数据覆盖原始内容。

## 当前规则与尚未实现的内容

当前临时牌组在 [data/prototype/combat.json](../data/prototype/combat.json)：五张攻击卡、单次伤害 1、敌人默认 3 HP、意图攻击 1。新冒险默认 100 HP、第 1 天；日期不会因出牌或移动自动推进，最多到第 7 天。

正式卡牌、道具和义体目录仍为空，正式奖励池也未填充。能量、格挡、状态、升级、消耗牌、多敌界面完整布局、后续周次和正式城市总览插画没有完成。预留字段或按钮不代表规则已经支持。

当前 `handSize` 是 `draw_cards()` 的补牌目标，不是所有效果通用的手牌硬上限。首次牌组由 `profile.deck` 正序放入抽牌堆，再从末尾 `pop_back()` 抽取，因此首次实际抽取为配置倒序；只有弃牌回收时会洗牌。牌堆浏览界面的排列与这些抽取规则无关。

## 出牌流程必须保持的约定

### 战斗临时义体

- 当前可用数量固定为 6（`CombatModel.CYBERWARE_LIMIT`），卡面两行三列，HUD 按实际可用卡计算数量。旧八卡快照保留历史配置供加成校验，但只开放前六张；第七、八张的旧冷却记录不计入可用数量，不可再次激活，已获得的伤害加成保留。

- 六张原型卡的 ID、名称、说明与加成量位于 `data/prototype/cyberware.json`，由 Game 合并入战斗 profile。正式 `data/cyberware/cyberware.json` 和局外 Meta 不受影响。
- `CombatModel.activate_cyberware()` 负责激活校验及状态更新；每张义体冷却 1 回合（含使用当回合）。`used_cyberware` 仅记录当前回合冷却的 ID，在成功进入下一玩家回合时清空，防止当回合重复使用，`next_attack_bonus` 叠加到下一次有效攻击的第一个伤害效果，多段攻击只加一次。无效出牌、空效果或非攻击牌不消耗，结束回合不清除。
- `cyberware_view.gd` 使用两行三列显示六张卡，与只读牌堆不同，点击或数字键 1—6 请求激活。场景通过 `commit_combat()` 保存，再刷新标记，不在动画回调中添加属性。
- 义体与牌堆共用 `pile_overlay` 模态占位，阻止底层出牌、结束回合、投降和开发快捷键；开窗时取消瞄准。不得把义体卡加入抽牌、手牌或弃牌堆。
- 快照新增可选字段 `usedCyberware`、`nextAttackBonus`，仍使用冒险 schemaVersion 2。缺字段按空数组与 0 恢复；`migrate_save()` 为旧战斗补入临时配置，不替换已有配置。`valid_cyberware_state()` 校验唯一 ID、合法加成及回合累计上限，允许未消耗加成跨回合累积。0.3.1 的已使用 ID 按当前回合冷却恢复，下个玩家回合解除，不需修改原存档。
- 当前只支持包含使用当回合的 1 回合冷却；如扩展多回合冷却或费用，需同步修改模型、存档校验、界面说明和测试。
- 使用 `tests/cyberware_tests.tscn` 检查规则、临时文件存取、旧档和损坏字段；使用 `tests/cyberware_visual.tscn` 检查六卡布局、鼠标／键盘激活、弹层隔离、重复激活及真实攻击结算。图形样本敌人 20 HP 仅在测试内存中设置。

一次出牌的顺序为：**按下选牌 → 目标确认 → 模型校验并结算 → 保存快照 → 播放命中与弃牌效果**。

### 按下与释放

- 手牌的 `card_button.action_mode` 使用 `BUTTON_PRESS`，按下即触发 `begin_card_aim()`；不要改回释放后选中。
- `selected_uid` 表示选中的实例，`held_card_uid` 只表示这一次鼠标按住的实例。卡牌定义 ID 不能代替实例 UID，否则同名卡容易被一起移除或重复使用。
- 左键释放时先清空按住状态，再重新检测目标。不能只使用上一帧的 `hovered_target`，也不能在两个信号回调里各提交一次伤害。
- 空白处松开保留点选模式；再次点选同一张牌、右键或 Esc 取消。取消后再松开左键不能出牌。
- 目标检测、箭头终点和卡面起点使用同一画布坐标体系。保持 `get_global_mouse_position()` 与卡牌 `get_global_transform()` 的转换，不混入桌面屏幕坐标。

### 回合提示与战斗时间条

- `DemoUI.chrome(section, show_days=true)` 保留默认日期显示；战斗调用 `chrome("战斗", false)`，同时隐藏七格日期与 WEEK 标注，不修改 `currentDay`，其他页面保持原样。
- `battle.gd.announce_turn()` 持有居中模态提示 `turn_banner`，用 `turn_banner.gd` 的 SubViewport 渲染中文，再由 `turn_banner.gdshader` 对完整字样自下向上扫描显隐；避免逐字 UV 导致每个字符单独擦除。提示含扫描线、轻微错位和闪烁；己方采用亮蓝字芯 `8fcaff`、电光蓝强调色 `3d9eff`、蓝色残影 `597bff`，敌方保留红色。
- 时序为显现 0.34 秒、停留 0.44 秒、消失 0.32 秒。首次 `first_draw` 成立时，等全屏进场结束后先显示“第1回合”再抽牌；已有手牌恢复不重播。原有首回合空手恢复边界仍存在，不能据此认为新增了独立首次发牌标记。
- 结束回合先锁定输入，将剩余手牌视图移出 `cards`，同时播放弃牌飞行与“敌方回合”提示。等待提示结束且所有卡牌飞抵后，再调用原 `model.end_turn()`、提交一次快照并播放受伤；若未结束战斗，显示“第%d回合”后补牌并解锁。不能在提示动画回调中再次结算或增加回合。常驻回合状态栏位于顶部 (550,24)，尺寸 340×48，采用亮蓝配色。
- 提示期间 `battle_busy` 与全屏模态控件共同拦截出牌、结束回合、牌堆、义体、菜单及键盘操作；提示移出场景后释放。未初始化或已有结局时不能发起结束回合。
- `tests/turn_banner_visual.tscn` 覆盖初始、第2／3回合、重复输入、未提前扣血、已有快照恢复、战败不再提示下一回合、地图日期保留。可加 `--fixed-fps 60` 和 `-- --record` 将实际动画写至系统临时目录用于制作预览；普通测试只保存阶段截图，不写正式存档。

### 模型提交与动画

`CombatModel.play_card()` 先验证目标、牌是否仍在手中及效果，再改 HP、移入弃牌堆并判断结局。视图随后调用 `Game.commit_combat()` 保存快照。重复点击和重复释放不得再次消费同一 UID。

当前非致命起手约 0.16 秒，命中后恢复操作；弃牌尾动画和飘字可继续播放。飞行卡牌必须立即移出视图的 `cards` 字典，并将本体和按钮的 `mouse_filter` 改为忽略。否则残影会挡住下一次点击，或回合回收时出现重复卡面。

伤害飘字由 `scripts/combat/damage_number_fx.gd` 绘制，以传入字体按实际字符宽度居中，使用多层描边在 Compatibility 下实现霓虹亮边；玩家受伤的 HP 后缀独立小号显示。亮白字芯、青红错位、斜闪和碎片仅在局部出现，短促放大后上浮淡出，总长 0.64 秒。`impact()` 为同一目标的存活飘字分配横向位置，最多五档；节点只绘图，无鼠标控件，不改模型和输入锁，切场景随父节点释放。敌方行动等待仍为 `visuals.impactDuration + 0.1`，不等待完整尾光；非致命攻击保持 0.16 秒命中后解锁。

抽牌视觉由 `scripts/combat/draw_fx.gd` 管理，开场和回合补牌共用 `deal_hand(true)`。卡牌始终属于战斗视图，不交给特效释放；等待发牌时隐藏，依次从抽牌堆中心沿弧线旋转展开。飞行时长为 `max(visuals.drawDuration, 0.38)` 秒，逐张间隔 0.055 秒。`landed` 信号发出前，恢复卡牌 home、home_scale 和 home_rotation，并解除特效对卡牌的引用；最后一张落稳后恢复输入，0.18 秒余光只绘图，不再触碰卡牌。读档恢复已有手牌走 `deal_hand(false)`，直接显示正常卡面。特效仅负责视觉，不抽牌、不存档、不修改输入锁。

弃牌视觉由 `scripts/combat/discard_fx.gd` 独立管理：接管已从 `cards` 移除的卡面节点，以三次贝塞尔路径飞向弃牌堆中心，绘制青红拖尾、卡形残影和入堆光环。特效不结算伤害、不移动模型牌堆、不修改输入锁。卡牌本体和按钮均忽略鼠标，特效节点随战斗场景销毁，尾动画结束释放所拥有的卡面。

单张飞行 0.40 秒，入堆光环 0.24 秒；非致命攻击在原 0.16 秒命中后解锁，致命命中等待 0.52 秒再转场。回合结束先清空视图 `cards`，每张相隔 0.045 秒、飞行 0.32 秒，以较低亮度播放；飞行与敌方回合提示并行；等待提示和最后一张飞行均结束后继续敌方表现，默认五张牌在提示期间飞抵，不再额外等待弃牌。上述时长由 `animate_discard()` 统一设置，旧 `visuals.discardDuration` 当前不再控制弃牌特效。

`set_busy(true)` 会清理按住状态并禁用手牌。新入口应检查转场锁 `transition_locked`、战斗忙碌 `battle_busy` 和牌堆弹层是否存在。致命命中、回合切换及转场期间继续锁定输入。Tween 随所属场景销毁；尾动画不应再修改战斗模型。

**战斗提交使用 `commit_combat()`，不能用 `checkpoint()` 替代。** 前者更新快照并发送 `status_changed` 更新 HUD；后者发送 `changed`，会触发视图重建。动画中误用后者可能销毁正在使用的卡牌节点。

`revision` 用于对白、选项和战斗退出的过期请求检查；`commit_combat()` 本身没有调用者 revision 校验。新增异步规则或多个提交来源时，需要另行处理过期状态，不能假定已有检查覆盖所有写入。

## 牌堆和按钮维护

牌堆数量的动画显示由 `shown_draw_count` / `shown_discard_count` 管理。`draw_fx.departed` 在卡牌真正离堆时通知视图减一；显示抽牌堆耗尽时，按现有回收配置先将显示弃牌数量转入，再继续减一。`discard_fx.landed` 在卡牌抵达弃牌堆时通知视图加一，普通出牌和回合清手牌共用，允许并行动画。显示计数不写模型或存档；初始化／已有快照恢复及整批补牌落稳后使用 `refresh_counts()` 与模型对齐，单张出牌不能在飞行途中强制刷新以免覆盖其他在途卡的计数。动画中的数字代表已离堆／已入堆数量，牌堆浏览仍读取已结算的模型；飞行结束后两者一致。`tests/pile_count_visual.tscn` 覆盖逐张抽牌、回合清手牌、部分回收、连续出牌、读档、关闭回收及短补牌。


牌堆浏览使用 `contents.duplicate()` 建立展示数组。默认排序键为：定义中的 `sortOrder`，未填写则使用卡目录位置；再按卡牌 ID、实例 UID 排列。`sortOrder` 是直接参与排序的数值，不是“所有设置了此字段的牌都排在前面”。

保留以下表现与输入约定：

- `GridContainer.columns = 5`，水平布局使用 `SIZE_SHRINK_BEGIN`。一张或两张牌也从最左边开始，不居中；重复卡逐张展示。
- 只读卡使用 `setup(..., true)`。它们可以显示卡面和悬停反馈，但不连接战斗出牌、不执行抬升位移，不截断滚轮传递。
- `ScrollContainer` 负责垂直滚动；调整卡面缩放时同步调整格子大小、间距和可视高度，检查最右列及最后一行完整可见。
- 弹层拦截底层按钮和快捷键；Esc、右键或返回按钮关闭弹层，不能直接退出战斗。关闭回调可能立即移除节点，标记输入已处理应发生在移除之前。
- 通用按钮通过 `DemoUI.button()` 创建，保留居中文字与对称内边距。无文字的敌方点击区域单独处理，避免把按钮角标画在立绘上。

## 增加卡牌和敌人的步骤

1. 在正式目录中定义唯一、稳定的 ID，检查 `battles.json`、`characters.json`、`assets.json` 等引用。正式卡与临时卡不要使用相同 ID；当前合并规则会保留正式目录中的同名定义。
2. 卡牌准备名称、说明、资源引用、费用字段和效果。当前执行器仅支持非负 `damage`，数值转成整数；维护时使用明确整数。空效果数组目前可以被打出并弃置，但不会造成伤害，不是完整的合法性校验。
3. 新效果须先实现模型的验证、执行和快照语义，再接入卡面说明、目标选择及动画，补充成功、非法目标、重复提交与读档测试。
4. 敌人目前只执行 `attack` 意图，HUD 也固定显示攻击。其他意图只填 JSON 会出现规则不执行或显示不符，需同时实现模型与展示。
5. 创建战斗时先 `CombatModel.new()` 再 `initialize()`。当前 `initialize()` 不清空旧模型，不支持安全地在同一对象上反复初始化。
6. 改卡牌或敌人数值后用新战斗验收。已有战斗快照包含 `profile`、`cardCatalog` 和敌人数据，修改 JSON 不会自动更新进行中的旧战斗；需要保留旧规则或显式迁移。
7. 新增演练入口时检查其事件确有名为 `battle` 的节点，并引用对应战斗。当前 `start_training()` 固定从这个节点进入。

`data/cards/schema.json` 是预留结构说明，当前运行时没有加载它进行验证，而且它只要求 ID，弱于代码实际需要的字段。JSON 能解析或存档通过基础校验，不代表所有内容引用及效果正确。新增正式内容后，还要同步调整测试中“正式目录为空”等原型专用断言，保留有效的业务检查。

## 立绘与界面资源

### 当前 UI 约定

- 后巷战斗背景由 `assets.alley.battleAssetId = alley_battle` 指向 `assets/backgrounds/alley_battle.png`。`battle.gd.battle_background()` 优先读取地点原资源上的该可选字段；未配置或目标纹理不可用时调用原 `background()`。有专用背景时关闭 `arena.paint_ground`，直接使用插画路面，并将底部硬色块／红色分隔线替换为 y=650 起的柔和渐暗，不影响点击。对白继续读取原 `alley.png`。此轮仅完成后巷专用美术，其他地点没有新增背景。
- 未使用专用背景时，`scripts/combat/arena_fx.gd` 绘制 y=448—704 的渐变地面、透视铺装接缝和柔和接触阴影，替代悬浮光圈。地面位于下方手牌遮罩之前；`battle.gd` 只为实际存在的敌方立绘注册 `contact_points`，缺图敌人不显示空阴影。诺伦不绘制程序阴影；敌人落脚点为其立绘左上角加 `(230,307)`，新立绘需重新校准。诺伦原图保持不变，`white_key.gdshader` 的可选 `ground_mask` 仅在 `noren_battle` 启用，使用 `noren_shadow_mask.png` 的 alpha 清除 UV.y >= 0.90 的原图投影，其他立绘默认关闭。角色立绘、姓名、敌方HUD与点击区域、双方命中坐标通过 `ACTOR_OFFSET = (0,24)` 同步下移；敌方阴影与瞄准终点随 `enemy_position()` 移动。

- 战斗页面已移除“道具栏”、三个空槽及“暂无道具”提示；道具数据与预留接口仍保留。

- 共用色板：底色 `090b12`、面板 `121722`、主操作红 `ff3158`、状态青 `64ffe1`、正文白 `f5f3eb`、次级文字 `a7b0be`。主操作红底深字，悬停白底；键盘焦点保留青色边框。

- 战斗手牌由 `hand_position()` 和 `hand_rotation()` 按数量排成扇形，基础缩放 `HAND_SCALE = 0.75`，中心间距上限 92（约为卡宽的69%，相邻卡约三成重叠）、总跨度上限 820，边缘旋转最多 ±14°、下沉最多 24。静止中心基线 y=875（home.y=760），卡牌下半部在视口外自然裁切，外侧随弧度额外下沉。悬停放大到 1.12、上抬 140、转正；选中上抬 150，整张卡均在视口内。移开后恢复下沉姿态。抽牌落稳与出牌后重排使用同一 home 参数，不能硬编码恢复缩放 1／旋转 0。只读牌堆预览不使用扇形或放大位移。
- 战斗手牌启用 `managed_input`：关闭卡面原生鼠标拦截，由 `battle.gd` 根据静止扇形的逆变换区域选牌；重叠区按绘制顺序优先后方序号较大的卡，悬停放大不会改变静止区域，避免卡牌反复抢焦点。离开静止区域后仍可点击抬起的卡面。`_input` 在按下时直接选牌并标记已处理，松开有效敌方目标出牌；模态弹层、忙碌、转场时均禁止。

- 战斗牌堆统一通过 `PILE_SIZE = (58,72)` 定义尺寸，左上角分别为 `(30,800)` 和 `(1352,800)`；抽牌起点与弃牌终点均取位置加半尺寸，调整布局时不能保留旧中心偏移。义体与结束回合按钮在 y=719 同高，均为 170×40，调试与投降在右上方纵向排列。

- 28 号及以上标题采用共用加粗字体。对白正文水平排版，仅边框错位；卡牌图形是临时 UI 模板，正式卡图仍通过 `artAssetId` 接入。
- 地图选中地区为白底深字，锁定地区仍可点击查看说明；正式总览图继续使用独立资源引用。

### 美术接入

- 对白读取 `portraitAssetId`，战斗读取 `battlePortraitAssetId`；缺失战斗图保持空位，不自动换成对白图。敌方 HP、意图及目标区域仍要存在。
- 背景取当前战斗地点的背景资源；城市总览使用独立 `cityMapAssetId`。港口背景不替代城市地图。
- 白底图在运行时通过 `white_key.gdshader` 去白。战斗图受 `assets.json` 的 `whiteKey` 控制，透明战斗 PNG 应关闭它。
- **对白立绘当前无条件挂去白材质。** 更换为透明对白 PNG 时，仅设置 `whiteKey=false` 不生效；需要同时调整 `DemoUI.portrait()` 的材质应用条件，并确认白色衣料与高光未被抠除。这是现有差异，尚未统一开关。
- 检查深色背景下的发丝、披风、机械轮廓及面部高光，并在实际窗口尺寸下查看。不要为去白直接覆盖原始美术。
- 中文字体位于 `assets/fonts`，按钮使用其 FontVariation。更换字体时检查中文缺字、按钮居中、小字号和随附字体许可。

## 存档维护与恢复

默认冒险文件为 `user://checkpoint.json`，备份为 `checkpoint.json.bak`，写入中间文件为 `.tmp`。macOS 当前目录为：

```text
~/Library/Application Support/MidnightCommissionDemo/
```

局外资料使用同目录下的 `meta_profile.json`。冒险 schemaVersion 为 2，Meta 为 1；UI 版本提升不会自动改变这两个格式。

### 必须区分的实际行为

- `checkpoint()` 和 `commit_combat()` 不检查 `save_game()` 的返回值。写盘失败会提示，但内存状态已经提交，不会自动回滚或停止；逻辑结算成功不代表已经可靠落盘。出现保存错误时，先排查权限和磁盘问题并尽量保留当前进程状态，不要假定重启后能恢复刚才进度。
- 冒险保存先写 `.tmp`，再复制旧主文件到 `.bak`，最后替换主文件。**`.bak` 是上一次主文件的副本，不保证一定有效**；当前代码没有校验旧主文件或检查复制结果。
- 加载依次尝试主文件和备份，迁移后再校验。只存在一个文件不代表可以成功继续游戏。
- `migrate_save()` 仅实现冒险版本 1 到 2。新增存档字段或删除既有 ID 时，同步改初始化、迁移、校验及旧档测试，不只修改版本数字。
- `valid_combat()` 检查基础字段、HP 范围、UID 唯一性与三个牌堆的实例守恒，但不完整校验所有效果和意图结构。
- Meta 只有 `.tmp` 替换，没有 `.bak` 恢复；加载失败时保留默认空资料。新游戏不主动清空正常加载的 Meta。
- `save_game()` 和 `save_meta()` 的函数内部没有 `save_enabled` 保护。调用方负责隔离；测试如直接调用保存，必须改为测试专用文件路径。

### 遇到损坏或不兼容存档

1. 退出游戏，先复制整个存档目录到单独的带日期备份。不要先删文件或开始新游戏。
2. 使用备份副本调查，记录游戏版本、Godot 版本、事件节点和错误输出，查看 `load_game()`、迁移及校验失败位置。
3. 程序会尝试 `.bak`。若从备份恢复成功，先保留这份备份的独立副本，再保存新进度；因为下一次保存可能先用损坏的主文件覆盖 `.bak`。
4. 两份文件均无效时，保留它们供修复或迁移。不要用测试存档替代玩家进度。
5. 回退程序前检查旧版本能否读取当前 schema。当前没有版本 2 降回版本 1 的迁移；旧代码与旧存档应配套恢复。

## 已知边界与扩展前检查

| 边界 | 当前证据 | 需要处理的情形 |
| --- | --- | --- |

### 可执行命令

以下命令在 `MidnightDemo` 目录执行。macOS 使用现有安装路径；其他安装位置替换 `GODOT_BIN`。也可在 Godot 中打开指定测试场景后按 F6，图形测试需要真实窗口。

```sh
GODOT_BIN="/Applications/Godot.app/Contents/MacOS/Godot"
```

```sh
"$GODOT_BIN" --path . res://tests/r1_visual.tscn
```

## 常见问题排查

| 现象 | 首先检查 |
| --- | --- |
| 必须松开鼠标才出线 | `card_view.gd` 是否仍为 `BUTTON_PRESS`，`chosen` 是否接到 `begin_card_aim()` |
| 取消后松开仍出牌或扣两次血 | `held_card_uid` 清理、释放回调是否重复、模型 UID 是否已移出手牌 |
| 线跟鼠标有偏移 | 全局画布坐标转换与 `canvas_items`，是否误用桌面坐标 |
| 连续出牌发卡或点击被吞 | 飞行卡是否仍接收鼠标、是否等尾动画才解锁、hover Tween 是否与重新排手牌冲突 |
| 打开牌堆改变了下次抽牌 | 是否直接 `sort()` 了模型牌堆，而非 `duplicate()` 后排序 |
| 少量牌又出现在中间 | `pile_view.gd` 的 `SIZE_SHRINK_BEGIN` 是否被改回居中 |
| 滚轮放在卡牌上不滚动 | 只读按钮的鼠标传递、滚轮透传、外层滚动容器与格子尺寸 |
| 弹层打开时还能结束回合或退出战斗 | 模态层级、鼠标遮挡、键盘事件是否在移除弹层前标记已处理 |
| 改 JSON 后旧战斗没变化 | 快照是否保留旧 `profile` 和 `cardCatalog`；先新开一场战斗验证 |
| 立绘白边或白色细节消失 | 共用 shader、素材是否透明、对白与战斗去白条件差异 |
| 继续游戏失败或重新补牌 | 保存版本与 ID 校验、主档／备份，再检查首回合空手恢复边界 |
| 画面更新时卡牌节点消失 | 是否误用 `checkpoint()` 引发整页重建，或旧异步回调访问已移除视图 |

报告问题时至少记录：工程版本、Godot 版本、窗口尺寸、从菜单开始的复现步骤、预期与实际行为、出现频率、错误日志，以及是否使用旧存档。只在必要时附相关存档副本，不附整个私人目录。
