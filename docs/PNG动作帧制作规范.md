# PNG动作帧制作规范

本规范面向制作、整理和交接角色动作图片的队友，说明文件夹创建、PNG命名与
工作台导入方式。按本文交付后，还需要在工作台校准大小、脚底和攻击演出。
适用于《午夜委托》当前敌人制作台，更新日期：2026-10-22。

## 先记住这四条

新建敌人素材时，统一按以下约定整理。

1. 一个角色一个文件夹，放在工程的`assets/combat_test/`下。
2. 文件夹使用`编号_角色ID`，图片使用`角色ID_动作标签.png`，图片名不带地点编号。
3. 每个角色先准备`idle`待机图，再按攻击类型准备其他图片。
4. 新素材统一使用小写英文、数字和下划线；中文名称写在交接说明中。

正确示例：

```text
文件夹：06b_luggage_lurker
图片：  luggage_lurker_idle.png
图片：  luggage_lurker_attack_bite.png
图片：  luggage_lurker_attack_bite_close.png
```

## 创建角色文件夹

素材根目录为`D:\Major Project\game-demo\assets\combat_test\`。
如果队友的工程放在其他位置，使用自己工程中的同一相对目录即可。

1. 先确认该角色是否已有文件夹。已有角色直接使用原目录，保留角色ID。
2. 新角色沿用项目已有的“两位数字＋一位字母”编号，例如`01a`、`06b`。
   编号由团队确认，不自行占用其他角色编号。
3. 在根目录直接创建`编号_角色ID`文件夹，把可导入PNG直接放在里面。
   不要再套`idle/`、`attack/`等动作子文件夹；扫描器不会递归扫描这些子目录。

| 项目 | 规则 | 示例 |
| --- | --- | --- |
| 文件夹 | 两位数字＋一位字母＋下划线＋角色ID | `01a_warden_shield` |
| 角色ID | 小写英文字母开头，其后使用英文、数字或下划线，最多64个字符 | `warden_shield` |
| 图片前缀 | 与去掉编号后的角色ID完全对应 | `warden_shield_` |
| 扩展名 | 真正的PNG文件，建议统一小写`.png` | `warden_shield_idle.png` |

已有主角目录`noren/`和占位角色目录`Finn/`保持原名；文件前缀分别为
`noren_`、`finn_`。新建普通敌人时使用带编号的目录，不创建多个目录共用同一角色ID。

## 基础动作命名

一个文件对应一个动作的关键姿势。当前流程支持单张姿势图，不要求每个动作
都制作连续动画。下表中的`角色ID`需要替换成实际英文ID。

| 文件名格式 | 用途 | 制作要求 |
| --- | --- | --- |
| `角色ID_idle.png` | 待机 | 必备；缺少时可整理草稿，但不能预览或发布角色 |
| `角色ID_move.png` | 移动 | 需要接近目标的打击、咬击角色建议提供 |
| `角色ID_damaged.png` | 受伤 | 建议提供，表现受到攻击后的反应 |
| `角色ID_block.png` | 格挡 | 按角色是否需要格挡姿势提供 |
| `角色ID_retreat.png` | 后撤 | 使用后撤演出时按需提供 |
| `角色ID_evade.png` | 闪避 | 按需提供；识别素材不等于自动新增闪避玩法 |

`damaged`表示被打，`attack_hit`表示主动打击，不要混用。
也不要把攻击图复制后命名为`idle`来绕过缺待机检查。

## 攻击动作命名

战斗演出分为打击、咬击和远程三大类。远程再区分飞行射击与射线，
新素材按下表命名。

| 文件名格式 | 图片内容 | 工作台识别 |
| --- | --- | --- |
| `角色ID_attack_hit.png` | 挥击、盾击、拳踢等出手姿势 | 打击动作`hit` |
| `角色ID_attack_bite.png` | 张嘴准备咬击的姿势 | 张嘴动作`bite` |
| `角色ID_attack_bite_close.png` | 嘴、箱盖或上下颚闭合咬住的姿势 | 咬合动作`bite_close` |
| `角色ID_attack_shoot.png` | 发射弹丸、能量弹等姿势 | 射击动作`shoot` |
| `角色ID_attack_laser.png` | 发射光束、射线的姿势 | 射线动作`laser` |

咬击制作两张关键图：**张嘴预备 → 闭合命中**。只画张嘴图不足以表达咬合。
兼容名称`角色ID_bite_close.png`与`角色ID_attack_bite_close.png`作用相同，
每个角色只选其中一种，推荐新素材使用带`attack_`的名称。

如果确实要用待机图承担闭合，必须在工作台明确选择`idle`作为出手／闭合姿势；
扫描器不会自动替你选择。缺闭合姿势时可以保存草稿，预览和发布会提示补齐。

同一个角色可以同时有多种攻击，例如同时有`attack_hit`和`attack_shoot`。
扫描后分别校准，并在工作台确认默认攻击及各动作的姿势绑定。
标签提供演出模板，不会自动改变敌人的伤害、意图或附加状态。

## 特效图片命名

特效单独导出为透明PNG，放在同一角色目录下。按用途提供即可，不需要凑齐所有类型。

| 文件名格式 | 图片内容 | 用途 |
| --- | --- | --- |
| `角色ID_vfx_muzzle.png` | 枪口闪光、发射端光团 | 显示在发射位置 |
| `角色ID_vfx_projectile.png` | 子弹、能量弹等独立弹体 | 从发射点移动到目标 |
| `角色ID_vfx_impact.png` | 火花、齿痕、命中爆点 | 显示在目标命中位置 |
| `角色ID_VFX.png` | 尚未细分用途的通用特效 | 待校准素材，需要人工确认用途与绑定 |

分类特效在只有一个攻击模板、对应槽位为空时可以自动关联；多个攻击模板需要
人工指定。多部件特效合图不会自动拆分，不要把多种效果拼在一张图里期待直接播放。
新模板可以使用程序特效，所以没有自制特效PNG也能先测试动作。

## 可以照着创建的完整示例

以下目录树分别展示打击、咬击和射击角色的交付结构。其中远程角色包含可选特效。

```text

│   ├── warden_shield_idle.png
│   ├── warden_shield_move.png
│   ├── warden_shield_attack_hit.png
│   ├── warden_shield_damaged.png
│   └── warden_shield_vfx_impact.png
├── 06b_luggage_lurker/
│   ├── luggage_lurker_idle.png
│   ├── luggage_lurker_move.png
│   ├── luggage_lurker_attack_bite.png
│   ├── luggage_lurker_attack_bite_close.png
```

这是命名示例，不表示现有目录已经全部改成这些名称。已有素材和发布引用

## PNG画面制作与导出

为减少动作跳动和校准工作量，制作同一角色时遵循以下建议。

- 使用真正的透明背景，角色和特效分别导出；不要把白色或棋盘格画成图片背景。
- 保持角色身份、朝向和身体比例一致，四肢、武器、箱盖等完整留在画布内。
- 尽量保持同一角色各动作的画布尺寸、主体尺度及脚底位置接近。
  大幅动作可以扩展画布；不要为了塞进画布单独缩小身体。
- 保留清晰的嘴部、武器接触处或发射口，便于在工作台标记攻击点。
- 地面阴影优先在工作台单独调整，避免烘焙的大阴影与角色分离。
- 当前没有所有角色统一的强制像素尺寸。保留清晰原图，最终相对noren的大小
  在工作台校准；不要凭PNG画布尺寸直接判断游戏中的体型。

这些是制作建议，扫描器不会自动修补肢体、改变画法或保证各姿势身体大小一致。
角色外形和动作设计依据[城市地点敌人设计](城市地点敌人设计.md)及已确认参考；
统一美术方向见[美术方向](美术方向.md)。

## 旧命名、重复文件与多帧图片

旧素材继续兼容。以下边界决定自动扫描能否正确识别，不要通过猜测后缀扩展命名。

| 情况 | 当前行为与处理方式 |
| --- | --- |
| `角色ID_attack.png` | 兼容导入`pierce`突刺槽，提示人工确认类型；新增素材使用明确攻击标签 |
| `hit`、`slash`、`pierce`、`bite`、`shoot`、`laser`、`blunt`后缀 | 支持已有动作名；新素材优先使用本文攻击命名表 |
| `gun_idle`、`gun_block`、`gun_damaged`后缀 | 兼容已有持枪动作，供noren等既有配置使用 |
| `角色ID_attack_bite_close.png`与`角色ID_bite_close.png`同时存在 | 同一槽冲突，扫描不会任意选一张 |
| `角色ID_attack_hit.png`与`角色ID_hit.png`同时存在 | 同一槽冲突，保留一个正式来源；已有手工动作不会被扫描覆盖 |
| `角色ID_attack_shoot_01.png`、`角色ID_attack_shoot_02.png` | 当前不支持按数字后缀自动组帧，在工作台手工导入并设置顺序 |
| `角色ID_attack_shoot_v2.png`、中文后缀、空格后缀 | 不作为上述标准动作识别，版本备份放到制作素材目录之外 |
| `reference`或`reference_`开头的目录 | 作为参考目录跳过，不用于正式角色导入 |
| 已有动作需要换图 | 使用工作台的手工替换流程；重新扫描不会覆盖既有动作与调参 |

扫描时标签大小写不敏感，但团队新素材仍统一小写英文，现有`Finn/`目录例外。
已有动作改名可能使草稿或其他引用失效。工具只对唯一可判断的旧攻击改名修复
缺失引用，不能代替团队确认所有改名；换图或改名后都要重新预览。

## 从交付到游戏验收

图片制作完成后，按以下步骤确认素材已进入正确环境。

1. 把PNG放入正确的角色文件夹，核对文件前缀和动作后缀。
2. 在Godot打开[测试制作台](../enemy_asset_pipeline/test/test_workbench.tscn)，按F6，
   点击**打开PNG制作工具**。工具已运行时，新增文件后点击**扫描新增PNG**。
   工具源码更新后需要重启原服务，浏览器刷新不会让旧服务加载新代码。
3. 选择角色，确认新增动作、闭合姿势与分类特效，处理缺待机、缺闭合或同槽冲突。
4. 对照noren调整角色大小，校准各姿势脚底、阴影、攻击接触点和播放节奏；
   保存右侧帧调参与左侧演出草稿。
5. 点击**送入战斗预览**，回Godot点击**刷新草稿**，查看完整攻击。
   用慢放检查打击接触、咬击闭合和远程弹体命中，再用真实战斗检查受击与格挡。
6. 正式制作在[正式制作台](../enemy_asset_pipeline/workbench.tscn)进行。
   验收后明确点击**应用当前角色到游戏**，新建战斗读取发布配置。

测试版与正式版草稿、发布目录彼此隔离。测试版点击应用不会更新正式游戏；
扫描到文件也不等于角色已经发布。完整操作见[敌人制作台说明](../enemy_asset_pipeline/README.md)。

## 交接前检查清单

队友交接时逐项确认，并附上角色ID、攻击类型和还未完成的素材说明。

- [ ] 文件夹位于`assets/combat_test/`下，编号与角色ID已经确认。
- [ ] PNG直接放在角色文件夹内，文件前缀不带地点编号且与角色ID一致。
- [ ] 已有清晰透明的`idle`，其他动作按实际需求提供。
- [ ] 攻击标签准确，咬击同时提供张嘴与闭合图，或注明需要人工选择闭合姿势。
- [ ] 同一动作槽没有两套别名；没有期待自动识别的数字帧后缀或版本后缀。
- [ ] 身体、武器和嘴部完整，主体尺度与脚底位置已对照检查。
- [ ] 特效与角色分开导出，特效用途清楚。
- [ ] 已扫描并查看提示，已在Godot验证动作，记录未完成项。
- [ ] 已说明交付的是原PNG、测试草稿，还是已经应用的正式版本。
