## 2026-10-20 故障机器人

垃圾场 B02 的故障机器人使用独立的站姿、掌心射线和受击图，每回合循环执行一次基础10伤害攻击，继续受力量、虚弱、易伤和格挡规则影响。掌心射线从细线逐渐扩张为粗光束，最粗不超过机器人手掌宽度，穿过目标后延伸出屏幕，再收细消失；贯穿是视觉效果，本次攻击仍仅结算一个目标、一次伤害。

## 玩法循环

2026-10-10 补充：当前可玩主角仍只有诺伦，初始 70 HP（2026-10-24调整）、十张基础牌（直击×4、护身×4、贴近×1、拉开距离×1）。角色专属技能尚未启用；本轮增加角色配置入口，没有增加选角界面。2026-10-11 战斗科技也接入角色独立配置，诺伦当前配置异次元口袋、加速时钟与后备能源（2026-10-23更新，最多四槽），见下文。

当前是第一周的原型流程：单主角诺伦在城市里接下委托，通过城市总览地图选择地点和事件，用对白与选择推进剧情，在部分事件中进行临时卡牌战斗，最后走到事件结算。【已实现】

一次完整的循环如下：

1. 从主菜单选择"开始新的委托"或"继续旅程"。
2. 新游戏直接进入 **E01"午夜酒馆"** 的对白，在酒馆里从金钱／治疗／迅捷芯片中免费选一枚支援，有空槽时自动携带，并约定完成三个委托后回酒馆领奖。已有进度时，菜单会先要求确认覆盖；新冒险不清空局外科技档案。
3. 进入**城市地图**。地图上可以查看地区详情，也可以直接开始当地事件，或先“进入地点”。
4. 事件由对白节点与选择推进；其中一部分事件包含一场战斗，另一部分没有战斗。
5. 战斗胜利后按 `returnNodeByResult.win` 返回战后剧情。正式失败结束本次冒险，进入独立战败页，只能返回主菜单开始新的委托，不能回地图重试。
6. 事件走到 **`finish` 节点**时才真正结算：事件首次被记为完成；E01开幕与E01R领奖不耗时，其余委托推进1天（第7天封顶）；正式战斗胜利与E01R显示信用点和卡牌奖励页，其余显示原事件结算页。
7. 在结算页确认奖励后回到城市地图。当前8个事件中，仅E01R要求完成E01及任意三个不同委托；原E12终局已删除，不会自动标记第一周完成。

移动、对白推进、出牌、结束回合和治疗都**不会**自动推进日期；第二、第三周目前没有内容。

## 目标与佣兵身份

### 目标

界面上的目标文字由 [game.gd](../scripts/game.gd) 的 `objective()` 决定。【已实现】

- 当 `flags.week1Complete` 为真时显示“第一周已完成 · 可继续探索剩余事件”。
- 否则只有一个已刷新事件时显示“事件标题 / 地点名”；多个时显示“N 个可进行的事件”。
- 没有已刷新且仍符合条件的事件时显示“探索城市，寻找新的委托”。

当前共8个事件：E01开幕、E01R酒馆回访，以及E02／E04／E11／E13／E14／E15六项独立委托。六项分别处理失控机器人、拦路黑帮、变异鱼、修枝猎犬、占厂抢修工与信标水母，均无前置；E01R要求完成E01及任意三项不同委托。现有对白不引用旧寻人目标。

### 自由佣兵

主角始终以自由佣兵身份接受委托。界面不再显示身份栏目，主菜单摘要只显示当前地点。没有加入组织、阵营归属、阵营条件或阵营专属事件。【已实现，2026-10-15】

港口追击、赛博精神病和机甲复仇已移除；所有地点仍可进入，当前8个事件按各自前置参与刷新。

### 委托目标

委托目标字段`state.targetId`仍接受`richard`、`lumina`或空字符串，此字段仅保留旧档兼容，新开幕不再设置目标，也不解锁港口事件。现有事件均不使用`{目标姓名}`；旧替换器保留空目标回退及已知角色名解析，仅供兼容。

## 地图、地点与事件

### 城市地图页面

可用鼠标滚轮或右下角 **−／＋** 将地图缩放到 **100%～150%**；点击中间百分比恢复全图。大于 100% 时按住鼠标左键向任意方向拖动，移动范围限制在地图边缘，100% 时固定不移动。放大后的地点标记和文字保持原大小；拖动图标不会误开详情，点击仍可查看地点。重新进入地图时恢复全图。【已实现】

地图页面读取 [data/map.json](../data/map.json) 的 `cityMapAssetId`，当前为 `city_map_expanded`，经 [assets.json](../data/assets.json) 指向 `assets/map/map-expanded-v1.png`。扩绘底图按原始比例铺排；`mapContentRect` 标出原城市在扩绘图中的归一化区域，17 个地点仍以原城市区域为锚点基准。旧 `map.jpg` 保留作来源与后备资源。【已实现】

- `coordinatesStatus` 为 `illustration-calibrated`。17 个 `mapAnchor`（0—1 比例坐标）相对于 `mapContentRect` 所标出的原城市区域，并非整张扩绘图；`map_rect` 表示该区域，`_art_rect` 表示完整底图。更换底图时先核对这两个坐标基准，保持原城市构图的扩绘可通过校准 `mapContentRect` 保留地点锚点；城市内部布局变化时才需相应重校 `mapAnchor`。`mapDisplay` 的 `offset`／`labelOffset`／`avatarSide` 只影响展示，`hitArea` 仅作元数据，实际点击命中取自图钉与头像的当前尺寸。
- 地图符号复用 `assets/icons/map/` 的 17 份素材，对应 17 个运行时地点；科技教会使用 `church.png`，默认开放，目前没有专属事件或服务。营地保留“归零运动营地”的名称与背景设定，主角可直接进入。
- 标记高度为逻辑 72 像素。当前位置显示青色标记与圆形诺伦头像；已刷新且仍符合条件的事件按战斗类型显示地点边框。两者落在同一地点时同时出现。
- 事件徽章按战斗类型分组：普通黄色感叹号、精英红色感叹号、Boss彩色霓虹故障骷髅头；同类型数量合计。事件不分主线／支线。所有地点开放，不显示地点锁或完成勾标。沃斯商场、黑市、地下诊所优先使用绿色边框及常驻无穷环角标，事件角标独立保留。
- 选中地点展示名称和详情，不额外叠加白色外圈，保留原有状态颜色。悬停时图案在 0.16 秒内轻微提亮并放大至 106%，不弹出简介卡；点击固定详情，已有固定卡时悬停其他地点不替换它。
- 常驻地点（黑市、沃斯商场、地下诊所）无事件时显示“常驻地点”，不显示“暂无新事件”或“此地暂无新的事件”。黑市底部入口显示红色“进入黑市 →”；沃斯商场入口为“进入商场 →”，其他地点入口与治疗功能保留。
- 详情面板列出该地点的描述与可开始事件，事件统一显示“刷新时间：随时”（有区间的事件按区间显示），点击事件按钮调用 `start_event()`；含治疗服务时显示回复比例和费用，余额不足或满血时禁用治疗，底部提供“进入地点 →”。空白处或 Esc 关闭详情，周次弹窗存在时 Esc 先关闭弹窗；详情靠近窗口边缘会自动翻转或平移，不移动底图。长标题与多事件可垂直滚动，底部按钮保持可用。
- 地图上的“周次档案”弹窗显示第一周进度与第几天，并注明第二、第三周内容待设计。

目标由 `Game.map_target_events()` 推导：返回全部已刷新且仍符合条件的事件，按事件 ID 稳定排序。`state.targetId` 是委托对象字段（理查德／卢米娜），`activeEventId` 可能停留在上一次事件，二者都不作为地图目的地。

### 黑市卡牌交易

2026-10-23接入。城市地图选择黑市并进入，打开老板与柜台专属界面，两行共十格：上排五张卡，下排四张卡和一个出售区。

- 每批从当前正式B／A／S牌中等概率无放回抽九张，不出现C级卡；同批不重复，跨批可再次出现同一张牌。
- 购买前确认价格，成功扣除信用点并把一张牌加入当前卡组；已购货位显示售罄，本批不自动补齐。
- 出售区选择一张实际拥有牌，包含C级初始牌。确认后移除一张实例并获得信用点；同名多张只移除一张，每批补货前最多成功出售一次。
- 第1、4、7天开始时整批重抽，买过和没买过的卡都替换，重置所有售罄状态和出售次数。进出黑市、读档、第7天封顶后的日期操作不重复补货；进入、购买和出售不推进日期。
- 购买价以B50／A100／S150为中心，上下浮动10信用点，逐货位等概率随机整数：B40–60、A90–110、S140–160；本批生成一次，进出和读档不重抽。出售固定C25／B50／A100／S150，旧无品级测试牌回收25。本轮价格修订会一次性更新旧库存未售卡牌标价，保留牌ID、售罄、出售次数、余额和卡组；已成交不追算。写入成功后记住价格版本，同版本保持本批标价不变。
- 库存、售罄、出售次数及实际卡组随冒险保存；旧档缺字段时生成所在补货周期库存并落盘，后续读档不重抽。交易保存失败不扣款、不移牌、不消耗出售机会。

### 事件可用性

E01与六个委托前置为**无**；E01R要求完成E01及E02／E04／E11／E13／E14／E15中任意三个不同委托。八个事件刷新时间均为**随时**。成为可开始事件仍需：未完成、位于刷新时间区间、地点存在，且已在当前冒险的`refreshedEventIds`中。

全地图同时最多3项，保留仍合格的已有项，空位从其余候选随机补齐。地图与地点使用同一个持久化池，打开地图或读档不重抽已有项；“无前置”不等于所有事件同时显示。E01R达到三委托条件后只是加入候选，不保证当场刷新；仍保留合格已有项并随机补位。候选与已刷新事件都按ID展示，`start_event()`再次检查刷新池和时间条件。

`refreshTimeRange`的日期起止包含两端，`null`表示该侧不限；目前全部两端为`null`。支付选项自身的信用点条件继续生效，不是任务前置。所有事件为一次性，完成后不再次刷新。

E13／E14／E15战前对白结束后直接进入战斗，不提供战斗／暂离选择；跳过对白同样直接进入战斗。战斗胜利后推进至`finish`才完成与结算，正式战败仍进入终局。园丁、值班电工、码头值守员只参与对白，不加入战斗，不新增护送目标或倒计时。

## 选择、条件与信用点

### 条件

对白节点和事件可用性都用同一套 `meets()` 条件求值，支持的键为：【已实现】

| 条件键 | 含义 |
| --- | --- |
| `all` | 列表内全部条件成立 |
| `any` | 列表内至少一个条件成立 |
| `completed` | 指定事件 ID 已完成 |
| `completedCount` | `ids`中至少`atLeast`个不同事件已完成，重复ID不重复计数 |
| `flag` | 指定旗标为真 |
| `target` | 当前委托目标等于指定值 |
| `creditsAtLeast` | 信用点不少于指定值 |

出现未知条件键时，`meets()` 会输出错误并返回假，不把未知条件当作成立。

### 选项

对白选项在对话节点里以 `choices` 数组定义，每个选项包含 `id`、`label`、`next`，可选 `condition` 与 `effects`。【已实现】

- 不满足 `condition` 的选项按钮会被禁用；若缺的是信用点，按钮文字会追加"（还差 N CR）"。
- 选择后先校验目标节点和效果，再整批提交 `effects`，最后进入 `next` 节点。
- 若 `next` 是 `@map`，表示返回城市地图。
- 已做过的选择会记录在 `choiceHistory` 中，键为"事件 ID : 节点 ID"。
- 选项效果实行**全有或全无**：任一条效果校验失败，整个选择都不提交。

### 效果

事件选项与 `finish` 节点都能使用效果动作，当前支持：【已实现】

| 动作 `op` | 作用与限制 |
| --- | --- |
| `setFlag` | 写入一个旗标；键不能为空 |
| `spendCredits` | 扣信用点；额度不足则失败 |
| `addCredits` | 增加信用点；负数失败 |
| `setTarget` | 兼容旧寻人剧情；开幕不再使用 |
| `grantTechnology` | 获得科技；有空槽且`equip=true`时自动携带，满槽不替换，重复拥有不复制 |
| `completeEvent` | 首次把指定事件记入已完成列表；E01与E01R不耗时，其余委托同时推进1天（第7天封顶）；重复提交不再推进 |
| `healHpPercent` | 按最大 HP 比例回复，封顶最大值；比例须在 0—1 |
| `advanceDay` | 显式推进天数，第7天封顶，不自动切周 |
| `finishWeek` | 设置 `week1Complete` 旗标 |
| `grantReward` | 按奖励 ID 发放信用点奖励；同一"事件:奖励"只发一次 |

- 新游戏初始信用点为 **100**（见 [config.json](../data/config.json) 的 `initialCredits`）；已有存档保留原余额。

### 后巷深处、力量与易伤（2026-10-19）

E04／B04接入黑帮老大与两名黑帮小弟：老大30 HP，每名小弟15 HP。两小弟依数组顺序各行动一次，最后老大行动；画面中老大在最右，两小弟位于左列一前一后，呈三角形。

- 小弟：每回合攻击4，已有力量逐段增加伤害。
- 老大：起始循环强化，每次给两名存活小弟各加1层力量，小弟下轮攻击才享受本次强化。
- **只在完整回合结束、下一玩家回合开始时**检查小弟是否已死亡；一个完整回合包含玩家行动和随后的全部敌方行动。初始阶段若在玩家行动中击杀小弟，当轮敌方阶段老大仍执行已显示的强化；若在敌方阶段被弹反或污染击杀，老大也不在中途改招。敌方全部行动结束后检测死亡，下一玩家回合的意图立即显示攻击8，再按「攻击8 → 施加2层易伤 → 攻击6」永久循环。另一名小弟随后死亡不会重置循环。
- 力量：每层使每段攻击基础伤害+1；可为负，范围−999～999，伤害最低0，不随回合减少。远程先加力量再乘形态倍率。污染、裂伤、弹反等特殊Buff伤害不受力量影响。
- 易伤：受到的**攻击伤害**增加50%，每段四舍五入后先扣格挡，增幅不随层数提高；不作用于污染、裂伤、弹反等Buff伤害。持有者自身回合结束减1层，最多999层，0层消失。例如敌方施加2层后，玩家下次回合末降至1层，该轮敌方攻击仍增幅；再下一次玩家回合末归零。

正式B04与主菜单B04演练均为15／15／30 HP；独立三人耐久动作测试仍各100 HP。进行中的旧战斗继续读取原快照，不自动替换人数、生命或意图；新开战斗生效。

### 变异的鱼与污染（2026-10-17）

黑潮泵站B11有两只变异的鱼，各30 HP，依序行动并独立循环意图：

| 敌人 | 第1次行动 | 第2次行动 | 第3次行动 |
| --- | --- | --- | --- |
| 第一只 | 攻击6 | 攻击2×2 | 施加3层污染 |
| 第二只 | 施加3层污染 | 攻击6 | 攻击2×2 |

每段鱼攻击在扣除格挡后造成大于0的实际伤害，便向受击者追加2层污染；全挡或0伤害不追加，多段分别计算。主动污染意图直接加层，不消耗格挡。

每只鱼死亡时向角色施加3层污染，仅在存活转为死亡时触发一次；攻击、裂伤、弹反或污染致死都生效，同时击杀两只合计6层。施加层数不消耗格挡、不立即造成伤害，仍受999层上限限制；后续污染结算可被格挡。最后一只鱼死亡也先施加，再判定胜利。已进行的旧战斗若显式保存 `deathPollution=5`，仍保留每只5层；没有该字段的更早快照默认为0，新开战斗读取每只3层。

污染为负面效果，双方角色均可持有，最多999层。持有者自身回合结束时先受到等于当前层数的伤害（先扣格挡），然后减少1层，降至0消失。它不会在对方回合结束时结算，也不会触发鱼的攻击追加污染或弹反。玩家污染在敌人行动前结算，若致死立即战败；敌人污染在其行动后结算。

主菜单“敌人测试”使用同样的双鱼30 HP配置。已有战斗快照继续保留原敌人数值和数量，新配置需新开B11战斗。

## 治疗与日期

### 治疗

【临时原型】实验室与地下诊所通过地点服务 `healHpPercent` 恢复生命：

实验室研究生物样本、污染分析与组织修复，以冷白实验台、密封培养舱和青色监测灯为环境特征；当前没有专属事件，组织修复装置提供以下恢复服务。地点内部 ID 保留 `hospital`，继续兼容现有存档。

- 每次恢复**最大 HP 的 30%**，封顶到最大值。
- 地下诊所每次支付 **150 信用点**；信用点不足时无法治疗，不扣款也不回血。
- 实验室维持**免费**。两处治疗均**不耗时**、不推进日期，没有次数限制；满血时不可治疗，也不收费。

服务由 `heal_at(place_id)` 统一处理，要求当前在地图或地点页；扣款和回血一次提交，成功后写入检查点并弹出提示。治疗量沿用四舍五入整数 HP、封顶最大 HP；接近满血时仍按一次治疗收费。地图详情和地点页显示费用，并在余额不足或满血时禁用治疗按钮。

### 日期

【已实现】

- 新游戏为**第1天**；日期是正整数，最多第7天，不会自动进入第二周。
- E01开幕对话完成不耗时，结束并返回地图后仍为**第1天**。E01R回访领奖也不耗时，其余委托首次到达 `finish`、加入完成列表时推进**1天（第7天封顶）**，包括全部战斗委托；重复完成同一事件不再耗时。
- 战斗胜利后仍需推进战后对白到 `finish` 才耗时；战败、移动、普通对白推进、出牌、结束回合、治疗、奖励选择／放弃和演练都不推进日期。
- `advanceDay` 仍可由明确请求或开发工具调用，第7天封顶。顶栏保留七格进度条，第7天继续完成事件时日期仍为7。
- 当前没有第一周终局事件，也不会自动切换后续周；第7天完成事件后日期仍为7。
- 旧档保留原日期，不根据已有完成事件追算耗时；缺少刷新池时补建池。第二、第三周仍为 `pending` 占位，没有事件。

| 精英 `elite` | 50% | 40% | 10% |
| Boss `boss` | 0% | 0% | 100% |

C 级不进入奖励池。以上为**每个候选的固定品级概率**，不是三选一中至少出现一张的概率；没有隐藏保底或随掉落变化的修正。现有 B／A／S 分别有 23／9／4 种，每级都足够生成三张不同的卡；若未来某级在一次抽取中用尽，只在仍有候选且权重大于零的品级间重新归一化。

奖励使用开战时冻结的 `battleType`；现有六场仍全部为普通。已生成的奖励保留原候选，不因概率调整或读档重新抽取；尚未生成的奖励使用新规则。若正权重品级合计不足三种有效卡，提示配置错误，本次不生成奖励、不到账信用点，也不标记领取。

2026-10-24金额调整仅作用于新生成奖励；旧档已到账的1000信用点战斗／酒馆回访记录保留原金额、候选与领取状态，不回算余额、不重复发奖。金钱芯片仍在正式胜利时额外提供30点，与基础奖励分开结算。

右下角“返回地图”离开奖励页。未选卡时离开将放弃本次选卡，界面会显示提示，已到账信用点保留。Esc／“返回奖励”仅关闭选卡弹层，不消耗机会。菜单继续和读档保留候选及领取状态，不重复发放。模拟演练、失败与无战斗事件不产生这份奖励。

当前 `rewardIds` 和事件奖励目录仍为空；战后信用点及旧测试卡兼容定义在 [prototype/rewards.json](../data/prototype/rewards.json)，品级概率在 [card_reward_rates.json](../data/card_reward_rates.json)。非战斗事件保留上面的旧结算方式；道具奖励等其他机制尚未实现，黑市交易见专节。

### 存档

2026-10-23：独立战败页显示“战败 / 本次冒险已结束”，只提供“返回主菜单”按钮；Esc同效且不再询问退出。主菜单禁用失败冒险的“继续委托”，可开始新的委托。失败检查点保留；旧档仍标记 `result: lose`、停在 `lose` 对白或战斗快照已失败时，也转为战败页。演练失败仍恢复原冒险并返回菜单。

【已实现】

- **2026-10-22：正式战斗中途退出后从本场开局继续。** 新战斗记录开战时的 HP、敌人、牌组顺序和资源；返回主菜单或关闭程序后点击继续，会回到第一回合，恢复同一初始手牌，不重新洗牌。战斗中已受伤害、已用卡牌、科技和状态在这次重开时撤销，开战前已有的损血仍保留。
- 若胜利或失败已完成规则结算，即使攻击动画尚未播完，也保留该结果：胜利进入战后剧情，正式失败进入战败终局，不能重开战斗或继续冒险。只查看牌库／牌堆再关闭，不算退出战斗。
- 没有 `battleStart` 开局记录的旧战斗无法准确还原当时的 HP 和牌序，因此沿用原进度继续；从下一场新战斗开始使用上述规则。演练仍不保存、不影响正式冒险。
- 冒险检查点为 `user://checkpoint.json`，备份为 `checkpoint.json.bak`，写入中间文件为 `.tmp`。
- 冒险存档 `schemaVersion` 为 2，包含 HP、最大 HP、天数、战斗快照及 `battleStart`、物品栏、剧情状态等；自动读取版本 1 存档并迁移为 HP 100、日期 1。
- 保存时先写`.tmp`，确认旧主档有效后经`.bak.tmp`轮换备份，再替换主档；坏主档不覆盖现有备份，复制或替换失败会提示。加载依次尝试主档与备份，再迁移与校验；两份文件均损坏时仍无法自动恢复。
- 正式胜利的战后结算若保存失败，战斗画面显示“重试战后结算”；存储恢复后点击重试即可继续，不重复战斗或发放收益。
- `checkpoint()` 与 `commit_combat()` 不检查保存函数返回值：写盘失败会提示，但内存状态已经提交，不会自动回滚。
- 因此逻辑结算成功不代表一定可靠落盘；遇到保存错误应先排查权限与磁盘。

备份轮换、迁移范围与恢复步骤的完整说明见 [维护文档](维护文档.md) 的存档章节。请勿用测试存档覆盖正式玩家进度。
