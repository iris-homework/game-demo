**核对信息**：核对日期 **2026-10-07（Asia/Shanghai）**；基线版本 **0.2.4-r1**（以 [project.godot](../project.godot) 为准），地图页面于同日接入。本文通过 [scripts/game.gd](../scripts/game.gd)、[scripts/combat/combat_model.gd](../scripts/combat/combat_model.gd)、[scripts/map.gd](../scripts/map.gd) 及相关视图与 [data](../data) 下的 JSON 做**文档静态核对**，不重跑剧情与战斗的完整游玩。地图的画面与真实指针输入验收见[地图界面验收清单](地图界面验收清单.md)：本轮已执行 `36-capture-final`（5 checks）与 `37/38/39` 三尺寸输入（各 111 checks，0 failures）。历史处理约定见 [维护文档](维护文档.md) 与 [修改记录](修改记录.md)，功能接入见 [开发接入说明](开发接入说明.md)。

## 玩法循环

2026-10-10 补充：当前可玩主角仍只有诺伦，初始 100 HP、十张基础牌（直击×4、护身×4、贴近×1、拉开距离×1）。角色专属技能尚未启用；本轮增加角色配置入口，没有增加选角界面。2026-10-11 战斗科技也接入角色独立配置，诺伦沿用原六张及现有效果，见下文。

当前是第一周的原型流程：单主角诺伦在城市里接下委托，通过城市总览地图选择地点和事件，用对白与选择推进剧情，在部分事件中进行临时卡牌战斗，最后走到事件结算。【已实现】

一次完整的循环如下：

1. 从主菜单选择"开始新的委托"或"继续旅程"。
2. 新游戏直接进入 **E01"午夜酒馆"** 的对白，在酒馆里接下委托并选择追踪目标（理查德或卢米娜）。已有进度时，菜单会先要求确认覆盖；新冒险不清空局外科技档案。
3. 进入**城市地图**。地图上可以查看地区详情，也可以直接开始当地事件，或先“进入地点”。
4. 事件由对白节点与选择推进；其中一部分事件包含一场战斗，另一部分没有战斗。
5. 战斗结束（自然胜利、自然失败）后，按该战斗的 `returnNodeByResult` 回到对应剧情节点。
6. 事件走到 **`finish` 节点**时才真正结算：事件被记为完成；正式战斗胜利显示战后奖励页，其余显示原事件结算页。
7. 在结算页确认奖励后回到城市地图。完成 E12 的 `finish` 会标记第一周完成。

移动、对白推进、出牌、结束回合和治疗都**不会**自动推进日期；第二、第三周目前没有内容。

## 目标与佣兵身份

### 目标

界面上的目标文字由 [game.gd](../scripts/game.gd) 的 `objective()` 决定。【已实现】

- 当 `flags.week1Complete` 为真时显示"第一周已完成 · 可继续探索支线"。
- 否则取当前可开始事件中的第一个**主线事件**（`optional` 为假），显示"事件标题 / 地点名"。
- 若没有可开始的主线事件，显示"探索城市，寻找新的线索"。

推进主线的关键在于：在 E01 选定追踪目标，取得后巷线索与港口线索，在港口完成所选追踪委托，随后在 E12 结束第一周。

### 自由佣兵

主角始终以自由佣兵身份接受委托。界面不再显示身份栏目，主菜单摘要只显示当前地点。没有加入组织、阵营归属、阵营条件或阵营专属事件。【已实现，2026-10-15】

完成 **E05A 或 E05B** 后，两条委托线均可进入 E12，并开放 E08、E11 支线。沃斯大楼、归零运动营地、发电厂、五号街区、黑潮泵站与白昼庭院使用相同港口完成条件；沃斯大楼、营地和发电厂当前只有地点介绍，无事件。

### 委托目标

委托目标字段为 `state.targetId`，只接受 `richard`、`lumina` 或空字符串。E01 的选择会写入该字段，之后的 E05A / E05B 分别要求 `richard` / `lumina`，对白中的 `{目标姓名}` 会替换成对应人物名（理查德 / 卢米娜）。若目标名缺失或出现未知变量，运行时会报配置错误。【已实现】

## 地图、地点与事件

### 城市地图页面

可用鼠标滚轮或右下角 **−／＋** 将地图缩放到 **100%～150%**；点击中间百分比恢复全图。大于 100% 时按住鼠标左键向任意方向拖动，移动范围限制在地图边缘，100% 时固定不移动。放大后的地点标记和文字保持原大小；拖动图标不会误开详情，点击仍可查看地点。重新进入地图时恢复全图。【已实现】

地图页面读取 [data/map.json](../data/map.json) 的 `cityMapAssetId`（经 [assets.json](../data/assets.json) 的 `city_map` 指向 `assets/map/map.jpg`）。底图按原始比例铺排，17 个地点以图钉尖端锚定到对应建筑。【已实现】

- `coordinatesStatus` 为 `illustration-calibrated`，即 17 个 `mapAnchor`（0—1 比例坐标）已按本轮底图逐个校准。`mapDisplay` 的 `offset`／`labelOffset`／`avatarSide` 只影响展示，`hitArea` 仅作元数据，实际点击命中取自图钉与头像的当前尺寸。
- 地图符号复用 `assets/icons/map/` 的 17 份素材，对应 17 个运行时地点；科技教会使用 `church.png`，默认开放，目前没有专属事件或服务。营地保留“归零运动营地”的名称与背景设定，主角可直接进入。
- 标记高度为逻辑 72 像素。当前位置显示青色标记与圆形诺伦头像；下一步可推进的主线目标显示金色图钉。两者落在同一地点时同时出现。
- 事件徽章：主线与可选分别显示 `!`／`?` 两枚角标，可以同时出现；数量按本类分别统计，不是两类合计。数量为 1 时只显示符号，大于 1 时在符号后显示数字。已完成且暂无新事件的地点不再显示勾标；所有地点均开放，不显示地点锁。
- 选中地点展示名称和详情，不额外叠加白色外圈，保留原有状态颜色。悬停时图案在 0.16 秒内轻微提亮并放大至 106%，不弹出简介卡；点击固定详情，已有固定卡时悬停其他地点不替换它。
- 详情面板列出该地点的描述与可开始事件，任务类型文案为“主线任务”与“可选事件”，点击事件按钮调用 `start_event()`；含服务时显示“治疗 · 回复 30% 最大 HP”，底部提供“进入地点 →”。空白处或 Esc 关闭详情，周次弹窗存在时 Esc 先关闭弹窗；详情靠近窗口边缘会自动翻转或平移，不移动底图。长标题与多事件可垂直滚动，底部按钮保持可用。
- 地图上的“周次档案”弹窗显示第一周进度与第几天，并注明第二、第三周内容待设计。

目标由 `Game.map_target_events()` 推导：按事件 ID 稳定排序，多条可推进主线全部标金色，不任意选择其中一条。`state.targetId` 是委托对象字段（理查德／卢米娜），`activeEventId` 可能停留在上一次事件，二者都不作为地图目的地。

地图直接治疗调用同一个 `heal_at()`，不改变 `state.currentPlaceId`；治疗引起的视图重建会在原地恢复所选详情。从地点返回地图时从干净总览开始。地图采用总览插画加点击标记的交互方向，不制作小人跑图、行走动画、寻路或碰撞。美术方向见 [美术方向](美术方向.md)，实际结果与证据见 [修改记录](修改记录.md) 与 [地图界面验收清单](地图界面验收清单.md)。

### 事件可用性

正常地图或地点流程中，要开始一个事件，必须同时满足【已实现】：

1. 未出现在 `completedEventIds` 中；
2. 满足事件自身的 `unlockCondition`；
3. 其所在地点 ID 存在。

`available_events()` 过滤完成状态与事件条件，`start_event()` 再校验事件条件与地点 ID。地点配置不再使用 `unlockCondition` 或 `lockHint`；开放地点不会提前解锁剧情事件。

所有第一周事件的 `repeatPolicy` 都是 `once`，当前通过完成列表阻止事件重复触发。事件列表排序把主线事件排在可选事件之前。

## 选择、条件与信用点

### 条件

对白节点和事件可用性都用同一套 `meets()` 条件求值，支持的键为：【已实现】

| 条件键 | 含义 |
| --- | --- |
| `all` | 列表内全部条件成立 |
| `any` | 列表内至少一个条件成立 |
| `completed` | 指定事件 ID 已完成 |
| `flag` | 指定旗标为真 |
| `target` | 当前委托目标等于指定值 |
| `creditsAtLeast` | 信用点不少于指定值 |

出现未知条件键时，`meets()` 会输出错误并返回假，不把未知条件当作成立。

### 选项

对白选项在对话节点里以 `choices` 数组定义，每个选项包含 `id`、`label`、`next`，可选 `condition` 与 `effects`。【已实现】

- 不满足 `condition` 的选项按钮会被禁用；若缺的是信用点，按钮文字会追加"（还差 N CR）"。
- 选择后先校验目标节点和效果，再整批提交 `effects`，最后进入 `next` 节点。
- 若 `next` 是 `@map`，表示返回城市地图。
- 已做过的选择会记录在 `choiceHistory` 中，键为"事件 ID : 节点 ID"。
- 选项效果实行**全有或全无**：任一条效果校验失败，整个选择都不提交。

### 效果

事件选项与 `finish` 节点都能使用效果动作，当前支持：【已实现】

| 动作 `op` | 作用与限制 |
| --- | --- |
| `setFlag` | 写入一个旗标；键不能为空 |
| `spendCredits` | 扣信用点；额度不足则失败 |
| `addCredits` | 增加信用点；负数失败 |
| `setTarget` | 设置委托目标；只接受理查德 / 卢米娜 |
| `completeEvent` | 把指定事件记入已完成列表 |
| `healHpPercent` | 按最大 HP 比例回复，封顶最大值；比例须在 0—1 |
| `advanceDay` | 推进天数；日期封顶第 7 天 |
| `finishWeek` | 设置 `week1Complete` 旗标 |
| `grantReward` | 按奖励 ID 发放信用点奖励；同一"事件:奖励"只发一次 |

### 信用点

信用点是当前实现的支付货币，初始数量与支付分支用于原型验证。【临时原型】

- 新游戏初始信用点为 **0**（见 [config.json](../data/config.json) 的 `initialCredits`，注释说明为演示值）。
- 目前**唯一**需要支付的选项是 E03 支付艾克 **300 信用点**买情报（条件 `creditsAtLeast: 300`）。初始为 0，所以正常开局无法直接支付，需要 F1 开发面板测试支付分支，或拒绝支付改用战斗路线。
- 奖励目录 [rewards.json](../data/rewards.json) 当前为空对象，`grantReward` 只支持 `type` 为 `credits` 的奖励。

## 战斗

### 诺伦卡牌（2026-10-16 / 0.4.0）

40 种卡牌及完整统一结算已接入，规则、状态、控制台和存档边界集中维护在[诺伦卡牌与控制台](诺伦卡牌与控制台.md)。新委托仅拥有十张 C 级初始牌，其他卡通过战后奖励或 F2 控制台获得。牌库可切换“已拥有”与“全部卡牌”，显示同名份数。

开场近战、2 弹药；每回合 3 能量、抽 5 张，弹药最多 6。近战每张攻击回弹 1，远程每张攻击耗弹 1、本体伤害乘 1.5；实际进入近战抽 1，实际进入远程的下张攻击减费 1。抽牌效果可超过五张。开场和弃牌回收均洗牌。

非攻击牌选中后跟随鼠标并优先接管左键，自身／群体非攻击牌在整个游戏画面内点击或拖放即可使用；点击其他手牌或按钮不会触发其操作。首次原地选牌松手不出牌，不显示释放大框或提示文字。需要敌人的技能仍须点有效敌人，点其他位置保留选中；右键／Esc 取消后恢复正常按钮操作。攻击牌保持贴底居中置顶及原有目标要求。拆卸弹药与可选额外耗弹都有明确的选择窗口。能量／弹药不足不能打出。结算一次后保存，再播放演出；整次演出结束才接受下一张牌。

回合结束弃置剩余手牌，敌人依次攻击并结算弹反，存活时进入下一玩家回合：清除玩家格挡、恢复能量、抽五张。状态按各自持续规则结算，能力与消耗牌离开循环。虚弱有层数时固定降低敌人攻击伤害 25%，逐段四舍五入，与层数无关；该敌人回合结束减 1 层，减至 0 失效，仍最多 999 层。全部敌人 HP 归零胜利，玩家 HP 归零失败；结果继续使用原剧情返回流程。

近战接近挥刃，远程切换现有持枪素材；太近时先后跳。B04使用下述黑帮三人战规则与专用动作，B11使用变异鱼美术与双鱼规则；其他正式敌人仍为Finn动作测试替身与3 HP／攻击1原型；B12演练及独立三人动作测试的每名对手为100 HP，不能据此认定新牌组难度已平衡。新专项包含三敌与多段攻击的测试夹具；真人完整游玩、卡牌升级、商店／删牌构筑和更多敌方意图不在本轮完成范围。

旧战斗保留冻结的目录和测试规则，配置修改不替换进行中的快照。当前正式卡图未制作，卡面为按稀有度着色的数据排版。

### 后巷深处、力量与易伤（2026-10-19）

E04／B04接入黑帮老大与两名黑帮小弟：老大30 HP，每名小弟15 HP。两小弟依数组顺序各行动一次，最后老大行动；画面中老大在最右，两小弟位于左列一前一后，呈三角形。

- 小弟：每回合攻击4，已有力量逐段增加伤害。
- 老大：起始循环强化，每次给两名存活小弟各加1层力量，小弟下轮攻击才享受本次强化。
- **只在整个敌方回合开始时**检查小弟是否已死亡；若已有任一小弟死亡，老大从攻击8开始，永久切换为「攻击8 → 施加2层易伤 → 攻击6」循环。玩家回合击杀小弟后，意图不立即切换；若小弟在敌方行动中被弹反或污染击杀，老大本轮仍执行原意图，到下一次敌方回合开始才切换。另一名小弟随后死亡不会重置已开始的循环。
- 力量：每层使每段攻击基础伤害+1；可为负，范围−999～999，伤害最低0，不随回合减少。远程先加力量再乘形态倍率。污染、裂伤、弹反等特殊Buff伤害不受力量影响。
- 易伤：受到的**攻击伤害**增加50%，每段四舍五入后先扣格挡，增幅不随层数提高；不作用于污染、裂伤、弹反等Buff伤害。持有者自身回合结束减1层，最多999层，0层消失。例如敌方施加2层后，玩家下次回合末降至1层，该轮敌方攻击仍增幅；再下一次玩家回合末归零。

正式B04与主菜单B04演练均为15／15／30 HP；独立三人耐久动作测试仍各100 HP。进行中的旧战斗继续读取原快照，不自动替换人数、生命或意图；新开战斗生效。

### 变异的鱼与污染（2026-10-17）

黑潮泵站B11有两只变异的鱼，各30 HP，依序行动并独立循环意图：

| 敌人 | 第1次行动 | 第2次行动 | 第3次行动 |
| --- | --- | --- | --- |
| 第一只 | 攻击6 | 攻击2×2 | 施加3层污染 |
| 第二只 | 施加3层污染 | 攻击6 | 攻击2×2 |

每段鱼攻击在扣除格挡后造成大于0的实际伤害，便向受击者追加2层污染；全挡或0伤害不追加，多段分别计算。主动污染意图直接加层，不消耗格挡。

每只鱼死亡时向角色施加5层污染，仅在存活转为死亡时触发一次；攻击、裂伤、弹反或污染致死都生效，同时击杀两只合计10层。施加层数不消耗格挡、不立即造成伤害，仍受999层上限限制；后续污染结算可被格挡。最后一只鱼死亡也先施加，再判定胜利。

污染为负面效果，双方角色均可持有，最多999层。持有者自身回合结束时先受到等于当前层数的伤害（先扣格挡），然后减少1层，降至0消失。它不会在对方回合结束时结算，也不会触发鱼的攻击追加污染或弹反。玩家污染在敌人行动前结算，若致死立即战败；敌人污染在其行动后结算。

主菜单“敌人测试”使用同样的双鱼30 HP配置。已有战斗快照继续保留原敌人数值和数量，新配置需新开B11战斗。

## 治疗与日期

### 治疗

【临时原型】医院与地下诊所通过地点服务 `healHpPercent` 治疗：

- 每次恢复**最大 HP 的 30%**，封顶到最大值。
- 原型阶段**免费**、**不耗时**，没有其他次数或费用限制。

服务由 `heal_at(place_id)` 统一处理，要求当前在地图或地点页；治疗成功后写入检查点并弹出提示。

### 日期

【已实现】

- 新游戏为**第 1 天**，日期范围 1—7。
- 移动、对白、出牌、结束回合和治疗都不会自动推进日期。
- 只有明确请求或开发工具才会调用 `advanceDay`，且日期封顶第 7 天，不会自动进入下一周。
- 完成 E12 的 `finish` 会设置 `week1Complete`，但**不会**改变日期。
- 第二、第三周在 [week2](../data/weeks/week2/week.json)、[week3](../data/weeks/week3/week.json) 中只有 `status: pending` 的占位，没有事件。

### 开发面板

F1 在开发模式下打开面板，可把信用点设为 0 或 300、日期 +1，以及把 HP 设为 50 / 90 / 1 / 100。它只修改当前检查点，用于测试支付与受伤分支。【临时原型】

## 奖励、存档、演练与科技

### 奖励领取

【已实现】事件结算页读取事件的 `rewardIds`：

- 若事件没有奖励，按钮显示"返回城市地图 →"。
- 若有奖励，按钮显示"领取并返回城市地图 →"，列出"可领取 / 已领取"状态。
- 两个按钮都走 `claim_rewards()`：按奖励 ID 逐个发放，然后返回城市地图。
- 发放以"事件 ID : 奖励 ID"为键记录在 `claimedRewardIds` 中，同一奖励不重复发放。

**2026-10-09 / 0.3.19-rewards 新增战后奖励【已实现，卡牌为临时原型】**：正式战斗胜利、战后对白与选择全部结束后，在 `finish` 显示战斗奖励页，自动到账 **1000 信用点**。点击“奖励卡牌”打开三个不同的非 C 诺伦卡选项，点一张或按 1／2／3 领取；候选暂按等概率抽取。已选卡加入冒险牌组，后续正式战斗会使用；同一场奖励只允许选一张。

右下角“返回地图”离开奖励页。未选卡时离开将放弃本次选卡，界面会显示提示，已到账信用点保留。Esc／“返回奖励”仅关闭选卡弹层，不消耗机会。菜单继续和读档保留候选及领取状态，不重复发放。模拟演练、失败与无战斗事件不产生这份奖励。

当前 `rewardIds` 和正式奖励目录仍为空；新增临时奖励独立配置于 [prototype/rewards.json](../data/prototype/rewards.json)。非战斗事件保留上面的旧结算方式。【设计未实现正式奖励池】

### 存档

【已实现】

- 冒险检查点为 `user://checkpoint.json`，备份为 `checkpoint.json.bak`，写入中间文件为 `.tmp`。
- 冒险存档 `schemaVersion` 为 2，包含 HP、最大 HP、天数、战斗快照、物品栏、剧情状态等；自动读取版本 1 存档并迁移为 HP 100、日期 1。
- 保存时先写 `.tmp`，把旧主文件复制为 `.bak`，再替换主文件；加载依次尝试主文件与备份，再迁移与校验。`.bak` 是上一次主文件的副本，**不保证一定有效**。
- `checkpoint()` 与 `commit_combat()` 不检查保存函数返回值：写盘失败会提示，但内存状态已经提交，不会自动回滚。
- 因此逻辑结算成功不代表一定可靠落盘；遇到保存错误应先排查权限与磁盘。

备份轮换、迁移范围与恢复步骤的完整说明见 [维护文档](维护文档.md) 的存档章节。请勿用测试存档覆盖正式玩家进度。

### 战斗演练

【临时原型】主菜单提供两个演练入口，用于查看战斗而不影响冒险：

- "战斗演练"从后巷事件进入战斗，
- "机甲演练"从蜂巢城寨事件进入复仇机甲战斗。

演练的隔离规则【已实现】：

- 开始前把当前冒险状态备份到内存，然后用全新临时状态进入战斗；期间**不写入冒险存档**。
- 退出或分出胜负后恢复之前的冒险状态，返回**主菜单**，并提示"冒险进度和血量未改变"。
- 演练**不授予**事件完成标记、信用点或奖励，也不是正式关卡。
- 演练从事件中名为 `battle` 的节点进入；新增演练入口时该节点必须存在并指向正确战斗。

### 角色的战斗科技

2026-10-11／0.3.23-character-cyberware：新战斗与演练根据当前主角独立配置科技，当前可玩角色只有诺伦，仍使用临时科技 01—06。点击“激活科技”或在弹层按数字 1—6 使用，每张为下次有效攻击 +1，多张叠加；使用当回合冷却，下个玩家回合恢复。未消耗加成跨回合保留，无效目标和取消瞄准不消耗。正在进行的战斗读档保留原科技、冷却和加成。

未来角色可有各自的 0—6 项列表；未配置科技时不会自动获得诺伦的六张。此处是开发者配置，当前没有玩家选角、获取或更换装备界面。接入方式见[角色科技配置](开发接入说明.md#角色科技配置)。

### 科技档案

【已实现】主菜单有"科技档案"入口，读取独立的局外资料 `meta_profile.json`（`schemaVersion` 为 1，初始 `cyberwareState` 为空）。该文件不随新冒险重置。

【设计未实现】当前局外档案没有可选科技和装备效果，页面**不发放物品，也不改变冒险或战斗属性**。正式局外科技目录 [cyberware.json](../data/cyberware/cyberware.json) 为空。
