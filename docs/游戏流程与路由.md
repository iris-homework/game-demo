## 页面与切换

页面由 [main.gd](../scripts/main.gd) 的 `VIEWS` 映射和 `Game.page` 共同决定。整个游戏只有一个主场景，切换页面时销毁旧视图并实例化新视图。【已实现】

| 页面键 `page` | 场景 | 主要进入方式 |
| --- | --- | --- |
| `menu` | [scenes/menu.tscn](../scenes/menu.tscn) | 启动、游戏内 `Game.request_menu()` 确认后返回、演练结束或菜单子页返回；“战斗演练”按钮打开统一模态面板 |
| `map` | [scenes/map.tscn](../scenes/map.tscn) | `go_map()`，事件结算后返回 |
| `place` | [scenes/place.tscn](../scenes/place.tscn)，黑市使用 [black_market.tscn](../scenes/black_market.tscn)，商场使用 [technology_shop.tscn](../scenes/technology_shop.tscn) | 地图点击“进入地点 →”调用 `visit()`；`market`／`mall`由`main.swap_view()`切换各自专属交易视图 |
| `dialogue` | [scenes/dialogue.tscn](../scenes/dialogue.tscn) | 事件开始或推进到对白节点 |
| `battle` | [scenes/battle.tscn](../scenes/battle.tscn) | 事件节点 `type: battle` |
| `result` | [scenes/result.tscn](../scenes/result.tscn) | 事件 `finish` 节点；正式战斗胜利显示 `reward.gd` 奖励视图，非战斗显示普通结算 |
| `defeat` | [scenes/defeat.tscn](../scenes/defeat.tscn) | 正式战败或恢复失败检查点；只返回主菜单，本局结束 |
| `cyberware` | [scenes/cyberware.tscn](../scenes/cyberware.tscn) | 主菜单"科技档案" |
| `card_library` | [scenes/card_library.tscn](../scenes/card_library.tscn) | 主菜单“牌库”调用 `Game.open_card_library()`，右上角“×”或 Esc 返回主菜单 |

- 主菜单的新委托在已有内存进度或磁盘存档时打开内嵌 `Control` 模态弹层：底层按钮禁用并设为 `FOCUS_NONE`，默认焦点在“返回”，Tab 只在两个弹层按钮间循环；取消或 Esc 关闭后恢复原按钮状态，不改动进度或损坏的存档文件。
- 地图页的目标标记通过 `Game.map_target_events()` 推导，不读取 `targetId` 或 `activeEventId`；悬停只提亮并放大图标，不弹出简介框；点击后固定详情，空白处或 Esc 关闭。

### 完成与失败路线

区分"是否完成事件"与"是否返回地图"很重要【已实现】：

- **只有 `finish` 节点才算完成事件。** `enter_node()` 进入 `type: finish` 的节点时，先应用该节点效果，再追加 `completeEvent`，首次追加时E01开幕与E01R领奖不推进日期，其余委托同一事务推进1天（第7天封顶），然后把页面切到 `result`。重复完成不重复推进；战斗胜利本身不会完成事件。
- **胜利**从 `returnNodeByResult.win` 回到该事件的 `win_01` 对白，玩家还要继续推进 `win` 系列节点，直到 `finish` 才结算并完成事件。
- **失败**进入独立 `defeat` 页面，显示“战败 / 本次冒险已结束”，只提供“返回主菜单”按钮；Esc同效且不再询问退出。正式战败代表游戏失败，不能回地图重试或继续冒险。
- 失败不完成事件、不发奖、不提供胜利线索、不推进日期。`result: lose` 与战斗历史保存，清空开局快照与待领奖励。致死模型在攻击动画结束前落盘也保存为终局，避免重启撤销败局；开始新的委托正常重置。
- 结算页仍使用 `result` 页面键。2026-10-09 / 0.3.19-rewards 起，`finish` 的 `prepare_battle_reward()` 检查当前事件、战斗、胜利结果与历史，按当前配置发放一次50信用点并保存三张候选。`result.gd` 对战斗奖励展示 `reward.gd`；E01R领取选择后复用该奖励页，显示“约定的回礼”；其他非战斗事件保留原视图。
- 选卡调用 `choose_reward_card(id, revision)`，把 ID 追加到 `state.deck` 并将奖励状态设为 `claimed`，一起保存。右下角退出仍调用 `claim_rewards()`；未选卡时按钮显示“放弃卡牌并返回”，点击记为 `skipped` 再回地图；已选卡显示“返回地图”。模拟演练不会进入此流程。
- 当前没有事件执行`finishWeek`，不会自动标记第一周完成或切换后续周。

## 演练路由

当前主菜单只有一个“战斗演练”按钮，打开居中统一模态面板，不改变 `Game.page`。面板内“经典战斗”直接提供黑帮三人组（B04）、双变异鱼（B11）和故障机器人（B02）；十种已发布单敌人的按钮也直接排在同一面板，不再打开新敌人子弹窗。打开面板时禁用背景菜单并约束键盘焦点；关闭后恢复菜单。

B04的“场景”按钮仍打开单独的次级弹层，打开期间禁用演练面板输入。选定、取消或Esc关闭场景弹层后回到演练面板；选择只影响本次会话内B04的表现，不改变正式地点、事件或冒险存档。Esc先关闭场景弹层，再关闭演练面板，之后才交给既有菜单恢复规则。

十种单敌人按钮调用 `Game.start_enemy_training(id)`，临时建立单敌人战斗，直接初始化真实战斗，不经过剧情对白；各100 HP、每回合攻击6，按对应地点选择背景。中途退出或胜负结束恢复原冒险，并删除本次临时战斗与敌人注册；正式剧情和战斗配置独立。

以下记录保留旧入口阶段的变化，当前操作以上述统一面板为准：

经典战斗与单敌人演练共用下列隔离流程【临时原型】：

1. 在统一演练面板点击经典战斗按钮，调用 `start_training(battle_id)`，分别传入B04、B11、B02；单敌人按钮调用 `start_enemy_training(id)`。经典战斗规则和数值保持原配置，故障机器人演练仍使用100 HP和攻击10循环，默认演练仍为B04。
2. `Game` 先把当前冒险状态完整备份到内存，再标记 `training_mode`，用一个全新临时状态进入该事件的 `battle` 节点。
3. 战斗过程中 `checkpoint()` 与 `commit_combat()` 因为处于演练模式而**不写入冒险存档**。
4. 战斗结束（`win` / `lose`）调用 `finish_training()`：恢复备份的冒险状态，把页面切回 `menu`，并提示"冒险进度和血量未改变"。
5. 演练不发放事件完成标记、信用点或奖励；返回菜单后冒险进度与血量与进入前一致。

复用正式战斗的旧演练入口必须确认对应事件存在名为 `battle` 的节点，并引用正确战斗。十敌专用入口由 `start_enemy_training()` 建立带 `trainingOnly` 的临时战斗，`start_training()` 直接初始化该战斗并调用 `checkpoint()`，不要求事件节点；胜负仍统一调用 `finish_training()`。

## 阅读时的已知边界

以下说明已按 2026-10-22 的当前源码和配置静态核对；本次未修改代码，也未运行这些场景。历史测试不能替代后续改动的验证。

- **地图资源路径的位置**：[map.json](../data/map.json) 的 `cityMapAssetId` 当前为 `city_map_expanded`；[assets.json](../data/assets.json) 的对应项指向 `assets/map/map-expanded-v1.png`，并以 `mapContentRect` 标出原城市区域。旧 `city_map`／`map.jpg` 保留作来源与后备资源。底图与 17 地点标记已经接入；科技教会 `church` 默认开放，可经详情卡进入地点页，再返回地图。
- **地点与可玩内容不同**：17 个地点中，7 个有事件（酒馆、垃圾场、后巷、黑潮泵站、白昼庭院、发电厂、港口），`hive`、`block5`、`tower`、`camp`、`hotel`、`church`、`mall`、`market`、`hospital` 没有事件；其中实验室 `hospital` 也没有服务，地下诊所 `clinic` 只有付费治疗服务。所有地点默认开放，具体内容见[游戏规则](游戏规则.md)的地点表。
- **战斗顶部提示框**：`battle.gd` 已移除正式诺伦战斗顶部“诺伦 / 形态与弹药”及演练顶部“演练模式 · 不影响冒险”的文字、底板和边框（2026-10-24）；仅旧规则正式战斗仍显示“旧版测试规则”。敌人生命与意图来自当前战斗模型；[combat.json](../data/prototype/combat.json) 的 3 HP／攻击 1 只是缺少对应定义时的原型回退值，不能代表所有敌人。
- **`lose` 是占位**：该节点的文本写明"后续剧情待补"；它不设置任何旗标，只把结果记入 `battleHistory`。
- **首次发牌与旧快照**：`start_hand()` 依据模型的 `opening_draw_done` 判断首次发牌；新快照保存 `openingDrawDone`，已完成开场抽牌后即使手牌为空也不会重发。仅缺少该字段的旧快照在 `restore()` 中使用“第 1 回合、手牌为空且弃牌为空”推断，不能把此兼容逻辑写成当前新快照的判断规则。
- **多敌与手牌扩展范围**：当前 B11 为双鱼、B04 为三人黑帮战，诺伦补牌目标为 5 张、基础牌组为 10 张；已不是单敌三张手牌原型。相关历史专项见[维护文档](维护文档.md)，本次未重跑。增加敌人数、扩展牌组或手牌上限时仍需检查布局、输入、规则和存档，不能外推历史样本的覆盖范围。
- **存档兼容不只版本 1 → 2**：`migrate_save()` 还补齐 schema 2 缺少的主角、奖励、对话记录和科技字段，并调用 `migrate_mercenary_story()` 处理已移除的阵营剧情；战斗恢复另处理可选字段缺省。没有通用降级迁移。新增字段、删除 ID 或回退程序前，按[维护文档](维护文档.md)的存档章节核对具体路径。
- **对白立绘无条件去白**：透明对白 PNG 不能只靠 `whiteKey=false` 关闭去白；详见 [维护文档](维护文档.md)。
- **地图坐标以原城市区域为基准**：`coordinatesStatus` 为 `illustration-calibrated`，17 个 `mapAnchor` 相对于 `mapContentRect` 对应的原城市区域，`map_rect` 与 `_art_rect` 分别表示原城市和完整扩绘图。更换底图时先核对区域映射；保留原城市构图的扩绘可沿用锚点，内部布局改变时需重校。
- **本次只做文档静态核对**：2026-10-22 未运行游戏、未修改代码或用户存档，也未重跑剧情、战斗和地图验收。[地图界面验收清单](地图界面验收清单.md)中的 `36-capture-final`（5 checks）与 `37/38/39`（各 111 checks，0 failures）为2026-10-07的历史结果，不是本次实测。
