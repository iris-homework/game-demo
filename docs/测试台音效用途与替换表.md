# 测试台音效用途与替换表

这份表说明音效测试台和正式游戏共用的 27 个 cue 分别播放什么、何时自动触发、使用哪个文件或保持静音，以及怎样替换和保存。2026-10-25 的用户授权方案已接入正式游戏：正式根目录是 [assets/audio/game](../assets/audio/game/)，18 个去重文件按原字节复制，覆盖 21 个非空 cue；测试台仍以 `assets/audio/incoming` 的 96 个候选作比较。正式游戏不扫描 `incoming`，也不读取测试台方案 JSON。

逻辑 cue、默认相对路径、两档角色音高和八声播放器来自共享核心 [sfx_player.gd](../scripts/audio/sfx_player.gd)。[game_audio.gd](../scripts/audio/game_audio.gd) 以 `assets/audio/game` 为根路径，并显式 `preload` 全部 18 个正式文件；测试台适配器 [audio_preview_bank.gd](../enemy_asset_pipeline/runtime/audio_preview_bank.gd) 以 `assets/audio/incoming` 为根路径扫描候选。测试台保存的 JSON 只覆盖测试台的绑定，不改变正式游戏。

当前正式与测试台方案关闭事件完成、切场景、回合开始、胜利、失败和能量恢复反馈。事件完成沿用 `reward`；`reward`、`transition`、`turn_start`、`victory`、`defeat`、`energy` 六个 cue 的共享默认绑定为空字符串。回合结束没有独立 cue，正式战斗与测试台都通过共享观察器把战斗 `snap` 加入实例级静音。其余 21 个 cue 使用正式目录中的 18 个去重文件，Cozy 逐字对话短音也在这 18 个文件内；96 个测试台候选仍可手动试听和绑定。

正式与测试台共用 [sfx_hooks.gd](../scripts/audio/sfx_hooks.gd) 的播放边界。回合数字增加时，观察器把同一次快照中的 `energy`、`ammo`、`block`、`parry`、`stance` 和 `technology` 变化视为回合重置并跳过；卡牌或科技在没有回合增加时造成的弹药、格挡、弹反、形态或冷却变化仍会播放。`energy` 已整体改为默认静音，因此卡牌或科技主动回能也不播放。战斗 **结束回合** 按钮不触发普通 `ui_click`，弃牌、抽牌和真正的刀枪攻击声音仍保留。对话逐字继续共用 `dialogue_blip` 文件，诺伦使用 `0.88`，NPC 与场景／旁白都使用 `1.0`，不新增 cue 或音频文件。

所有 cue 播放都要求绑定非空且文件可读取。测试台的共享观察器还要求顶部 **启用场景音效** 已勾选；`victory`、`defeat`、`transition` 和 `ui_error` 由测试模拟器直接播放，不受这个开关控制。正式 [main.gd](../scripts/main.gd) 直接发出错误提示音，并创建正式播放器和共享观察器；转场、胜败和能量恢复的 cue 入口即使存在，六个空绑定也会使它们静音。对话逐字和卡牌悬停分别受 80／70 毫秒节流限制，短时间内连续变化可能被跳过。

正式主入口把根节点交给共享观察器，因此会监视当前页面、根级弹层按钮和错误提示；测试台适配器只监听模拟视口。测试台顶部场景按钮、返回工作台按钮和右侧候选操作按钮不属于被观察页面，所以点击它们本身不会触发 `ui_click`；需要进入左侧正式页面操作或点击页面内按钮。

## 先分清三层声音

共享播放器负责 cue 绑定、节流、对话摘录和 8 个声道。正式 [game_audio.gd](../scripts/audio/game_audio.gd) 只注册 `assets/audio/game` 的 18 个 `preload` 资源；测试台 [audio_preview_bank.gd](../enemy_asset_pipeline/runtime/audio_preview_bank.gd) 负责扫描候选并在载入测试方案时覆盖测试台绑定。两边使用同一组 cue 名，但文件根目录和配置来源不同。

右栏的 **此动作静音**、 **试听动作**、 **绑定所选** 与 **候选总音量** 只修改测试台。正式反馈来自 [main.gd](../scripts/main.gd) 创建的共享观察器；测试台反馈来自 [audio_scene_hooks.gd](../enemy_asset_pipeline/runtime/audio_scene_hooks.gd) 这个薄适配器。原战斗刀声、枪声、归位声和程序生成命中声另走 `combat_audio` 独立播放器，也不受右栏控制。

下表“自动”表示共享观察器或正式入口会调用这个 cue，测试台可进入对应场景复现；“仅手动”表示代码里没有自动调用处，只能用 **试听动作** 或先双击候选试听；“默认关闭；可手动重新绑定”表示触发位置保留，但共享默认绑定为空字符串，正式与测试台当前都不播放。测试台仍可临时重绑并保存预览方案，正式替换按本节末尾的流程更新共享配置和正式资源。

## 回合重置的静音范围

回合静音只处理观察器看到回合数字增加的那一次状态快照。正式与测试台共用的 [sfx_hooks.gd](../scripts/audio/sfx_hooks.gd) 在这次快照中不再比较并播放 `energy`、`ammo`、`block`、`parry`、`stance`、`technology` 六项资源差值，避免把手牌用尽、结束回合后的新回合恢复误听成卡牌或科技反馈。`turn_start` 保持默认静音，不恢复回合开始的提示音。`energy` 另有默认空绑定，所以无论自动回能还是卡牌／科技主动回能都不会出声；以后重新绑定 `energy`，回合数字增加的那一次恢复仍被这层过滤跳过。

这个范围不包含结束回合按钮点击，也不包含战斗画面的其他声音。**结束回合** 按钮不触发普通 `ui_click`；进入下一回合后的抽牌 `card_draw`、清手牌 `card_discard`、洗牌 `card_shuffle`、消耗牌 `card_exhaust`，以及真正的 `slash`／`shoot` 攻击声仍按原条件播放。共享观察器在正式战斗和测试台挂载战斗视图时，都会把 `snap` 加入 `combat_audio.muted_cues`，离开战斗视图时恢复挂载前状态。`combat_audio` 中 `snap` 的源配置仍是 −10 dB，但当前调用被实例静音关闭。没有回合数字增加时，卡牌或科技造成的弹药、格挡、弹反、形态或冷却变化仍会触发对应 cue；能量增加会调用 `energy`，但默认空绑定使其保持无声。

## 对话角色与两档音调

按用户最新要求，NPC和场景／旁白统一为`1.0`原调，诺伦保留`0.88`偏低音调。仍保留三个角色键用于识别，但实际只有两种音高。

自动对话逐字仍使用 `dialogue_blip` 的同一个绑定文件，通过 `DIALOGUE_PITCHES` 调整这一次播放的音高。角色由当前对白节点的 `speakerId` 决定：`noren` 直接使用诺伦音调；`@player` 先经 `Game.resolve_character_id` 解析，当前 `defaultPlayerCharacterId` 为 `noren`，因此也使用诺伦音调；空 `speakerId` 使用旁白音调；其他非空 `speakerId` 使用 NPC 音调。没有新增 cue，也没有新增音频文件。

| 角色 | `speakerId` 与解析 | `DIALOGUE_PITCHES` | 当前听感方向 | 备注 |
| --- | --- | --- | --- | --- |
| 诺伦 | `noren`，或 `@player` 经 `Game.resolve_character_id` 解析为 `noren` | `0.88` | 低于原调 | 当前默认可玩主角为诺伦 |
| NPC | 其他非空 `speakerId`，例如 `bartender`、`robot`、`gang` | `1.0` | 与旁白相同的原调 | 所有非诺伦的有名角色共用这一档 |
| 旁白 | 空 `speakerId` | `1.0` | 保持原调 | 场景说明和无名旁白使用这一档 |

`play_dialogue(role)` 只为这一次自动逐字播放应用角色音高；普通 `play_cue` 和手动试听都使用 `1.0`，避免复用 8 个声道时把上一句的角色音高带到按钮、卡牌或下一次试听。总音量仍是共享播放器的全局音量，角色音高与音量分别控制。

要改两档音调，打开共享核心 [sfx_player.gd](../scripts/audio/sfx_player.gd)，修改 `DIALOGUE_PITCHES` 中 `noren`、`npc`、`narrator` 的数值。不要改 `audio_preview_bank.gd` 来设置音高；它只继承共享核心并增加候选扫描。保留这三个角色键，也不要把角色音高写进测试方案 JSON；方案保存的是 `dialogue_blip` 的共享绑定文件，三个角色都会继续使用该文件。当前诺伦为 `0.88`，NPC 与场景／旁白均为 `1.0`。

在 **对话** 场景可分别等待 `@player`、空 `speakerId` 和 NPC 台词逐字显示来比较两档音调。手动双击候选或点 **试听动作** 只播放 `1.0` 原调，不能代替角色场景试听。逐字触发仍为 80 毫秒节流，超过 100 毫秒的摘录仍在末尾约 15 毫秒淡出。

## 只替换一个动作

右栏方案适合逐项比较。先保存候选文件，再绑定，最后用对应场景或 **试听动作** 检查；每次操作只改变当前选中的 cue。

1. 准备一个可读取的 OGG、WAV 或 MP3。需要缩短、去头尾或统一响度时，先在外部音频工具处理，再把成品作为新文件放入 incoming，原候选保留。
2. 放入 `assets/audio/incoming` 下合适的分类目录。文件名使用小写 ASCII、下划线和两位序号，例如 `dialogue/dialogue_blip_cozy_low_02.wav`；避免空格、中文文件名、隐藏目录、`_originals` 和 `.import` 文件。
3. 回到音效测试台点 **重新扫描**。候选库会自动识别 OGG、WAV、MP3；新增分类需要重开模拟面板才会出现在分类筛选里。扫描时明确保留六个空字符串静音绑定。
4. 在右栏搜索并选中候选，先用 **试听所选** 听完整文件，再用动作下拉框选择目标 cue，点 **绑定所选**。需要暂时关闭时用 **此动作静音**。
5. 按上表进入对应场景触发一次，或用 **试听动作** 播放当前绑定。`coin` 只能使用后一种手动检查，因为它没有自动挂钩。对话角色与两档音调必须在 **对话** 场景逐字触发；手动试听固定为 `1.0`，不能用来比较角色音高。
6. 调节 **候选总音量** 后点 **保存音效方案**。只关闭面板而不保存，改动不会写入方案文件。

如果直接覆盖同名音频，先点 **停止全部** 清掉播放缓存，再点 **重新扫描**；重新打开测试台也可以重新加载。优先保留旧文件并给新版本另取文件名，便于来回比较。

替换共享默认值要改 [sfx_player.gd](../scripts/audio/sfx_player.gd) 的 `DEFAULT_BINDINGS`；只保存测试方案不会改变共享默认、其他机器或正式游戏。三种对话角色共用的绑定仍改 `DEFAULT_BINDINGS.dialogue_blip`，只改角色音高时改同一脚本的 `DIALOGUE_PITCHES`。正式游戏已经接入当前方案；继续更新正式文件时，按下方“调音边界与保存位置”的正式流程同时维护 `assets/audio/game`、`game_audio.gd` 的 `preload` 和来源登记。

## 调音边界与保存位置

共享播放器的总音量默认是 −12 dB。测试台界面提供 −40 至 0 dB 的滑杆，保存字段为 `volumeDb`；方案只有测试台全局音量，没有逐 cue 滑杆。正式游戏使用共享默认值，测试台方案不会修改它。

| 项目 | 当前值 | 生效范围 |
| --- | --- | --- |
| 总音量 | 默认 −12 dB；测试台可调 −40 至 0 dB | 正式播放、测试台自动反馈和手动试听共用播放器实现 |
| 对话逐字节流 | 80 毫秒 | `dialogue_blip` 的自动触发 |
| 卡牌悬停节流 | 70 毫秒 | `card_hover` 的自动触发 |
| 对话自动摘录 | 最多 100 毫秒，末尾约 15 毫秒淡出 | 只作用于长度超过 100 毫秒的 `dialogue_blip` 流 |
| 对话角色音高 | 诺伦 `0.88`／NPC `1.0`／旁白 `1.0` | `DIALOGUE_PITCHES`；只作用于自动对话逐字 |
| 同时播放上限 | 8 个声道 | 共享播放器；不属于原战斗独立声音 |

测试台保存只影响预览：普通制作台保存到 `enemy_asset_pipeline/audio_preview_bindings.json`，测试版制作台保存到 `enemy_asset_pipeline/test/session/audio_preview_bindings.json`。直接运行独立模拟场景时默认使用普通制作台路径；从测试版制作台打开时会切到测试版路径。

方案 JSON 包含 `schemaVersion`、`volumeDb` 和 `bindings`。测试台打开时只载入 schema 版本为 1、绑定字段有效且候选仍存在的条目。正式 `game_audio.gd` 不读取这个 JSON，也不扫描 `incoming`；把试听结果落实到正式游戏需要更新共享默认、复制正式资源并维护 `preload`。

测试方案仍优先于测试台默认，但不会覆盖正式文件。六项静音由共享 `DEFAULT_BINDINGS` 的空字符串表达；重新扫描时这些空字符串绑定仍作为静音项保留。保存方案时应把 `reward`、`transition`、`turn_start`、`victory`、`defeat`、`energy` 这六项写成空字符串，其他 21 个 cue 的测试绑定保持原样。要让正式游戏恢复某个静音 cue，必须在共享默认中填入路径、准备正式文件、更新 `preload` 并原生导入，保存测试方案本身不会生效。
