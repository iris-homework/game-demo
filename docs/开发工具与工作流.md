## 子 agent 配置与调用（2026-10-06）

子 agent 使用约定以 [AGENTS.md](../AGENTS.md) 为准。项目配置位于 [.codex/config.toml](../.codex/config.toml)，默认子模型为 `deepseek/deepseek-flash`／`high`，最多同时打开一个子 agent，不修改用户全局配置或主会话模型。

- [midnight_worker](../.codex/agents/midnight_worker.toml)：执行范围明确的代码、冒烟测试、文档、文件整理与已授权的 Git 操作。
- [midnight_reviewer](../.codex/agents/midnight_reviewer.toml)：`gpt-6-astra`／`medium`，只读合并评审美术与有证据支持的游戏体验；仅在用户明确点名 Astra 时调用，每阶段默认一次。

配置只定义角色，不启动任务。Astra 不负责日常扫描、修正、复测或全工程阅读，不自动重试评审或提高强度；主协调者传入摘要与必要截图，完成后关闭子 agent。用量工具可用时记录评审前后账户共享快照，不据此承诺固定百分比消耗。DeepSeek 第三方路由的计费仍取决于本机接入方式。

当前会话提供通用子 agent 派发入口，按 AGENTS.md 显式指定模型、强度并传入对应 TOML 的角色指令；角色文件用于维护分工，不假定该入口会自动选择具名角色。后续客户端提供具名角色入口时再直接使用角色名。项目默认值需重新加载工具配置或开启新会话后读取；本机工程已受信任，其他机器需信任项目后才能加载项目级配置，不改变机器权限作为替代。

配置格式依据 [官方子 agent 文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。本机 CLI 0.160.0 普通配置读取已确认默认模型、强度和并发；角色文件按 TOML 语法与必要字段验证。严格全局校验受既有 `mcp_servers.context7.type` 旧字段阻挡，未修改原有 MCP。提示渲染仅显示会话指令，不能用其中的角色名证明具名角色自动发现。本轮不发起模型调用，也未验证供应商连通性或实际评审质量。

## QA 入口

从工程根目录在 PowerShell 执行：

```powershell
.\tools\qa.ps1 -Target menu
.\tools\qa.ps1 -Target dialogue
.\tools\qa.ps1 -Target map
.\tools\qa.ps1 -Target place
.\tools\qa.ps1 -Target battle
.\tools\qa.ps1 -Target pile
.\tools\qa.ps1 -Target cyberware
```

这些命令摆出已有页面并截取 Godot 真实视口。`place` 当前选择酒馆；`battle` 和 `pile` 使用 B12 演练，`pile` 打出两张牌后打开弃牌堆。截图工具关闭自动保存并使用临时测试路径，不覆盖冒险或义体存档。摆出状态并截图只验证画面，不等同于鼠标游玩通过。

按改动范围执行现有测试，图形交互测试逐个运行：

```powershell
.\tools\qa.ps1 -Suite integration
.\tools\qa.ps1 -Suite interaction
.\tools\qa.ps1 -Suite drag
.\tools\qa.ps1 -Suite pile
.\tools\qa.ps1 -Suite story
.\tools\qa.ps1 -Suite combat
```

`story`、`combat` 使用 headless；截图和图形集成使用渲染窗口。`interaction`、`drag`、`pile` 使用屏幕内可见窗口，会移动鼠标，运行时避免手动操作。脚本检查退出码、脚本错误与最终测试汇总，超时只结束自己启动的进程。

默认输出到 `artifacts/qa/<时间>-<类型>-<目标>/`，含 stdout.log、stderr.log。正常结束的进程另存 result.json（含 passed/failed）及当次生成的截图，失败会返回错误；超时保留日志。`-OutputDirectory` 可指定证据目录；`-TimeoutSeconds` 可调整超时。生成证据被 Git 和 Godot 导入忽略，需交付的精选截图另行保留。

### 地图 QA（`tools/run_map_qa.ps1`）

地图页面使用独立入口，从工程根目录执行：

```powershell
.\tools\run_map_qa.ps1 -Suite import
.\tools\run_map_qa.ps1 -Suite logic
.\tools\run_map_qa.ps1 -Suite story
.\tools\run_map_qa.ps1 -Suite combat
.\tools\run_map_qa.ps1 -Suite capture -Resolution 1280x800
.\tools\run_map_qa.ps1 -Suite input -Resolution 1280x800
```

`-Suite` 可取 `import`、`logic`、`input`、`story`、`combat`、`capture`，另有 `-Resolution`、`-OutputDirectory`、`-TimeoutSeconds`。`logic`、`story`、`combat`、`import` 使用 headless；`capture` 只摆出状态并截图；`input` 打开可见窗口并移动系统鼠标，必须顺序运行且执行时不要手动操作窗口。脚本为子进程设置隔离的 `APPDATA`，所有测试存档写入 `artifacts` 测试路径，不写 `user://checkpoint.json`、`checkpoint.json.bak` 或 `meta_profile.json`。

本轮地图证据根目录为 `artifacts/qa/map-build-2026-10-07`：地图逻辑 `12-model-final` 为 138 checks／0 failures，剧情 `04-story` 为 690 checks／0 failures，战斗模型 `05-combat` 为 191 checks／0 failures，资源与脚本导入通过。最终截图 `36-capture-final` 为 5 checks／0 failures；最终输入 `37-input-final`（1280×800）、`38-input-final-1600`（1600×1000）、`39-input-final-wide`（1440×810）各为 111 checks／0 failures，覆盖文字显示、任务按钮、滚动与实际点击。宽屏保持 1440×900 逻辑画布，PNG 为 1296×810，窗口左右留边。17 份图标原图和 10 项正式存档路径的哈希与存在性均未变。失败日志保留，实际证据与范围见[地图界面验收清单](地图界面验收清单.md)。

`-Suite` 可取 `baseline`、`import`、`capture`、`input`、`performance`，默认为

## 分阶段制作

本阶段采用城市总览插画叠加地点与任务标记，不安排地图小人、行走、寻路、碰撞或角色动作制作。

1. **样板美术**：依据 [美术方向](美术方向.md)，制作城市总览构图样稿，叠加代表地点标记及一种详情面板，检查城市辨识度、交互重点与文字可读性。
2. **可运行样板**：选定底图后接入真实 Godot 地图，校准比例锚点、点击范围和状态提示，验证地点选择、事件、锁定及已有治疗入口，以截图和对应输入检查验收。
3. **内容扩展**：样板通过后精绘全城并补齐现有地点标记与详情状态；按当轮影响范围回归，更新修改记录及资源来源。

每阶段提交实际文件、可运行入口、截图、执行过的检查和待处理问题，由用户分阶段验收。城市总览地图已于 2026-10-07 以 0.2.4-r1 接入并完成画面、逻辑与三尺寸输入检查，证据见上文地图 QA；主菜单于同日以 0.2.5-r1 接入 P0，0.2.6-r1 起改用用户审核的逐帧动画背景。2026-10-04 与 2026-10-06 两轮仅调整文档、参考资料、skill 和子 agent 配置，未进行新的游戏运行测试；历史结果与本轮结果分别保留。
