## 保留的 Windows QA 入口

以下是历史 Windows 工作流的调用示例，运行前须核对当前平台、脚本与待测规则是否匹配；不代表本次已运行。以 `MidnightDemo` 为工作目录，在具备对应环境的 PowerShell 中执行：


这些命令摆出已有页面并截取 Godot 真实视口。`place` 当前选择酒馆；`battle` 和 `pile` 使用 B12 演练，`pile` 打出两张牌后打开弃牌堆。截图工具关闭自动保存并使用临时测试路径，不覆盖冒险或科技存档。摆出状态并截图只验证画面，不等同于鼠标游玩通过。

按改动范围执行现有测试，图形交互测试逐个运行：

```powershell
.\tools\qa.ps1 -Suite integration
.\tools\qa.ps1 -Suite interaction
.\tools\qa.ps1 -Suite drag
.\tools\qa.ps1 -Suite pile
.\tools\qa.ps1 -Suite story
.\tools\qa.ps1 -Suite combat
```

`story`、`combat` 使用 headless；截图和图形集成使用渲染窗口。`interaction`、`drag`、`pile` 使用屏幕内可见窗口，会移动鼠标，运行时避免手动操作。脚本检查退出码、脚本错误与最终测试汇总，超时只结束自己启动的进程。

默认输出到 `artifacts/qa/<时间>-<类型>-<目标>/`，含 stdout.log、stderr.log。正常结束的进程另存 result.json（含 passed/failed）及当次生成的截图，失败会返回错误；超时保留日志。`-OutputDirectory` 可指定证据目录；`-TimeoutSeconds` 可调整超时。生成证据被 Git 和 Godot 导入忽略，需交付的精选截图另行保留。

## 分阶段制作

本阶段采用城市总览插画叠加地点与任务标记，不安排地图小人、行走、寻路、碰撞或角色动作制作。

1. **样板美术**：依据 [美术方向](美术方向.md)，制作城市总览构图样稿，叠加代表地点标记及一种详情面板，检查城市辨识度、交互重点与文字可读性。
2. **可运行样板**：选定底图后接入真实 Godot 地图，校准比例锚点、点击范围和状态提示，验证地点选择、事件、锁定及已有治疗入口，以截图和对应输入检查验收。
3. **内容扩展**：样板通过后精绘全城并补齐现有地点标记与详情状态；按当轮影响范围回归，更新修改记录及资源来源。

每阶段提交实际文件、可运行入口、截图、执行过的检查和待处理问题，由用户分阶段验收。城市总览地图已于 2026-10-07 以 0.2.4-r1 接入并完成画面、逻辑与三尺寸输入检查，证据见上文地图 QA；主菜单于同日以 0.2.5-r1 接入 P0，0.2.6-r1 起改用用户审核的逐帧动画背景。2026-10-04 与 2026-10-06 两轮仅调整文档、参考资料、skill 和子 agent 配置，未进行新的游戏运行测试；历史结果与本轮结果分别保留。
