## 观察到的行为

浏览器初轮实际把黑帮小弟 idle 组缩放从 0.108 调到 0.107，保存并生成草稿。
HTTP 检查设置阴影半宽 36、半高 10、透明度 0.55，绑定两名黑帮小弟，
应用到测试目录后核对资源文件存在，再恢复应用前配置。

Godot 试用场景直接进入战斗。刷新草稿后自动选中相应敌人；实际 sprite
缩放为 0.107，阴影与后端一致。攻击演示保持模型快照不变，真实直击只扣
一次 6 HP；退出草稿后保留编号素材路径适配，角色没有错误退化为 Finn。

runtime 检查覆盖发布／预览隔离、敌人绑定、缓存刷新、源图回退、WAV、
逐帧时间、一次／循环播放、镜像、诺伦形态、挂件 owner 变换与排序、
拖尾前后层、禁用帧索引、逐帧切片和结束清理。多帧攻击不会被固定收招时间截断。
GPU 场景使用合成轨迹夹具检查 shader 实际渲染，截图不作为角色美术定稿。

已目视检查 `godot-draft.png`、`godot-trail-gpu.png` 和网页本地布局截图。
Godot 检查采用程序驱动渲染与注入输入，不代表物理鼠标或完整游玩验收。

## 中间失败与边界

首次图形联调为 17 项、0 失败，但日志发现清除草稿时重新创建 resolver
丢失旧测试台的内存路径适配；已保留原 resolver，并补充角色种类断言。
其后的 `workbench-final-*.log` 记录过一次局部变量类型推断编译失败和超时；
加上显式 `float` 后，最终 `workbench-fixed-*.log` 为 18 项、0 失败。

原生浏览器 confirm 曾使自动浏览器控制阻塞，最终界面改用页面内确认框。
应用／回退通过 HTTP 和 runtime 验证；最终页面内确认框、导入文件选择器、
新增的双向动作／帧同步尚未完成物理鼠标验收。浏览器截图只证明界面及
初轮实际调参保存，不把接口测试当作完整网页交互证据。

runtime 的旧 Finn 配置仍有目录大小写警告，强制原图读取检查会产生导出提示；
正式发布资源需要先让 Godot 完成导入。WAV 已正向实测，OGG／MP3 只有
格式分派及加载器接入，本轮没有真实样本正向解码证据。
