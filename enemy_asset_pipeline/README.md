# 午夜委托敌人制作台

把人工整理的 PNG 动作接入实际战斗：导入、逐帧校准、调整演出、战斗预览，
最后明确应用到游戏。工具复用 XSXB Frame Tuner 的编帧和拖尾源码，
不接入 FrameBaker，也不调用 AI 改图。

队友制作与交接素材前，先读[PNG动作帧制作规范](../docs/PNG动作帧制作规范.md)，
按其中的文件夹和命名示例整理PNG。

## 启动

在现有 Godot 工程中打开场景，再按 **F6 运行当前场景**：

| 用途 | 场景 | 数据范围 |
| --- | --- | --- |
| 先试用 | [test/test_workbench.tscn](test/test_workbench.tscn) | `test/` 内的独立草稿和应用结果 |
| 正式制作 | [workbench.tscn](workbench.tscn) | `authoring/` 草稿、`published/` 游戏配置 |

场景直接进入战斗工作台。左侧切换地图／卡牌，右侧切换`noren`／敌人槽位。
点击上方 **打开PNG制作工具**，场景启动本机 Node 服务并打开浏览器编辑器。
Node 路径从工程 `tools/local_paths.json` 读取，缺省使用 `node`。
不需要 npm 安装，也没有 BAT／CMD 启动器。

浏览器是帧制作界面，Godot 是实际战斗验收界面；两者通过保存的配置交接。
测试端口为 5193／5194，正式端口为 5191／5192，只监听本机。
退出场景会关闭由该场景启动的服务；复用的已有服务由启动者管理。

两个工作台的角色名称统一显示素材目录名，如`01a_warden_shield`、
`02b_robot`，主角及旧占位角色分别为`noren`、`finn`。网页选择框、
内嵌编辑器、绑定列表和Godot角色信息使用相同规则；内部外观ID与绑定不改。
多个测试定义共用同一素材时名称相同，悬停选项可查看各自的内部敌人ID。

## 自动识别素材目录

打开 PNG 制作工具时，服务扫描 `assets/combat_test/` 的角色子目录，
把缺少的动作追加到当前制作草稿。工作台开着时新增文件，点击左侧
**扫描新增PNG** 即可，无需逐张选择。测试版、正式版各自扫描、各自保存草稿，
扫描不会应用到游戏；你仍需校准并使用预览、应用按钮。

按角色 ID 命名图片。目录可带地点编号，文件前缀使用去掉编号的角色 ID。
以 `01a_warden_shield/` 为例：

| 文件名 | 识别结果 |
| --- | --- |
| `warden_shield_idle.png` | 待机 |
| `warden_shield_move.png` | 移动 |
| `warden_shield_attack.png` | 攻击姿势，接入现有 `pierce` 动作槽 |
| `warden_shield_damaged.png` | 受伤 |
| `warden_shield_VFX.png` | 待校准特效素材 |

文件后缀大小写不敏感，也识别现有的 `slash`、`pierce`、`shoot`、`block`
等动作槽位。`reference_idle/` 不参与导入，不能从其他角色前缀猜测图片用途。
新增角色即使缺少待机，也可先整理已有动作；页面提示缺少 `idle`，补齐后再预览、
发布，不会把攻击图冒充待机。

扫描只补缺项，保留已有动作、帧顺序、脚底、缩放、阴影、绑定与挂件。
已有动作需要换图时继续用手工替换。新增动作的脚底、大小只根据透明边界与
待机轮廓估算，使用诺伦对照检查后人工校准。重复扫描不会重置调参。

VFX 识别为特效 PNG，不作为角色动作帧。已有命中特效保留；多部件合图需要
另行拆分并配置挂件或拖尾，扫描不会自动切图，也不能凭文件名判断命中时机。
扫描提示会列出缺少待机、坏图、同槽冲突等情况。

## 攻击标签与演出模板

你可以在PNG文件名中标明攻击类型。文件夹名保持原样，扫描只建立制作草稿，
不会改动原PNG或自动发布。

| 文件后缀 | 动作槽与默认演出 |
| --- | --- |
| `*_attack_hit.png` | `hit`，接近后打击 |
| `*_attack_bite.png` | `bite`，张嘴预备 |
| `*_attack_bite_close.png` 或 `*_bite_close.png` | 咬合命中姿势，与张嘴动作组成咬击模板 |
| `*_attack_shoot.png` | `shoot`，原地发射 |
| `*_attack_laser.png` | `laser`，原地射线 |
| `*_vfx_muzzle.png` | 发射端特效候选 |
| `*_vfx_projectile.png` | 飞行弹体候选 |
| `*_vfx_impact.png` | 目标命中特效候选 |

例如`06b_luggage_lurker/luggage_lurker_attack_bite.png`配合
`luggage_lurker_attack_bite_close.png`（也兼容`luggage_lurker_bite_close.png`）。
旧`*_attack.png`仍导入`pierce`，并提示你
确认攻击类型。同一动作槽出现两个候选文件时提示冲突，不任意选一张。
已有动作和人工参数优先；扫描不会重置已保存的模板或人工选择的默认攻击。
旧攻击文件改名且原路径失效时，只有一个明确类型攻击候选才修复旧帧引用，
并保留原动作槽和校准。更新工具源码后需重启PNG服务，重新打开网页再扫描。

网页左侧的**攻击方式**选择敌人的默认动作，**攻击演出模板**分别编辑各动作：

1. 选择动作并启用模板。已有无标签素材也可直接选择类型，无须重命名PNG。
2. 为预备、出手和收招选择现有姿势。旧攻击图在`pierce`槽时，可以手工绑定它。
   咬击必须明确绑定闭合姿势；缺少`bite_close`时允许保存草稿，但阻止预览、
   发布。只有你明确选择`idle`时才把待机用于闭合。
3. 设置位置行为、预备、出手后延迟、收招和远程传播秒数。
   远程只允许原地或后撤，弹体到达时才显示受击与血量变化。
   模板的时间参数优先；原来的全局预备／收招只用于旧演出。
4. 输入出手PNG原图坐标，或点击**在当前帧点选发射／接触点**后在上方图片中
   标记。此操作不改脚底锚点。近战接触点控制水平接近位置，脚底保持在地面；
   目标命中点使用对方脚底为原点的局部坐标。
5. 按需绑定透明特效PNG。只有一个模板时，分类VFX可自动关联空槽；多个模板时
   提示你手工关联。通用`*_VFX.png`保持待校准，不会自动播放整张合图。
   模板留空使用程序冲击、齿痕或弹体；**使用已绑定的命中特效**可显式关联旧图。
6. 保存演出草稿、送入战斗预览，在Godot刷新草稿后检查完整演示。
   测试台支持正常、半速、四分之一速，以及脚底、地面、攻击点辅助线。
7. 在正式制作台点击**应用当前角色到游戏**。新建战斗读取相同模板与固化资源，
   已经创建的角色不热换；测试版发布继续隔离在`test/`内。

一个角色可以同时保存多个动作模板。`noren`继续由卡牌与形态选择挥砍、突刺、
射击，不强制整个角色使用一种类型。敌人有多个模板时需确认默认攻击；
正式意图中显式指定的`animation`选择同名模板，优先于默认攻击。
这些配置只改变演出，伤害、格挡与附加状态仍由`CombatModel`计算一次。

已有角色若尚未建立攻击模板，可在本界面直接按现有动作绑定；新标签只用于新增文件。
工具不会将攻击图冒充待机。现有角色的PNG名称和正式发布配置未批量改写。

## 从 PNG 到游戏

按以下顺序完成一个角色。先用测试版熟悉操作，再在正式版制作；
两套草稿和应用目录相互独立，测试版不会自动晋升到正式版。

1. 按上述命名放好图片并扫描，或在 **导入PNG** 输入角色 ID、名称和动作槽位。
   `idle` 是必需动作。
   多张 PNG 按列表顺序播放，导入前可以上下调整顺序。
   `move`、`slash`、`pierce`、`damaged` 等动作分别导入。
   替换动作必须勾选替换；会清除该动作的逐帧微调、挂件、音效和拖尾绑定。
2. 在左侧选择动作和帧，点击图片的脚底接地点，按 **保存本帧脚底**。
   每帧独立保存；同一动作的不同姿势可以使用不同接地点。
3. 在右侧选 **角色／组／帧** 调整整体大小、动作大小或单帧大小，
   再调整偏移、旋转和时长。缩放、旋转、偏移数值框可直接键入精确值，
   按回车或离开输入框提交，Esc恢复本次输入前的值；两侧按钮继续提供微调。
   缩放值必须大于零，非法输入会恢复当前有效值并显示提示。
   残影与参考帧便于比较。
   **组** 对应一个动作；角色总体缩放会叠加到各动作。
   最后点击右侧 **保存调参**。
4. 左侧设置原图朝向、攻击方式、地面阴影、移动速度、攻击距离、
   预备和收招时间、命中特效倍率／偏移，以及鼠标选敌区域。
   新外观可多选要替换的现有游戏敌人；留空按相同外观 ID 应用。
   诺伦使用专用 `noren` 配置。点击 **保存演出草稿**。
   切换角色时从服务端重新读取已保存的演出参数；保存左侧参数不会刷新右侧帧编辑器。
5. 需要额外特效时，在左侧导入命中特效 PNG，在右侧设置逐帧挂件、
   音效或攻击拖尾。旧咬击演出需要 `bite`、`bite_close` 和命中特效图；
   新咬击模板可使用程序齿痕，见上方模板说明。
   射击需要 `shoot`；掌心射线需要 `laser`、掌心坐标和掌宽。
6. 点击 **送入战斗预览**，回 Godot 点击 **刷新草稿**。
   台内自动选择对应角色，检查姿势、完整攻击、移动、阴影和镜像。
   左侧可换地图、添加真实测试卡牌，右侧可放入最多三个敌人对比大小。
7. 满意后点击网页 **应用当前角色到游戏**，核对确认框。
   正式版保存当前角色及其绑定，并把引用的图片和音效复制为独立发布资源。
   新建战斗读取新配置，已经播放中的角色实例保持原样。
   **撤回上次应用** 恢复应用前的整个发布目录配置。

应用前必须保存右侧帧调整和左侧演出参数。原始 PNG 按字节保留，
校准只写配置。工作台没有自动生成缺失动作，也不会自动修补画坏的肢体。

## 诺伦尺寸对照与单帧演示

网页幕布默认白色，地面阴影会随左侧参数即时预览。勾选 **noren等深度对照**，
幕布左侧显示诺伦虚影；使用 **虚影透明度** 调节参照的明暗。点击
**一键并排 · 脚底对齐**，让诺伦与当前角色按同一纵深、同一缩放比例并排显示。
调整角色或动作大小后，参照跟随重新取景，诺伦自身大小不随敌人参数改变。

诺伦参照优先读取正式已应用的待机配置，无有效配置时使用游戏内置待机校准；
测试草稿不会改变参照。图高比值包含武器和头发，用于比较可见轮廓，
不等同于人体身高。脚底对齐以你保存的锚点为准，仍需先校准各张图片的脚底。

当一个非待机动作只有一张启用帧时，点击 **播放**，按
**待机 → 当前动作 → 待机** 演示一次，结束后停在待机。移动、攻击、格挡、
受伤等使用相同方式；持枪动作优先返回持枪待机。动作阶段默认停留 0.45 秒，
可在 **演示停留** 调节，已设置的帧时长更长时沿用较长值。支持暂停与继续；
点击 **结束演示** 恢复当前动作的编辑画面。缺少有效待机帧时提示先导入并启用。

该演示不插入帧、不改变动作循环或保存时长，也不生成过渡图；多个启用帧
继续按原序列播放。预备、位移、收招与命中特效的完整节奏仍在 Godot 战斗台验收，
需要发布的参数继续使用 **保存调参** 和 **保存演出草稿**。

## 缩小后的角色锯齿

正式制作台的 `workbench.tscn` 已把 `character_mipmaps` 设为开启。场景加载角色时，
会根据当前纹理在内存中生成带 mipmap 的显示副本，并给角色、挂件及归位残影使用
**Linear with Mipmaps**。原始 PNG 保持原样，不缩小、不重绘；每次先显示一个动作时
会短暂生成纹理，之后沿用缓存。状态栏显示“角色Mipmap平滑”时表示该路径已启用。

该开关只改变制作台预览的采样方式。正式游戏场景仍使用原纹理路径，是否推广到
正式战斗需要另行验收。若仍需更锐利的成品，可再比较导入级 mipmap、内部视口尺寸
和最终窗口缩放；不要用 MSAA 或 FXAA 代替纹理 mipmap。

## 常见问题怎么调

工作台负责定位问题，让你决定修哪一帧。

| 问题 | 调整位置 |
| --- | --- |
| 整只怪过大／过小 | 右侧角色缩放；只影响某动作时改组缩放 |
| 动作过程中忽大忽小 | 用参考帧／残影比较，逐帧改缩放与偏移 |
| 人物漂浮、脚底抖动 | 左侧逐帧脚底锚点；再检查组与帧的偏移 |
| 人和阴影错开 | 阴影以角色脚底为原点；调整阴影偏移、半宽、半高 |
| 画面停顿或跳帧 | 检查帧顺序、各帧时长、禁用状态和循环播放 |
| 角色图本身扭曲、装备变样 | 替换这张 PNG；变换参数只能校准位置和大小 |
| 挥砍拖尾位置不对 | 右侧逐帧拖尾，检查前后层、节点位置与切片 |
| 命中特效过大或偏位 | 左侧特效倍率／偏移；咬击可替换特效 PNG |
| 大体型角色难以鼠标选中 | 左侧鼠标选敌区域，按脚底原点调整宽高和偏移 |

脚底锚点使用原始 PNG 像素坐标；阴影、距离、选敌区域和特效偏移使用
战场局部坐标。角色仍随实际战场的纵深和镜头一起缩放。
掌心坐标使用 `laser` 原始图片像素坐标，便于对准手掌。

## 数据与维护边界

目录职责如下，发布前保留整套制作资料。

| 目录／文件 | 内容 |
| --- | --- |
| `vendor/xsxb/` | 固定版本的上游源码与 MIT 许可；不参与 Godot 资源扫描 |
| `upstream.json` | 上游地址、固定提交与本地修改说明 |
| `authoring/data/projects/midnight/` | 正式 manifest、调参、帧音效、挂件、拖尾、演出参数 |
| `authoring/data/projects/midnight/asset_scan_report.json` | 最近一次自动扫描的新增、跳过、警告；测试版对应文件在`test/session/` |
| `authoring/workspace/` | 正式手工导入图片、附件和音效 |
| `authoring/preview_catalog.json` | 正式制作草稿的临时战斗预览 |
| `published/catalog.json` | 游戏只读发布配置，初始为空，显式应用后写入 |
| `published/assets/` | 按内容哈希固化的发布图片和音效 |
| `published/backups/` | 每次应用前的配置备份；旧资源保留用于回退 |
| `runtime/` | Godot 加载、校验、序列播放及 XSXB 拖尾适配 |
| `test/session/` | 测试服务的独立素材、草稿、发布文件和临时用户目录 |
| `test/preview_catalog.json` | 测试版战斗草稿 |
| `test/evidence/` | 本轮日志、截图和结果，不作为游戏资源 |

应用只替换视觉和演出参数。生命值、伤害、意图、卡牌结算、奖励、
新敌人遭遇和剧情解锁仍由原有游戏数据及 `CombatModel` 管理。
逐帧碰撞框不参与本游戏回合制伤害计算，所以本地界面隐藏该上游面板。

无有效发布配置时沿用原有外观；无效覆盖被拒绝并留下诊断。
导出游戏前让 Godot 完成 `published/assets/` 导入，并确保 JSON 和 `runtime/LICENSE-XSXB.txt` 随包发布。
制作服务和 `authoring/` 不需要随玩家版本运行。退出制作台前保存网页调参。

初始正式制作资料包含 15 个 PNG 外观：诺伦、鱼、黑帮两种、机器人及
10 种已有待机图。待机图的初始尺寸只是估算，需人工校准；Finn 的 WebP
保持游戏原有加载方式，本轮未转换为 PNG 制作资料。

## 验证

检查入口均位于 `test/`，测试场景关闭正式存档写入。图形检查顺序运行。

正式敌人的外观与特效路径还需运行 `tests/combat/enemies/enemy_visual_library_tests.tscn`；
制作台有历史素材路径兼容处理，不能仅以制作台显示正常判断正式战斗接入成功。

- 在本目录运行 `npm test`：管线、正式诺伦参照、等比例几何与单帧演示，
  包含导入、变换、锚点、资源固化、绑定、音效／附件／拖尾和发布回退。
- `test/enemy_resource_paths.test.cjs` 检查正式外观与已发布目录的全部资源路径，
  逐级核对文件名大小写，避免 macOS 能读而其他系统失效。
- `test/web_metadata.test.cjs` 使用真实网页事件处理与隔离后端，检查保存后
  切换角色再保存、未保存帧保护及保存失败保护；DOM 与内嵌帧编辑器使用替身，
