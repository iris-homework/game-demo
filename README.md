# 午夜委托 第一周 Godot Demo

根据工作区的四份设计文档制作的第一周剧情流程原型。可以从地下酒馆接取委托，沿公司或革命军路线完成首周 Boss，并探索支线。战斗按设计要求保留为开发占位页，尚未实现出牌玩法。

## 打开与运行

- 使用 Godot 4.x 标准版导入本目录的 `project.godot`，等待素材导入后按 **F5**。
- 本机已用 **Godot 4.7.2** 验证。项目使用 GDScript 与 Compatibility 渲染，不需要 .NET 或第三方插件。
- macOS 可双击 `启动Demo.command` 直接运行（需要 `/Applications/Godot.app`，也支持 PATH 中的 godot/godot4）。
- 初次进入点“开始新的委托”。窗口默认为 1280 × 800，设计画布为 1440 × 900。

## 操作

| 操作 | 按键 |
| --- | --- |
| 选择地点、事件、对白选项 | 鼠标点击 |
| 显示完整句子，再推进对白 | 空格 / 回车 / 继续按钮 |
| 选择对白选项 | 数字 1、2 |
| 打开菜单 / 返回当前进度 | Esc |
| 开发信用点面板 | F1 |

地图先点击地点，再点右侧“进入地点”。粉色节点代表当前有事件。锁定地点可以查看解锁提示。

## 本版内容

- 16 个地图地点；地图、地点、对话、战斗、结算各为独立场景。
- E01—E12 全部对白，E05 分为 A/B，共 13 份事件配置。
- 开局理查德委托通往公司；卢米娜委托通往革命军。两条招募剧情中的接受与拒绝，都按原稿加入对应阵营，并记录选项。
- E03 支持支付 300 信用点与拒付战斗。信用点不足时显示差额并禁用支付。
- 10 个战斗入口均支持胜利、失败、投降；只有正确的胜利或支付分支能获得线索。
- 一次性事件、原节点恢复、自动存档、备用检查点和奖励领取去重。
- 已接入四幅场景、四幅人物图。缺图地点与角色使用统一文字占位；未确定归属的商店图未接入。
- 使用原图副本；人物白底仅在运行时通过 shader 处理，原文件没有修改。正式透明立绘可直接替换资源。
- 内置 Noto Sans CJK SC 字体及 SIL OFL 许可证，中文显示不依赖本机字体。

## 演示配置与边界

1. 初始信用点设为 **0，仅为开发演示值**。正式数值待定。按 F1 可设为 300 测试支付，也可拒付进入战斗。
2. E08、E11 暂在阵营入门完成后开放；E11 暂挂黑潮泵站外海；E12 暂以本阵营发电厂任务完成为前置。这些假设已写入数据与界面提示。
3. 失败、投降进入“后续剧情待补”，保留结果并返回地图；事件未完成，可重新进入验证。没有自行添加治疗、死亡、阵营惩罚或战败剧情。
4. 卡牌、敌人数值、奖励池和常驻服务均未擅自补造。结算显示“本次无奖励”。只有配置了有效奖励时才发放。
5. 首周 Boss 胜利写入 `week1Complete`。第二、三周为保留目录，在地图“周次档案”中显示“内容待设计”，当前周维持为 1。
6. 没有加入音效或配乐，现有素材包未提供音频。
7. “午夜委托”为本原型的工作标题，可在 `project.godot` 和界面标题中调整。

## 存档

每次场景／对白节点切换及有效选项提交自动保存。菜单“继续旅程”恢复当前地点、当前句子或战斗入口。开始新游戏前会提示覆盖。

存档为 `user://checkpoint.json`，同目录的 `.bak` 是前一检查点。macOS 默认实际目录为 `~/Library/Application Support/MidnightCommissionDemo/`。F1 面板显示当前实际路径。写入使用临时文件替换；主存档损坏时尝试恢复备用检查点。开发测试使用单独测试文件，不污染正常存档。

## 扩展入口

| 修改内容 | 文件 |
| --- | --- |
| 人物显示名、立绘引用 | `data/characters.json` |
| 场景、立绘路径 | `data/assets.json` |
| 地点说明、坐标、开放条件 | `data/places.json` |
| 第一周对白、分支、事件条件 | `data/weeks/week1/events.json` |
| 战斗 ID、参战者、三种返回节点 | `data/battles.json` |
| 开发模式、初始信用点 | `data/config.json` |
| 卡牌与奖励入口 | `data/cards/`、`data/rewards.json` |
| 正式战斗替换模块 | `scenes/battle.tscn`、`scripts/battle.gd` |
| 状态、条件、事务、存档 | `scripts/game.gd` |

新事件加入事件配置、指定既有 `placeId` 即可出现在地点列表，不需修改地图查询代码。详细约定见 `docs/开发接入说明.md`。

## 验证

执行下面命令（将 `godot` 换成你的 Godot 可执行文件路径）：

```sh
godot --headless --path . --editor --import --quit
godot --headless --path . res://tests/run.tscn
```

验收脚本覆盖两条阵营线及两种招募回应、E03 支付与拒付、所有战斗三种返回、重复点击、首周结束、存档恢复、奖励幂等与事务回滚。图形回归可运行 `tests/visual.tscn`，截图输出到系统临时目录。测试不会写入正式存档。

设计依据：`地图事件对话与卡牌战斗游戏实现文档.docx`、`卡牌游戏第一周制作注意点.docx`、`事件对话整理与润色.docx`、`城市地点设定.docx`。
